# Dark Nights MVP版发布计划

日期：2026-10-20。范围：CL阶段内的一次基础采矿远征。实现、验证和发布候选状态统一维护于[执行台账](DEVELOPMENT.md#stage-cl)。

MVP首先验证现有内容能否自然、顺畅地完成一次远征，重点看自动航行、船与地图衔接、地面通行、矿物发现、采挖手感及收获反馈。船内采购暂采用补给电脑方案。撤离压力、怪物、失败惩罚和永久成长后置，不作为这版完成闭环的前提。

本计划是发布准备范围，不代表已经生成或发布可玩包。CL完整目标继续保留；本次MVP通过不自动结束CL阶段。发布对象、平台、时间及最终候选仍待明确。

## 目标与完整流程

```text
船内准备 → 正式自动航行 → 到达并降落
    → 下船探索 → 发现矿物 → 挖掘与采集
    → 带矿返回 → 入舱交货 → 集合撤离
    → 飞船脱离星球，确认货物与收入
```

正式航行包括导航选择、确认、船位推进、ETA、到达和自动降落，不要求玩家手动驾驶。验证必须从船内准备开始，不能从已经落地、靠近矿脉或已有船货的状态代替。

这版需要回答三个问题：玩家能否不依赖调试完成全程；每个环节是否知道该做什么；找路、挖矿和返程本身是否顺手、有发现感。流程成立与体验满意分别记录。

## MVP范围

| 纳入本版 | 最小交付 |
| --- | --- |
| 船内准备与采购 | 容易辨认的补给电脑、现有商品与价格、余额和装备信息、明确的购买结果 |
| 导航与自动起降 | 正式航程、全员可见的目标与ETA、落稳后允许出舱、明确的撤离集合条件 |
| 飞船与地表衔接 | 船体、舱门、坡道和停靠地面位置对应，角色可实际走出并走回 |
| 矿洞与基础通行 | 先确定一张MVP候选及一条完整往返路线，覆盖主要坡面、跳跃或落差与可辨认岔路 |
| 发现与采矿 | 路边露矿、一次挖墙揭露壁内矿团、正式采集和随身货物反馈 |
| 带货与结算 | 随身矿物转入船货，全员集合撤离，安全脱离后一次性出售并显示收入 |
| 合作与必要可靠性 | 沿用2–4人目标；两人真实闭环及所发布人数范围内的空间、交互、同步和货账核对 |

本版后置：新撤离压力、怪物／巢穴遭遇、伤害与失败惩罚、永久升级、多主题或大图池、手动驾驶、DIY飞船、运输自动化。已有系统和作者资产保留；后置范围不要求删除历史成果，也不把已有事件擅自改为另一套规则。

当前地图中的既有地形变化仍需检查通行与可读性，但不为本版新增事件密度、封路压力或危险组合。若候选路线会触发已存在的事件，先明确是否纳入该条QA路线及具体后果。

## 补给电脑与飞船方案

### 本次选择

采购入口采用船内可辨认的实体补给电脑。玩家先看见设备及用途，走近后出现明确交互提示，再在电脑界面选择商品；购买不再依赖一个不起眼的触发点突然弹出无来源的商店窗口。

导航沿用已确定的Win98界面方向。补给电脑可以使用旧式终端的模拟感，但不强制使用Win98底色；其最终配色、机壳和界面构图仍需审阅。

### MVP交互建议

```text
走近补给电脑 → 查看商品、价格与共享余额
    → 确认购买 → 相邻领取口出货 → 领取并确认装备位置
```

建议采用电脑与紧邻领取口的组合，让付款和取得实物有对应关系；具体领取方式与舱内位置待布局审阅。商品先使用现有正式装备目录，不为填满商店扩充武器和消耗品，也不要求玩家先买武器才能采矿。

| 需要看清的内容 | QA要核对的结果 |
| --- | --- |
| 商品名称、用途、价格、当前余额 | 不靠放大装备图标解释价格；选中与确认购买有明确区别 |
| 可购买条件与拒绝原因 | 余额、空间或领取状态不满足时给出原因，不扣款后让玩家猜测物品去了哪里 |
| 成交与领取 | 成功只扣款一次、只发放一次；关闭／重开界面不会再次付费或丢失待领取物 |
| 装备去向与当前携带 | 玩家知道领取后在什么位置、怎样使用，基础矿镐和手电可正常准备 |
| 多人共用 | 共享余额、购买权限及交互占用沿用既有合同；他人购买后信息及时更新，领取归属需在实施前明确 |

完整远征的起点要求基础矿镐、手电和必要购买资金就绪；起始货袋及船货为空。补给电脑采购另记一次实际购买／领取检查，不以“已有基础装备”跳过商店验证，也不把购买支出混成本趟采矿收入。

### 飞船与地图衔接建议

飞船为固定船体，飞行时以内部活动为主，落地后经同一舱门和坡道进入地表。船内外保持角色尺度、地板高度和门的位置对应；内外切换可通过船壳显隐与镜头跟随完成。

布局优先满足“舱门旁交货、附近补给、内部导航”的动线。先保证四人活动、购物和进出清楚，再决定船体最终长度；大量商品优先进入电脑目录，不要求每件商品增加一个实体货架。大型单舱、分舱、最终外观及镜头缩放仍属待审阅项。

地图制作时一并规划船体占地、支脚接地、坡道出口、附近可站空间和洞口方向。地表材质、背景与植被沿用矿区主题，避免船停在与地图无关的孤立平台上。预留停靠区不要求扩大整张矿区，也不新增运行时自动改地形系统。

## QA起点与完成标准

| 项目 | 约定 |
| --- | --- |
| 起点 | 基础矿镐、手电和必要购买资金就绪；货袋与船货为空，收益来自本次真实开采；包含一次正式航程和降落 |
| 路线 | 选择当前地图的一条完整采矿往返路线，覆盖主要通行特性和一次壁内矿物发现；暂时不要求走完整张地图 |
| 终点 | 真实采到的矿物完成交货，人员登船，正式撤离并完成结算；玩家能说清这一趟收获了多少 |
| 正常操作 | 不用传送、调试发矿、直接改余额或跳过航程凑闭环；诊断操作另记，不能冒充自然路线通过 |
| 记录 | 飞行、找路、开采、返程分别计时；标出误操作、卡点和不知道下一步做什么的位置 |

### 分环节检查

| 环节 | 本轮重点 |
| --- | --- |
| 准备与出发 | 能否理解导航、选定目标；基础装备是否够用，是否需要调试帮助才能出发 |
| 飞行与降落 | 航程等待是否合适，船位／ETA是否清楚，镜头与起降衔接是否自然，何时可以下船是否明确 |
| 地图探索 | 出生点到洞口是否好找，真实身体能否通行，跳跃／坡面／落差是否顺手，岔路是否容易辨认 |
| 地图特性 | 露头、壁内矿团、不同矿物分布是否形成实际发现；现有地形变化是否影响通行并容易理解 |
| 挖掘与采矿 | 指向是否准确、有效距离是否直观、连续挥镐是否顺畅，破岩与采矿的节奏、反馈及收益是否清楚 |
| 带矿返船 | 是否记得回路，返程耗时是否合适，地形是否造成意外卡点，返回过程是否明显乏味 |
| 交货与撤离 | 交货口是否容易找到，随身矿物／船货变化是否清楚，集合和起飞条件是否容易理解 |
| 循环结束 | 安全脱离后货物是否正确结算，玩家是否明确知道“这一趟完成了、收获了多少” |

### 货账与记录口径

入舱交货只转移随身矿物，不提前发出售收入；安全脱离后才按现行规则出售船货并确认到账，重复交互不能重复出售。分别记录各矿种采得、随身剩余、交货、售出和剩余船货数量。

初始余额、采购支出、本趟出售收入和最终余额分开记录；在没有其他经济变动时，最终余额应等于初始余额减采购支出加出售收入。若发生已允许的其他变动则逐项列明，不能用最终余额差替代采矿收益。

每次记录包含源码／配置／依赖／Player身份、地图ID与版本、人数、装备和起始状态，以及各环节耗时、卡点位置、货账前后值。按实际候选关联截图、录制或失败记录，详细证据留在执行台账链接的相应位置。

结论分两栏：流程为通过／失败／未验；体验记录可复现的问题、影响和下一步调整。例如航程过长、矿镐难瞄、挖墙拖沓和返程空跑，即使不阻断流程，也属于本轮主要改进结果。

## 制作顺序与发布门槛

| 顺序 | 工作包 | 对应模块与交付 |
| --- | --- | --- |
| 先定样板 | 明确MVP地下路线、停靠区和采矿点，核对起始装备及QA起点 | CL-01／05／06；交付可审阅路线与船舱布局，不把风格图当成可玩地图 |
| 船内准备 | 补给电脑、采购结果、交货口和导航用途可辨认 | CL-05／06／08，CL-07核对共享经济与领取关系 |
| 地图与采矿 | 正式角色走完整条路线，露矿、破岩、采矿和拾取反馈衔接 | CL-01／05／08；先解决通行与采挖，再扩内容 |
| 连通远征 | 自动航行、降落、下船、返船交货、集合撤离和结算 | CL-05／06／07／08；货物、人员和航程状态一致 |
| 候选体验与交付 | 按上述QA跑真实闭环，修复阻断与主要手感问题，形成可交付Player | 结果只写DEVELOPMENT；编译、运行、多人和独立Player验收分开 |

发布候选需满足：所声明范围可通过正式入口完成全程；不存在阻断出发、通行、采矿、交货或撤离的问题；钱和货正确且不重复结算；主要交互与完成反馈可理解；声明的人数范围和对应联机过程有证据；最终Player已按[项目验收约定](../AGENTS.md)构建并独立运行。

体验问题按阻断、主要操作／理解问题、可后续优化问题整理，由用户评审可接受遗留项。一次顺利完成只证明该候选的一次闭环，不代表全地图、所有人数、跨机器、恢复或长期重玩已经通过；发布范围中的必要合同仍需对应证据。

本轮只建立计划与矿洞讨论稿，不执行测试、构建或发布。后续实施、验收和交付按具体任务推进；MVP评审不自动关闭CL或启动后续阶段。

## 矿洞初步设计讨论稿

用户说明此前版本主要用于美术风格验证。因此保留其素材与技术成果，但MVP地图需要重新明确路线用途、空间尺度和体验验证；不能直接将风格认可视作路线、碰撞或采掘节奏通过。

### 建议先包含的内容

| 内容 | 设计用途 |
| --- | --- |
| 与飞船相接的停靠空地和短地表 | 明确离船／返船方向，展示船的实际占地，让洞口能被找到 |
| 容易辨认的天然洞口与入口段 | 让玩家理解开始下矿；不用先长时间挖一条通往玩法区的隧道 |
| 一条可原路往返的天然主路 | 用坡面、宽窄变化、可回跳的小落差组织行进；首轮必经路不依赖喷气或待定梯具 |
| 一处浅层试采点 | 很快体验命中、破岩／采矿、拾取和货量变化，也能带少量收获先回船 |
| 一处分岔与短支洞 | 出现“顺路先采还是继续深入”的选择；尽头有矿或明确线索，避免纯空跑 |
| 一处壁内矿团发现 | 看见少量露头，挖开后发现规模未知的矿团；检验局部盲盒感，不预设长矿线通往核心 |
| 一个更远的探索目标与返程地标 | 通过可见露矿或空间变化诱导继续前进；沿途用独特岩柱、洞室轮廓或背景变化帮助原路返回 |

以上是用于下一步选型的最小内容建议；数量、尺寸、矿量、矿种分配与时长尚未定案。沿路深度按距离与到达难度理解，不能只按垂直高度判断；浅层短途有收获，远端潜在总价值更高。当前已有矿种优先，不为分层另造新矿种。

### 路线候选

| 候选 | 空间与体验 | 主要取舍 |
| --- | --- | --- |
| 斜向深入主路加短支洞 | 停靠区接洞口，天然主路逐步深入，浅层小矿、岔口短支洞、中段壁内矿团、远端诱因依次出现 | 推荐先讨论；能同时看通行、发现和原路搬运，需避免画成没有选择的长走廊 |
| 横向洞厅加上下错层 | 以少量洞厅连接，矿点位于厅侧与可返回的平台 | 地标和队友位置容易辨认，能容纳多人；需防止过度开阔导致矿全被一眼看完 |
| 竖井加分层矿廊 | 主体向下延伸，每层进入横向矿廊 | 下矿感强，但返程爬升与梯具规则会抢占验证重点，建议后续再做 |

首轮建议以第一种为骨架，吸收第二种的局部洞厅；不把回环／捷径设为必做，不把跳下去却回不来的落差放在必经基础路线。高处梯具、封路事件与怪物仍按所属阶段问题处理。

```text
飞船与停靠区
    └─ 短地表 ─ 洞口 ─ 浅层试采点 ─ 岔口 ─ 中段壁内矿团 ─ 远端露矿
                                       └─ 短支洞试采
                    ←──────────── 原路返船 ────────────
```

该图只表达节点关系。洞室用不同轮廓、局部高差和背景形成记忆点，主路可以弯折但不做绕圈配额；矿团藏在主通路侧面的岩壁里，主路深入距离和局部挖入岩壁的进深分开设计。

下一步先选路线骨架，再画真实角色尺度的地形剖面：标注支脚与坡道、实际净空、落脚点、双向通行、矿物露头、壁内储量和回程地标，最后填矿量与节奏。矿洞选型与具体改图需继续讨论，本稿不覆盖已有作者地图。

## 发布前保留的问题

1. 发布对象、平台、时间、候选版本和声明支持人数；既有2–4人目标不因初次两人QA自动收缩。
2. 地下路线选型、实际长度与高差、必经／可选段、矿团规模及浅深收益预算。
3. 最终船体尺寸、单舱或分舱、内外镜头方式、补给电脑与领取口布局。
4. 成交后直接入包或实物领取的最终选择，以及待领取物的归属、满槽和多人竞争规则。
5. 主要体验问题的可接受程度及用户确认的MVP发布标准。

更长期的梯具、失败／救援、永久成长及其他未决规则继续在[CL目标与问题](EXPEDITION_CORE_LOOP_GOALS.md)维护，本计划不另立一份问题账本。
