## 生成与配置

### 作者关卡矿洞

`Res/Terrain/MineMaps/*.minemap` 为唯一可编辑的关卡输入，每图一份 JSON，原生导入为 `MineMapAsset`。在 Cave Wall Tuner 的「地图生成 → 关卡矿洞」选择资源并保存地图与航程；留空恢复原随机洞穴。新增同合同文件即可选择，无需修改角色、手电、菜单列表或网络注册。

当前五图以 H5 06–10 的 132×78 格为只读基线，逐行嵌入 264×156 格矿洞，通过新增洞庭、分岔、封岩和回程扩展。Unity 保持 16 像素格；矿洞局部偏移 (40,32)，正式地图仍为 320×192。基线材料 0／1／2 分别转换为空格／slate／带软岩标记的 slate，矿簇位置及容量保留来源；正式挖掘权限与矿层分配沿用现行规则，不复制 H5 的手感或基岩开采规则。

`ExpeditionFlowConfig.MineMap` 是作者资源引用；冻结后的纯 `MineMapDefinition` 仅作为一次后台生成输入，不序列化到共用设置，不拥有运行世界。内容指纹及预览重建身份包含完整冻结数据，切图或改通路会重新生成。天空、泊位、入口 Modifier、最终坡形、矿层分配与背景捕获仍使用正式流水线；接缝保护检查先于这些正式阶段执行。新选择只影响新局，已有地图和旧存档不自动重生成。

竖井与高洞使用真实前景结构，没有预搭梯子；搭梯／回收、痕迹观察、隐藏巢穴及 H5 交矿不在此批恢复。相关上下层通行留给后续切片与人工验证，不能以生成或画面完成宣称全程可达。

正式星球与预览复用WorldSession航程／地图配置的完整生成入口；独立预览不装配正式会话、网络或玩家存档。Modifier显式影响最终格子，启停、顺序及参数由作者草稿保存；场景和资源编辑规则见[工作台](EDITOR_WORKBENCH.md)。

前景完整地图和矿层分别由会话生命周期托管，房主保存有界权威数据。矿床静态元数据不能当作恢复最终状态的蓝图；旧按床实体、逐格对象投影或第二张权威地图不重新接入。保留矿床Prefab／Definition用于配置及来源，不因正式实例退出删除作者内容。

生成阶段、统一入口和作者数据来源详见[Modifier记录](archive/TERRAIN_GENERATION_MODIFIER_PIPELINE.md)、[生成统一记录](archive/CAVE_GENERATION_ALIGNMENT.md)和[航程工作台来源](archive/TUNER_JOURNEY_WORKBENCH.md)。这些原记录的通过数不作为当前源码验收。

### CL-01／04露矿、壁内矿脉与巢穴联合设计（待实现）

本节承接D-11及用户引用的「准备 CL-04 游戏素材」。天然通路、矿脉潜力与巢穴一起在开发端规划，审核后保存完整结果；“开盲盒”来自玩家尚未看见矿脉全貌，不在每次挥镐或揭露时重新抽储量／巢穴。若需要同图不同内容，制作并审核完整变体，具体规模仍归Q-09，不将运行时独立抽签带回正式开局。

| 空间／内容 | 联合设计目标 |
| --- | --- |
| 天然主路与岔路 | 初始基础路线以正常移动／跳跃往返，近／中／远岔路提供不同投入选择；高处记录携带梯具需求，不预置梯子 |
| 路程深度 | 建议从矿区入口沿初始合法通路到矿脉露头／接近点计距离，攀爬等另记到达难度，按阈值分档后冻结；多个接近点优先核对较近合法路径。具体起点与阈值待样板确定，不再以Y／Floor高低直接分价值 |
| 路边小矿 | 数量较多、容易接近和采集，提供有效短途收益；不把所有可见小矿都做成必须开墙或触发巢穴的门票 |
| 壁内矿脉 | 以真实可采的露头连到围岩内的矿格，玩家挖墙后逐段揭露；静态关联保留矿脉身份、露头／内部占格、储量和规模档。短脉／普通脉／富矿可作为规模模板建议，露头不保证后面一定巨大 |
| 富矿与关联巢位 | 富矿按路程深度提高伴巢概率，候选读取矿脉潜在规模、可改形范围、巢体／出虫净空和初始通路；巢口在矿体后侧或相邻围岩开口的布置为建议，具体模板／触发待定 |

深层收益高于浅层通过更贵矿种、更多储量及区域潜在价值体现；路边采矿的低开路成本让短途仍有吸引力。建议同时统计“每档区域总可得价值／高价矿占比、路边可采价值、壁内储量、开墙／行走／梯具成本”，不要只比较矿点数量；具体比例及短途收益目标尚未定案。矿种与储量在制作时冻结，玩家挖通近路、搭梯或发生塌方只改变本局可达与成本，不重抽已生成矿物。

共同生成时先规划通路及路程分档，再规划有露头的矿脉规模／价值，巢穴抽选读取这份同批计划；随后共同预留矿体、巢体／出虫点、前兆显露空间与地质区域，完成局部改形，最终生成坡形和实际矿层。矿脉潜力必须与最终格容量一致，不能先按“大富矿”放巢、最后只分到少量矿仍沿用原档位；冲突或预算不足时有界调整并记录，不无限重抽整图。现有作者矿位与基线继续受作者允许范围约束，不能为放巢静默挪走原矿。

“富矿大概率伴巢、越深越高”是已定方向，概率数值、最低／最高值、巢穴数上限及富矿门槛待联合讨论。制作工具既显示设定概率，也显示经过空间／预算筛选后的实际富矿挂巢率及剔除原因，避免参数较高却因落位失败产生不同实际分布。抽选发生在开发端；游戏中揭露、触发和出虫属于CL-04所属状态，不因客户端、视野或加载重新选择。

首轮试参可先提出近／中／远富矿伴巢概率约60%／75%／90%，仅用于开发端已有富矿候选，保留少量无巢富矿；这是待用户审阅、待实测的建议值，不是现行配置或已确认平衡。路边小矿不套用这组富矿概率，具体普通矿遭遇规则另定；空间与数量上限筛选后仍须核对实际分布，不为凑概率在无效位置强放巢。

首个遭遇建议复用已准备的伏击幼虫、虫卵、巢穴口素材，过程为“露矿 → 挖出更多矿 → 巢穴／卵显露 → 已选触发条件 → 前兆与出虫”；拟态矿虫保留为后续独立遭遇候选。该顺序、首种生物及触发格均为本次设计建议，尚未由用户定案；采真矿与巢穴触发分别处理，不能用怪物身份冒充矿格或重复发奖励。

初始天然基础路线须正确；其后梯具损坏、矿脉开挖和塌方可能切断原路，系统不保证玩家一定返回。完全封堵表示通道截面被填满，与是否可挖是两个参数；既有CL-02清障实现保留，正式清障代价、破坏来源／伤害与失败规则待确定。退避空间用于核对局部反应窗口，不代表整张地图有保底逃生路。专项回程积怪刷怪本片不接入。

### CL-01／04巢穴与地图协同生成（待实现设计）

2026-10-15用户认可浅层空巢线索、中段侧壁活巢、墙后空腔和深层碎壳侧室的布置方向，并要求巢穴生成介入地图生成、两者共同作用。以下是完整接入设计，正式生成器、作者地图、运行逻辑、协议或存档尚未按此修改；上述R2仅实现离线富矿附加巢腔子集，实现与验证状态只见[阶段台账](DEVELOPMENT.md#stage-cl)。数量、触发、危险窗口和奖励不因此成为已确认平衡值。

按同日后续D-09，以下共同生成步骤执行于开发端，生成、修整及审核后导出完整版本；正式运行消费已审核布局，不重新抽巢。固定作者图和随机候选提供不同的制作输入，共用巢穴约束、局部地形／矿层及最终校验；不由场景启动脚本或区块加载回调临时扫描空地放怪。先前关于运行开局生成候选的接线方案按此调整，具体实现仍待联合切片。

#### 当前接入基础与缺口

- 两种地图均经`TerrainGenerator.GenerateCave → PlanetTerrainGenerator.GenerateCandidate`；正式开局、航程和工作台已经复用这一入口。现有Modifier在`AfterCave／AfterSky／AfterDock／BeforeGeometry`执行，最终坡形、矿床占格和背景随后形成。
- `TerrainBlueprint`已有洞室与矿床输入，作者通路用于雕刻；`PlayableTerrain`已有最终地形与矿层来源。两者尚无完整连接描述与巢穴静态放置合同，`TerrainGenerationContext`也没有事件空间预留；审核导出／入库合同同样待补齐。
- 作者图的`Room.Id`目前传入`TerrainRoom.Kind`，随机洞室的`Kind`则是可重复类别；作者`Paths／Shafts`尚未完整进入生成结果的连接描述。需要显式区分稳定`RoomId`、类别和路线语义，不能把类别、中文名称或对象名当作巢穴身份。
- 当前新增房间矿物仍采用`Floor > 100`粗分矿种及面矿／埋矿固定容量，不能直接代表D-11的路程深度与未知规模矿脉；需承接初始路线距离、露头与壁内占格、潜在规模及关联巢位，复用现有最终矿层和采掘事务，尚未改动实现。
- `TerrainCavityConnectivity`主要检查后置改形是否保持原有空腔连通关系；它不证明原图所有房间均可达，更不证明角色身体净空、坡形、跳跃落点及无喷气返程。巢穴生成不能拿该检查替代CL-01通行验收。

#### 共同生成的顺序

| 顺序 | 地图与巢穴共同产出 | 屏障 |
| --- | --- | --- |
| 1 冻结输入 | 开发端地图生成种子、版本、角色基础运动约束、巢穴模板需求及分布规则 | Unity配置先冻结为纯数据；后台不读Prefab、资产数据库或运行State；本局运行WorldId／RNG不重新决定已审核布局 |
| 2 规划天然路线与矿脉 | 稳定洞室／连接、入口安全区、天然岔路、初始沿路深度／难度、露头与壁内矿脉规模／价值计划及高处梯具需求 | 矿脉规模先提供巢穴关联输入，巢穴空间需求同时参与规划；不以垂直高度代替路程，不生成梯子，作者图只用声明区域 |
| 3 完成基础地形与入口 | 现有洞穴、天空、泊位、入口步道及其他地形Modifier完成 | 先保护飞船和实际进出通路，不能先落巢再被入口雕刻覆盖 |
| 4 富矿关联巢位与预留 | 读取同批矿脉计划，按规模、路程深度、空间和预算抽选，预留矿体／巢体、出虫点、前兆显露与局部退避／矿层排除区 | 富矿大概率伴巢且越深越高，具体概率待定；临时预留不写成永久不可挖保护位，也不授予梯具免毁 |
| 5 局部共同雕刻 | 在允许区域内塑造壁脚凹槽／侧室、保留可挖封岩，确定朝向与贴地锚点 | 不改主路、基岩、泊位、作者基线或既有矿床；原矿位冲突时换巢位 |
| 6 最终坡形与矿层 | 全部地形修改后生成真实坡形，矿物分配避开巢口、出虫点和退路 | 排除区须进入最终矿床占格分配，不能只比较矿床中心点 |
| 7 校验并冻结 | 对最终碰撞／矿层复核落位、可接近性、退路、封岩与事件冲突，得到最终静态巢穴清单 | 捕获背景并返回开发端完整候选；获批实走等审核完成后才能导出入库，后续运行装配不再修改初始布局 |

实现沿现有生成器固定顺序插入“所有地形Modifier完成后、最终坡形前”的巢穴内容步骤，并在最终坡形／矿层之后设置只读校验屏障。局部步骤内部明确依赖顺序，不依靠Inspector列表拖动顺序保证入口、巢穴和矿物的关系；不另建通用任务调度框架。早期模板需求参与洞室规划，最终落位读取实际格子，避免只凭房间包围框判定可放置。

#### 两种地图输入与最小交接数据

作者`.minemap`拟增加有稳定身份的巢穴候选声明：所属`RoomId`、允许类型／朝向、搜索范围、允许局部改形范围及必要的退路／前兆区域。作者源负责意图和允许边界，运行选择不回写文件。此扩展须显式升级作者文件Schema与导入校验；现有Schema1文件在未增加候选前不自动产生巢穴。既有基线及接缝检查仍须在巢穴改形后重新核对，不能借已有`Seams`扩大改图权限。

开发端随机洞穴从生成中的洞室／连接意图形成相同候选，按房间构造键生成稳定`RoomId`，按局部槽位生成稳定`SiteId`；不能使用运行遍历顺序、GameObject名称或最终EntityId反推位置。地图种子相同、全部冻结输入和版本相同时应有相同结果。制作时巢穴选择／外观使用由地图生成种子、专用版本域和稳定SiteId派生的独立确定性随机流，不能消费原地形／矿床随机序列。开关巢穴只改变声明的局部改形、排除区及相关落位，不能连带重抽基础路网或无关矿物；最终选择随审核版本保存，不在游戏中重新执行这轮选择。

冻结输入指纹纳入巢穴模板／规则版本、候选声明、空间需求、分布参数及Definition关系；完整审核版本摘要还纳入最终两层地图、实际选中的SiteId、模板、格坐标、朝向和初始类型。改变有效制作输入须使预览缓存及受影响审核失效，单纯浏览、区块装卸或加载存档不重新生成。业务输入与素材表现身份继续分开，不让动画帧排序决定巢穴位置。

| 数据 | 最小内容 | 唯一职责 |
| --- | --- | --- |
| 洞室／路线描述 | 稳定RoomId、连接Id、天然主路／岔路、初始路径距离／难度分档、梯具高处、初始禁放区及通行约束 | 制作时静态空间输入，连接图不代替真实运动校验；不据此强制维护动态破坏后的全局可达 |
| 矿脉计划与关联 | 稳定矿脉身份、露头／内部占格、所属路径深度、矿种／储量／规模及关联SiteId | 生成与审核元数据，不拥有运行已采储量；真实矿格仍归同一权威矿层 |
| 巢穴模板需求 | 稳定模板键及冻结Definition GUID、巢体／出虫净空、贴附与支撑、线索占格、允许改形方式 | 只读配置；美术画布尺寸不直接成为身体或碰撞尺寸 |
| 候选槽位 | SiteId、RoomId、候选类型、允许区域与改形掩码、朝向、可选／必要标志 | 供确定性筛选；候选不等于已生成巢穴 |
| 本次空间预留 | 巢体／出虫区、线索区、退避／通路保留区、矿层排除区、与地质事件的互斥范围 | 仅在候选生成中协调资源，不形成第二张运行权威地图 |
| 最终静态放置项 | SiteId、RoomId、模板／Definition GUID、世界格锚点、朝向、空巢／占据初始类型、封岩来源／线索点及依赖范围 | 随同最终地图深度冻结；不持有活跃怪物、HP、计时、RNG进度或已触发状态 |

表中契约名只表示必要语义，不要求预建完整生态框架。作者局部格只在输入适配时统一转换为世界格；生成表使用X向右／Y向下，原生地图接口按`CellCoord(x,-y)`转换。SiteId属于本图稳定内容身份，运行唯一性还须限定WorldId／世界代次；EntityId由会话事务单独分配。

#### 选位、冲突及失败处理

1. 按D-11，以露矿引导壁内矿脉为首片发现手段，更多矿物线索后置；富矿大概率伴巢且按路程深度递增。飞船、出生与第一次基础试采的初始安全范围保留；巢体可靠矿脉后方／侧壁，显露、触发与出虫净空共同设计。旧“浅层空巢＋中段活巢”仅为早期样板建议，不再代替富矿关联规则；具体生物、概率、数量与触发待定。
2. 出虫点须位于最终空格，具备对应生物的身体净空与有效支撑／贴附；接近点、触发边界、前兆可观察位置与退出方向一并检查。不能出现前兆完全封在岩后、角色站在出生点上、怪物只能生成在墙内等结果。
3. 检查初始天然基础通路、出入口和落点，初始巢体／卵簇不以实体占据制造错误净空；高处按玩家携带梯具条件核对，地图不补梯。此项只核对初始布局，不禁止梯具在运行中被破坏或原路被塌方全堵／收窄，也不自动恢复返程；动态风险按D-11记录并与CL-02／07承接。
4. 巢穴、塌方来源／落点和局部反应空间共用同批候选信息。首片不无意叠放未审核危险，后续组合需显式规划、记录触发与后果；允许组合造成断路或探险失败，不承诺保底解法，但不能由两个独立抽签绕过完整版本审核。
5. 真正的矿床保持原采集与奖励事务。拟态矿虫使用独立遭遇身份及矿纹表现，不冒充可采矿格，也不因挖封岩同时发矿／刷虫。原矿床与巢穴足迹冲突时放弃该巢位，不静默移动、清除矿物或补发收益。
6. 候选稳定排序并设置尝试上限。可选巢位失败则记录有界原因并减少布置；必要的样板点位失败则候选明确失败，不退到飞船旁、唯一主路或错误朝向。不得为了凑巢穴数无限重掷基础地图。回退只撤销本候选自己的改格／预留，并重算受影响坡形、矿层及背景，不能冻结半回退结果。
7. 开发端分布配额决定审核版本内哪些位置存在巢穴；CL-03运行预算决定本局何时允许激活、同时有多少生物。运行准入须在前兆开始前预留额度，已开始的前兆／反应窗口不由预算随意跳过；具体等待、取消和退休语义在遭遇切片中确定。空巢不因离开视野或危险升级自动变成活巢。

#### 候选装配、运行状态与恢复

优先扩展既有`PlayableTerrain`，携带最终静态巢穴放置项和生成规则身份；不额外包一份平行的世界／地图模型。`TerrainBlueprint`及生成上下文承接空间输入和候选临时结果；`SessionTerrain`只保留相关冻结元数据。全部复制、`Blueprint()`转换、Capture／Swap／Restore及内容指纹路径要显式承接，防止转换时静默丢掉巢穴。

编辑工作台调用共同生成入口，预览最终落位和失败原因，不创建业务对象；审核导出保留这些最终静态结果。正式开局的`SessionTerrainNetwork.SelectNew／CreateAuthority`和后续航程的`ExpeditionFlowBehaviour／SessionJourneyTransfer`改为消费同一种已审核静态加载结果，而非重新生成布局；航程业务本身仍按Q-05保持原范围。后台读取校验为纯数据，主线程先按最终清单异步准备Definition／Prefab租约，再在不跨await的事务中共同安装地图、矿层、巢穴对象及SiteId→EntityId只读索引，最后激活、发布和放行Ready。资源或关系校验失败保持原世界／无半开局，迟到候选按任务身份撤销并释放。

每个活巢的触发、已显形／清理、剩余出虫额度、必要计时和RNG进度归其YYGC Behaviour／State；每个已出生生物归自己的所属对象State。纯空巢和痕迹可作为冻结站点所属的原生只读表现，不为静态装饰建立有计时的业务对象；若后续允许破坏／交互，再明确所属状态。View只画巢口、卵、痕迹和生物动作。出生事务原子验证SiteId、地图代次、出虫额度和实际占位后创建对象、登记关联并扣减额度；重复触发不能重复出生或结算。地形被玩家挖改后读取当前权威格子重新验证，不回写作者文件、不重建整张地图。

晚加入／重连取得Host当前冻结投影和同代次局部地图，区块装卸只管理表现；客户端不按种子再次抽巢，不因重新加载贴图／Prefab而重触发。生成SiteId与EntityId建立专用显式关系，不能未经合同升级塞进当前只允许作者布局键的`PlacementKey`。

正式保存须记录最终巢穴布局、所属状态、出虫／生物关系以及最终两层地图，加载时恢复已存在结果，已清巢不能按初始清单复活。当前v23基础合同仍拒绝敌方Actor，也没有巢穴字段；正式接入要同批补齐协议、严格保存字段／关系校验及版本，不得沿用v23标签偷偷加字段或丢弃状态。本轮不指定新版本号、不迁移或删除用户存档；Q-05／08中的远征循环和失败规则继续保留。

工具台需同时承接候选编辑、随机地形／巢穴分布参数、空间约束及共同预览；UI与参数分组提案见[工具台编辑方案](EDITOR_WORKBENCH.md#cl04-workbench-design)。原型示意不代替同源生成和最终碰撞校验。

## 局部装载与换区

前景和矿层分别加载可信角色／船体附近的有界区域，现有区域最多160×160格、按32格区块移动，并保留完整渲染页及原生邻格缓冲。无可信槽位时使用船体，不把闲置角色当作本地玩家。两层共用世界代次，各自维护流会话、代次和提交；同步确认见联机合同。

新区域完整区块到达后安装页面，旧区域提交不能放行新区域。后加载格和采掘变化共用ApplyCell与岩壁／柔光缓存失效入口，首次整批由Flush建立几何，不能因随后相同基线而遗漏后加载区块。

同世界同源换流先标记等待新基线，保留背景及重叠格／页面，装入新增区块后卸载退出范围的区块。前景和矿层复用同一局部装卸逻辑；矿层不因订阅Generation变化销毁宿主。RefreshingReplica为真或当前矿层尚未确认新基线／实绘时Ready为假，不累积沿用旧代次的就绪位；保留旧画面不构成新流已就绪。不同世界、撤权、断线和地图退休清理旧源／任务及绑定，不让迟到清理释放新安装的地图。

表现缓存和后台几何任务只读独占冻结局部格副本；完成核验源、区域及地形修订，旧结果丢弃。Unknown与区域外保持保守遮挡。诊断摘要只覆盖本端订阅区，不能比较不同区域摘要来宣称全图一致。

该换区修复的当前编译、缓存回归和连续移动画面仍见[待验队列](DEVELOPMENT.md#当前待验队列)；[原诊断](archive/TERRAIN_STREAMING_FIX_20261007.md)不代表最终视觉通过。

## 采集事务

矿床可以藏在墙后。拆墙只修改前景，不伤矿物或产生矿物奖励；矿格露出后才能采，部分露出不改变其余覆盖格。

选取和权威命中共同检查工具能力／实际持有、距离、射线遮挡、前景为空、地图代次、目标内容版本与货袋容量。每轮冻结工具、选择版本、目标及瞄准意图；命中时失效不转打后一层。工具配置不由请求中的伤害或客户端声明授权。

普通采集组合一层地图及角色状态，候选先校验、安装后通知。达到采出阈值后减少实际储量；尚有储量恢复耐久，最后一份清矿格。耐久、每轮产量、工具伤害及资源映射读取既有冻结配置，不在本页另立平衡值。铁／金只进入个人货袋；自动矿工、物流、出售、警戒和返航结算继续暂停。

合法手持爆破沿既有输入链作用于前景及投射物，不新增背景矿物爆破玩法。普通采集组合事务不等于意外运行故障下已验收的通用双地图原子提交。

### CL-02独立地质功能样板

`GameplayLab.unity` 是独立离线功能场景。布局来源为场景原生 `GeologyLabBlock` 的格矩形／材质，现有两段分别来自 `rift-expanded.minemap` 基线x50–89／y30–55和 `vein-maze-expanded.minemap` 基线x17–56／y8–31；原作者源只读，横向连续岩格合并为原生岩段。原生地形宿主复用正式岩壁、背景和同一权威前景；当前片段为完整格碰撞，不签署正式生成管线的全图坡形／返程通过。两份局部Definition位于 `Res/Effects/Geology/Event`，分别声明支撑消失和角色进入，未加入正式定义数据库；WorldSession原资产、规则JSON及正式玩法入口不改。运行复用ObjectSession、YYGC状态事务、GameInputActions、正式身体运动和矿镐。

事件顺序为待触发→前兆→落石→土石堆→清障完成；来源改变、实际飞行路径被结构占用或地图退休时安全退休，已触发实例不再次装备。区域只读取活动主角权威位置，空闲／倒地／登船对象不触发。前兆起拒绝矿镐对源岩的新目标及待命中动作；完整前兆结束后，源岩脱离及落石阶段同批提交。碎岩轨迹和权威落地时刻共用冻结重力／距离／错峰时间，纵向位移为½gt²，水平散开在脱离后逐渐展开，避免提前穿过相邻洞顶。每块源岩对应一个可清障区域；土堆边缘使用坡形占据，不把区域数等同实体体积守恒。

当前混合版以26颗独立碎岩为主体：4颗18–22像素大块、12颗11–15像素中块、10颗4–8像素小块，多数方形，混入切角块。`MixedRock0–3.png` 为16×16原生像素画法，100PPU／Point／sRGB进入既定Linear流程；棕褐调色板与墙壁同系。`MixedDust.png`、`MixedChip.png` 配原生Debris粒子，前兆及下落持续掉灰，触地／块间接触散出尘雾和小石粒。旧Soil、Rock及预览资产保留来源，当前Prefab改绑Mixed资源，全部集中于 `Res/Effects/Geology`。

不预排三角形或固定土堆：配置冻结时，以90Hz、7次有限接触迭代烘焙320像素／秒²重力、旋转盒分离轴接触、低回弹和地面摩擦；大小影响接触质量，侧向受作者声明的有限散落带约束。颗粒完全离开源岩孔前保持孔内净空，避免预分裂挤压穿入洞顶。私有数组形成只读轨迹，不启动运行时第二套物理世界，不消费业务RNG；事件60Hz权威时钟驱动采样和暂停。静态轨迹不响应途中临时地形改变，真正脱落／落地时重新预检，异常安全退休；正式地图、联机与保存恢复仍未接入。

落地仍复用同一前景地图及矿镐：从最终颗粒轮廓逐列推导自底向上的16像素整格包络，当前两事件分别23／24个清障区域，最多31个，不再假定源岩九格与清障区域一一对应。包络属于保守量化，颗粒间空隙及外围少量空像素仍可能有整格碰撞，边缘手感与清障成本待实景复测；没有宣称像素级碎岩碰撞通过。`RubblePile.prefab` 按同一冻结颗粒位置／角度／画法生成透明网格，仅在权威实际占用位图改变时重绘，挖除区域同步消失。事件拥有的区域经TerrainReplicaSource可选只读投影排除岩壁绘制，默认网络／地形路径及Unknown语义不变，不建立另一张可写地图。

`GeologyLanding` 分别预检源岩与推导堆积：源岩必须为未保护、无资源产出的slate；结果格互不重复且为空、无矿格、无建筑，逐层具有既有完整地面或同批下层瓦砾支撑。每颗冻结轨迹按3帧间隔连同旋转包围体积做有界采样，不能用整个包围矩形误判邻近洞顶。源岩脱离和落地是两个明确的同步事务，各自与阶段同批安装后发布通知；不会把已坠落源岩重新放回洞顶。角色占位期间碎岩已落在下方，只延后实体填格；离开后一次填入，超时安全退休而不伤人，源岩保持脱离。此安全分支及保守包络不承诺体积保全或正式伤害结果。

瓦砾使用原材质默认耐久，正式射线、冻结动作、版本及矿镐耐久继续沿原入口；清完不重触发。三层堆积需要清障，不再声明一格跳越；保留保护地面，完整返程仍需验收。粒子和碎岩只消费冻结反馈／模拟时间，暂停时不推进、不结算伤害；尘雾／石粒每类每事件最多256粒，撞击按块只发一次，石粒在样板地面作衰减弹跳并到期释放。原生粒子Prefab、碎岩贴图／材质和事件资产按[效果归属](ARCHITECTURE.md#效果资源归属)集中，不复制作者岩壁源。

场景退出丢弃本局事件和地形，不使用文件保存、网络或正式事件投影。伤害、爆破累计扰动、噪声／预算、奖励矿室和正式图集成未接入；与CL-01交接保护结构、落点、事件区域和返程方案后，再安排联机与事件恢复合同。
