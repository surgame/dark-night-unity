# 矿镐吸附与挥砍统一距离

本任务于 2026-10-02 开始，2026-10-03 继续在 Local 单一 Unity 通道验证。用户要求扩大可砍范围，使原先能吸附但提示过远的墙格可采集，并将距离归矿镐配置。

## 评估与实现

问题来自 Entry 的 `HeroMiningPointer`：只读吸附查询使用 `MiningToolRules.Reach + PlayableTerrain.CellPixels`，但有效性和服务端 `HeroMining.TryMine` 只使用 `Reach`。正式 Reach=48，因此距离 48–64 逻辑像素的真实墙面被选中却不能砍。

沿用现有 YYGC 配置合同，在 `item.pickaxe` Definition 的 `MiningToolConfig` 中将 Reach 调整为 **64 逻辑像素（4 格）**；新建配置的默认值同步设为 64。移除 Entry 额外增加的一格，前景和启用后的矿床查询直接读取同一冻结 `Reach`。权威落镐已有相同读取路径，无须新增伤害入口或平行状态。

不增加独立的吸附距离开关：两套可分别编辑的距离会重新产生不一致。统一是采集工具的固定合同，具体大小由每个工具自身 Definition 配置；选择器网格外圈仅为视觉提示，不决定触及范围。

配置入口为 `Dark Nights / 工作台 → 工具与采集能力 → 矿镐 → SharedConfigs / 工具采集能力`，字段显示为 **吸附与挥砍距离（逻辑像素）**。距离从手部沿瞄准方向量到最近真实表面，按原坡形裁剪，不按格中心量距。修改保存后在新会话生效。

## YYGC 与数据合同

- 工具继续由 `MiningToolBehaviour` 的 RequireConfig／Inject 装配，能力在 `EquipmentDefinitionCatalog` 启动时冻结。客户端选格只读副本；服务端从角色真实装备身份取得规则。
- 最近墙面、基岩与 Unknown 遮挡、目标类别／材料／等级、货袋容量、控制租约、内容版本、一次落镐与去重继续走现有校验及事务。
- 可触及的合法目标不再因预览与伤害距离不同而拒绝。挥镐期间人物移动、换装、目标被其他玩家改变或容量变化时，落镐仍须按当时权威状态校验。
- 没有修改 YYGC 框架、依赖锁、线缆字段或存档结构；协议 **22**／存档 **v15**／AMP1 schema **2** 保持。Reach 已纳入工具配置指纹，内容不同的构建和存档可能被原有内容校验拒绝；保留原档，不自动迁移。
- 保持现有人工资源 GUID、镐伤害、动作周期、命中进度和其他工具配置。

## 验证状态

复用 Local `6000.4.9f1`，经用户明确授权退出当前 Play。首轮 35 项中 20 通过、15 失败；配置／选择器 17 项、真实主菜单进入快速局并鼠标采矿 1 项、快速会话采矿与恢复 2 项通过。失败发生在两个旧夹具读取 Definition 索引时，尚未进入采矿判定；补充夹具 SetUp 调用 YYGC `RebuildLookup`，保留首轮报告并只重跑失败项。

修正后失败项专项 **15/15** 通过，与首轮已通过项按影响合并为 **35/35 个不同用例**。测试夹具初始化修正只影响两个失败夹具，已通过的配置／快速局项目不重复运行。Local Unity 导入／编译完成，真实主菜单 Play 测试结束后回到 Bootstrap 非 Play 状态。

新增回归覆盖原超距预览墙面（52 像素）、统一范围边界（64）、越界伪造目标（64.1）、工具改为32时的40像素目标、冻结距离及指纹变化。最终结果见 [机器证据](evidence/pickaxe-unified-reach-20261002.json)。本批未构建 Player、未运行独立进程联机、弱网、IL2CPP 或双机器；此前工具批次的 Player 证据不计入本次。
