# 快速测试与场景使用

2026-10-02。本批分支 `ft-20261002-quick-tests-scene-catalog`。主菜单 Debug Hub 已接入“已着陆 · 矿镐”，复用正式 Bootstrap、Expedition、YYGC 对象及采集逻辑；当前协议 **22**／存档 **v15** 不变。本轮完成 Editor 使用范围的验收：规则／保存恢复／场景合同 **21/21**、真实主菜单 Play **1/1**、快捷键与实际 GUI 点击 **1/1**，共 23 个不同用例按影响合并通过。已重启同一 Editor 验证选择记忆，并检查实际 1280×800 与 1704×864 画面。没有构建新 Player，不宣称多人快速局、IL2CPP、双机器或性能通过。

## 平时如何快速进入

1. 在 Unity 打开 **Dark Nights → 工作台 → 日常开发 → 正式游戏入口**，或选择 **快速测试 → 已着陆 · 矿镐** 打开同一 Bootstrap。
2. 点击 Play，停在主菜单；按 **F1 或反引号**打开 Debug Hub。
3. 在 **快速测试** 页点击 **启动所选测试**。首次默认矿镐项，本机记住上次的有效测试 ID。
4. 等待正式地图、背景、角色及 Ready 完成。飞船已经安全着陆并打开坡道，主角在附近安全舱外位置，装备槽 1 的矿镐已选中。
5. 按正常 WASD／跳跃操作，鼠标指向岩壁并按住左键挥镐。重测可从暂停菜单返回主菜单，再点同一入口；每次回到干净地图和空货袋。

入口只在 **主菜单空闲** 时出现在 Hub 中，帮助页、暂停菜单、连接或生成过程中、正式游戏内均撤下。第一次实现包含一个矿镐预设；选择记忆不会自动启动游戏，不改变普通“新游戏”、继续或加入。

只在 Editor 和 Development Build 提供 Hub。普通发行 Player 没有这项调试入口；本批没有构建新 Player，也不据 Editor 结果宣称独立进程联机或 IL2CPP 通过。

## 初始条件与存储

预设使用当前 WorldSession 的首个启用星球及固定种子 `DN-QUICK-PICKAXE-20261002`。它仍使用正式生成、地图业务与装备 Definition；不读取或改写旧测试存档，不绕过后续选取、触及、落镐伤害、耐久、货袋与奖励规则。正式配置无法生成安全泊位或可采岩壁附近的安全出生点时，启动报错并回到主菜单重试。

地图激活后、服务端发布初始投影前，在同一对象事务内准备一致的航程／船体／人物状态。Host Ready 接管这名预置人物，重复 Ready 不增员。已着陆和矿镐状态同时进入冻结重开基线，因此测试局“重开”也恢复此初态。保存恢复合同从 ObjectSession 中抽入 ObjectSessionPersistence，以保持手写文件上限；仍复用原先严格验证与原子候选交换。

测试存储位置为原版本化存档目录下的 `QuickTests/landed-pickaxe/`。断开后恢复普通槽位目录；测试与正式存档互不覆盖。偏好键按当前 Unity 项目路径隔离，在 Editor 存 EditorPrefs、开发 Player 存 PlayerPrefs，只记录一个稳定测试 ID。

本轮修正 `SessionTerrainNetwork` 的生成代次：断开清空候选并使未完成结果失效，取消后恢复菜单提示。没有取消纯算法线程本身；它完成后丢弃结果，生成结束前仍显示为忙，避免并发生成。`QuickTestPreset` 使用现有完整身体碰撞查询确定出生支撑与净空，提交包含所需的 `TerrainBodyCollision` 纯读取辅助文件；既有斜坡、天空及其他未提交候选不作为本轮验收结论。

早期 0 项发现不计通过；首次 Play 等待、旧提示字符串和固定屏幕坐标的测试错误均保留失败记录，修正后仅重跑受影响阶段。电脑工具原生 F1 没有形成可确认的游戏输入，快捷键通过真实 InputSystem 键盘事件验证；实际 GUI 启动由原生鼠标点击完成。GUI 专项为显式人工用例，自动全套不会运行它；运行 `QuickTestGuiPlayTests.GuiButtonStartsLandedSession` 后两分钟内点击按钮，否则失败并清理。

此次交付为 Editor 快速测试入口。若扩展到开发 Player 或多人快速局，需要对应的新 Mono 构建及独立 Host＋Client 检查；普通 Join 的预设参数仍为空，本轮没有连接远端服务器。场景内容保持原字节，未为了验收重序列化人工场景。性能与美术风格的最终评审不由本轮两个画面代替。
