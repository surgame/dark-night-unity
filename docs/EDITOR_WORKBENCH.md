## 矿洞地图工作台现行入口

入口：`Dark Nights → 工作台 → 地图与表现 → 矿洞地图工作台`，搜索`Cave Wall Tuner`仍能定位。用户已确认采用「任务导航」布局；窗口类型及原GUID保持，UITK负责导航／工具栏／生产参数，原地图渲染画布继续复用。编译、导入及未验边界见[执行台账](DEVELOPMENT.md#stage-cl)。

左侧为地图来源、空间生成、矿物分布、额外设计、画面表现、检查与使用，底部高级与兼容。中间画布常驻，右侧只显示当前任务属性；窄窗任务栏改为顶部排列，右侧原生分隔可拖动。

2026-10-22易用性修正：任务导航采用编号、主标题与职责提示的扁平列表，选中项用左侧强调条和底色标识，高级区单独分隔。画布「站点」只标实际生成的巢穴／塌方，数量对应下方摘要；保留的人工塌方草图只在「额外设计 → 塌方」且查看候选时显示，常驻颜色图例明确标为编辑草图，可定位放大。存在冲突时不会假造实际站点或允许冻结；空间页提供处理入口，详细生成日志默认折叠。切换画面表现页不会因首次属性绑定重建预览，表现Undo按工作副本身份刷新；不重新生成地图。未启用／未通过的旧草图保留作者输入，不自动迁移或清除。

1. **看新规则地图**：地图来源 →「从新规则创建／继续草稿」。工具在同一草稿内处理旧作者引用与规则互斥，并生成完整候选；不要求手工清资源框，也不保存或更换新局引用。继续在空间生成选道路、入口、矿室及空间种子；字段变更只标过期，点击更新候选才替换旧画布。
2. **打开旧作者或冻结版**：地图来源选作者矿洞后更新候选，或选择已有冻结资源只读查看。版本目录显示实际资产（最新32版），不是把离线导出自动登记成已审核图池。当前画布对象、候选是否过期、正式新局引用分别常驻；查看切换不装配。
3. **配置矿物与额外设计**：矿物分布编辑独立内容种子及预算；只重排内容保留基础空间。额外设计内切巢穴／塌方，清单与实际画布站点可选择定位。巢位仍规则落位，塌方仍每图一个人工点，完整精确字段按需展开；取格工具明确下一次点击对象，Esc取消。
4. **保存并使用**：保存地图草稿 → 更新同一候选 → 核对静态数据 → 创建冻结新版本。默认仅创建新资产；可勾选创建后同时设为新局，或之后明确将所选版本用于新局。保存输入后旧冻结引用不匹配时明确提示新局会拒绝，不以旧画布宣称新输入已生效。
5. **正式试玩**：检查与使用可打开Bootstrap，但不自动Play；用户Play后普通建房加载正式新局冻结引用。F1「已着陆·矿镐」仍走独立种子生成，不加载该冻结版，不能拿它核对所选版本。未装配候选直达隔离试玩尚未接线，窗口不显示假成功。

保存域：顶部按钮只保存地图／航程作者草稿；画面表现单独列出共享影响后保存；本机矿巢实验只保存UserSettings。Ctrl+S在表现任务保存表现，在本机矿巢实验保存工具预设，其余保存地图／航程；关闭窗口选择保存全部时先列出实际涉及域。临时拆填从不纳入保存或冻结。

高级与兼容保留旧生成步骤、旧联合配方、星球／泊位／航程、临时拆填及本机矿巢实验；仅这些原有复杂兼容绘制器保留IMGUI，不是把整个旧窗口包进UITK。新规则仅有旧入口步道时隐藏其无效参数，配置仍保留。未删除作者图、旧随机能力、Modifier、原始素材或旧版本；持久修整、多点／自动塌方和多方向生物仍未因此实现。

## 地图工作台UITK设计与迁移边界

2026-10-21用户要求先评审统一布局，随后确认「任务导航」模板并要求实施。本节保留信息架构、旧能力去向及迁移边界；现行操作以上节为准。显示名称已改为「矿洞地图工作台」，工作台菜单、窗口类型和Cave Wall Tuner搜索兼容保持；实现不代表GUI或游戏验收通过，也不自动切换默认地图。

### 问题与设计原则

- 当前左栏按历史开发批次堆叠，地图来源、生成参数、局部实验、表现与航程并列。用户无法直接判断当前画布是作者图、生成候选还是正式冻结版。
- `MineMap`、`Rules.Enabled`、`ReviewedMap`及`JointDraft`共同影响预览；新规则需要清旧引用再勾开关，属于暴露内部互斥条件，不应成为普通操作步骤。
- 保存地图／航程、共享表现、本机矿巢工具预设具有不同持久化目标；多页重复“生成新联合地图并用于新局”又把导出与装配混为一步。应分开标示目标、适用范围与写入影响。
- 一张地图始终只有一份作者草稿、一个当前候选及原生Undo链。界面选择不产生第二份配置／运行状态，也不在切页时偷偷重生成、保存或替换新局。
- 默认打开最近工作上下文并明确来源，不自动强制覆盖旧图。无草稿时显示当前正式引用，同时给出“从新规则创建草稿”；新规则和已有作者图是互斥的可见来源选项，不要求手工清空资源框。

### 布局与任务

用户已选择「任务导航」：左侧任务栏、中间常驻地图、右侧当前任务属性；「画布优先」保留为原设计对照，不另建第二套窗口或数据模型。界面保留来源、草稿状态、候选身份和正式新局引用。

| 任务 | 普通用户先看到什么 | 深层能力与边界 |
| --- | --- | --- |
| 地图来源 | 从新规则创建、打开已有作者图、本轮候选／冻结版本入口；所选版本身份与当前新局引用 | 候选列表须读取实际输入与导出，原型中的五份导出尚未成为Unity图池；导入／索引接线属于后续实现，不伪造已入库状态 |
| 空间生成 | 入口、道路、矿室配比、空间种子、更新候选 | 更多参数渐进展开；修改标记过期并保留旧画布，显式更新才替换；作者图模式不展示无效的随机空间参数 |
| 矿物分布 | 内容种子、预算、露矿／壁内分布、实际区域结果及失败原因 | 只重排内容保持基础空间，内容改形从基础重建；旧局部矿形／动画实验不混入本图参数 |
| 额外设计 | 「巢穴」「塌方」类型切换、站点清单、画布标记和选中项属性 | 巢穴现有规则落位及单个人工塌方点先迁移；生成的站点显示来源，不能因统一清单就声称支持任意新增／移动、多方向、多点或自动塌方 |
| 画面表现 | 岩壁、地下背景、点缀／遮挡与原生样式属性 | 表现草稿与共享资产影响独立保存；保留原字段及冲突检测，不因换布局丢底层调参能力 |
| 检查与使用 | 草稿保存、候选过期／冲突、静态数据检查、创建冻结版、是否设为新局 | 拟拆分创建版本与修改新局引用；旧资产／旧档保留。不把静态检查写成实机／通行／多人验收 |

地图上方固定「草稿候选／正式新局引用」查看切换，并在画布内重复标明当前对象；下方显示真实尺寸、区域／矿量／站点摘要及旧版是否仍被引用。查看切换不是装配操作。格线默认关闭，平移／缩放／定位及叠层集中在画布工具栏，逻辑／渲染网格快捷键继续尊重文本焦点。

右侧仅显示当前任务；常用字段先展示，精确参数在本任务内展开，不再把所有原生字段拉成长表。窄窗口改为顶部任务栏，属性区可折叠或移至下方，不把控件压到不可读。正式UITK实现需要核对Unity实际最小窗宽、分隔拖动、主题、键盘、中文、焦点与保存提示，不能以本轮浏览器排版代替Editor验收。

### 巢穴与塌方的额外设计层

“额外设计”是作者组织方式，不建立第二张地图或新的事件系统：巢穴仍消费同批矿群和围岩并使用既有冻结站点，塌方仍保存到`ExpeditionFlowDraft.Config.Geology`。预览与检查复用最终组合候选；站点清单、地图选择和属性检查联动，不以图标位置代替实际约束。

巢穴先显示开关、自动落位清单、关联矿体和被跳过原因；现有仅右侧出巢能力应明确，不以完整类型选择器暗示多方向已实现。局部动画／矿形回放保留为「制作实验（仅本机）」。

塌方先选效果与触发方式，再通过明确的画布工具指定源岩、落点、支撑／进入区、退避和允许改形范围，右侧保留精确坐标及全部效果参数。切换操作必须清楚提示“接下来点选什么”，退出工具恢复普通选择。首片仍每图一个人工点；冲突可定位并说明原因，不能点一下就标为通过，也不自动扩展伤害／多点。

### 旧功能的处理清单

| 现有能力 | 拟处理 | 不可误删的边界 |
| --- | --- | --- |
| 新规则、作者图、冻结版 | 纳入同一地图来源／版本流程 | `.minemap`仍是有效作者源，不因界面老就判为废弃 |
| 旧随机洞穴入口 | 从普通新建流程退出，放「高级与兼容」 | 保留旧来源复现，先核对调用与作者引用，再另行判定代码是否可移除 |
| Modifiers | 按来源显示适用步骤，高级参数按需展开 | 只屏蔽规则模式不消费的旧入口步道，不把全部Modifier当作旧功能删掉 |
| 矿脉与巢穴旧制作页 | 正式矿物参数归矿物分布，巢位归额外设计，局部回放归制作实验 | 本机工具预设、原素材和失败证据保留，不自动迁移为生产配置 |
| 临时拆填 | 明确改名「预览实验」，离开主操作栏 | 常驻“不保存／不导出”提示；不能包装为持久地图编辑 |
| 星球、泊位、航程和过场示意 | 退出地图制作主导航，转交现有星球／航程入口 | 泊位仍是地图输入，修改后候选过期；不删除自动起降业务或另造第二份配置 |
| 多处保存／冻结按钮 | 合并为可见的保存域与单一检查／导出流程 | 先列写入目标；“保存草稿”不顺带保存本机实验或共享样式 |

“退出主流程／隐藏无效参数”与“删除代码／资产”分别评审；本轮未授权据此直接删除旧素材、地图或工具。

### 操作状态与实施切片

建议流程为「打开来源 → 调空间／矿物 → 配额外设计 → 更新候选 → 保存作者草稿 → 核对静态数据 → 创建冻结版本 → 明确选择用于新局」。现有导出把创建与装配捆绑，拆分需要真实游戏侧Editor接线，不只是更换文案。快速试玩应明确使用哪个冻结版；从当前候选直达正式快速局是新增提案，未接好前不能给出假成功。

冻结门控分列未保存、候选过期、静态冲突、临时拆填等具体原因；附定位／处理入口。不把通行、净空、跳跃或自然返程加入本批门控，继续遵守D-19；静态检查与游戏验收分别记录。旧存档不随作者修改重生成。

用户确认后按以下有限切片迁移；真实进度只写DEVELOPMENT，不把本设计清单写成验收通过：

1. 盘点原窗口每项字段、操作、保存目标与引用，建立迁移对应，确认主布局及退场清单。
2. 使用Editor UITK `CreateGUI`、UXML／USS、原生工具栏／分栏／列表／属性控件搭建同一窗口；沿用`ExpeditionFlowDraft`、预览宿主和原生Undo，不重写生成器、框架或运行状态。
3. 统一来源选择、草稿／候选／正式引用提示与过期状态；接入空间、矿物和额外设计及选择联动。暂时保留必要的原生属性兼容区，不能把整个OnGUI套进容器冒充完成迁移。
4. 按确认的保存域集中接线，拆分冻结与新局装配，迁移旧制作实验并保留来源，核对实际依赖后才撤除被替代的界面路径。
5. 默认只编译并核对字段／引用；获准后再做GUI、Undo、关闭／重开、来源切换、候选过期、共享样式冲突、单点塌方／侧巢及指定版本快速试玩验收。

易用性评审重点：首次打开能说清“看的是哪张图／来自哪里／正式新局是不是它”；选择新规则不需要清空资源框；切任务不丢画布；额外设计能从标记到属性并定位失败；保存和生成不偷偷换图；所有无效操作说明下一步而不只灰掉。

## 独立浮窗与保存边界

工作台、Workshop、Viewer、地形业务、Tuner和采集校验复用独立浮窗及原草稿。新窗居中，已有浮动窗保留位置；手动停靠后再次从工作台打开恢复浮窗。切分类不自动打开工具，关闭工作台不关闭专用原生窗；Viewer按需直接打开。

窗口只保存导航／来源／匹配／搜索状态。重建／关闭释放项目Inspector、事件和调度，不提交其他窗口草稿；来源缺失显示路径，不生成资产。Play期间运行诊断可打开，作者编辑及场景打开暂停；导入／编译期间暂停工具打开，资料定位仍可用。操作实际资产前等待编译／导入屏障，保留人工Prefab、场景、Theme和GUID。

### 矿脉与巢穴制作预览

现行入口：`Dark Nights → 工作台 → 地图与表现 → 矿洞地图工作台 → 高级与兼容 → 本机矿巢实验`。勾选「启用矿巢制作预览」后画布显示同一完整候选的局部材料剖面；切回生产任务恢复正式岩壁画布。本区不启动Play或正式会话，已有临时拆填须先取消，不能误当作已纳入候选。

- 矿形：厚团、分叉、邻接矿团、错层厚带；背景矿不沿巢腔轮廓描边，矿格与前景墙／巢腔可以同坐标存在。矿体面积与总储量独立，总储量不能低于矿格数，每格至少1单位；大矿脉按原合同分成每片不超过64格的矿床初值，不增加运行对象。
- 样点：读取当前完整生成候选，有限扫描天然左侧开口、可开采围岩、连续支撑及完整封闭巢腔；保护格、基岩和原矿层不被候选占用。样点编号循环选择，世界格坐标、样点数和矿格数可见。没有合法位置则显示原因，保留上一候选，不补造作者地形来凑成功。
- 回放：先拆前景墙再采背景矿，前兆处暂停，选择继续破开薄墙或带矿后退；透视只改变遮挡显示，不重建矿形或重置回放。独立关闭巢穴保留同一矿形与矿量。当前为侧壁样点、被动原PNG与示意角色；其他朝向、实际体型／碰撞、工具范围、AI和伤害未由本页验收。
- 保存：「保存本机工具预设」或本区Ctrl+S仅写`Game/UserSettings/DarkNights/TerrainVeinStudy.asset`，参数支持原生Undo；顶部地图保存不连带提交该预设。关闭自动预览后保留旧候选并提示失效，显式生成成功才替换。
- 正式接入：旧作者图的「新矿脉上限／包含侧巢」保留在高级与兼容的旧联合配方；新规则使用作者配置中的独立参数。生产冻结／装配统一到检查与使用，本机实验不再提供重复出口，也不保存局部脚本回放。基础输入与正式冻结版不符时，新局会拒绝，需显式创建并装配匹配版本。

| 更新完整联合候选 | 使用当前草稿及整图矿脉上限／侧巢开关共同生成；失败显示明确原因，未通过的点不装入候选 |
| 保存地图与航程草稿 | 保存本图点配置；已有未保存作者源冲突仍拒绝覆盖 |
| 生成新联合地图并用于新局 | 要求草稿已保存、候选仍匹配且无冲突；冻结已预览的同一候选，不在导出时另抽布局 |

塌方页「更新完整候选」与统一更新入口相同，静态核对／冻结归检查与使用；局部矿巢形态、储量和脚本回放不直接导出成整图。顶部「保存地图草稿」包含本图塌方输入，不连带提交共享表现或本机实验。已有临时拆填时先取消，塌方编辑与导出不消费临时笔触。

### CL02塌方独立测试

从「Dark Nights → 工作台」，在工作台中选择「场景与测试 → 专用测试 → CL-02 塌方 · 大小混合版」，或顶部搜索「CL-02」打开 `CL02CollapseLab.unity`。不再保留单独的CL02直达菜单。旧 `GameplayLab.unity` 已保留GUID更名，旧菜单及首建入口退场；不要重新执行历史初始化脚本。打开不会自动Play。正常Play由既有ScenePlaySelection转交Bootstrap服务，再直接初始化本地测试会话，无需在主菜单开房。若修改场景，先保存再Play；场景不加入Player构建列表。

场景使用裂谷／断脉迷宫的两个原生片段、正式岩壁／背景与矿镐，原关卡源不改。2026-10-18修通两片段间路线；当前125个原生岩段，第一落点到第二触发区的连续地面及44像素身体净空保持。出生点X=784，第一段支撑岩在角色起点右侧一格（U=50）；黄色定位标记默认隐藏，只有显式勾选GeologyLabEntry.ShowSupportMarker才在待触发时显示，挖断后仍隐藏。第二段进入区在更右侧（U=92～95），橙色测试框保留、触发后隐藏。按用户要求先保留简单效果，两处均为3×3、9格真实源岩；下沿后续应复用普通地图地形的轮廓处理，本批未交付专用错齿模块。每处显示26颗大小混合棕褐碎岩，错峰重力下坠、撞击扬尘／石粒并形成不对称碎岩堆，支撑／区域事件分别为23／24格落地清障区；64个原生槽位是预留容量，不是实际石块数。清障使用同一权威地图，碰撞为16像素保守包络。

LabCamera的Pixel Perfect Camera在编辑态关闭，由GeologyLabEntry.RuntimePixelCamera显式绑定并在试玩初始化时启用，100 PPU／640×360／PixelSnapping参数保持；不要在编辑态手工启用该组件。Unity仍可能给场景留下无内容差异的脏标记。现行CL02在Play前以原生saveAsCopy保全到 `artifacts/scene-play-checks/`，与磁盘场景逐字节一致时允许通过Bootstrap启动，不清星号、不改写作者源；确有内容差异或核对失败仍要求先保存。重新点击工作台打开已处于活动状态的同一场景保留现有草稿，不再重开或触发多余保存提示。其他关卡门控不受本CL02处理影响。

人工测试步骤：

1. 打开上述场景，按Play，点击Game视图获得输入；应直接出现配矿镐的角色及顶部「CL-02 塌方 · 大小混合版」。移动／跳跃／挥镐沿用当前正式改键，默认A／D、空格、鼠标左键，鼠标指向挥镐目标。
2. 在起点瞄准右侧一格的低矮支撑岩（默认无黄色提示），顶部应显示「已瞄准，按住左键」。保持瞄准并按住左键，支撑岩耐久依次40→30→20→10→0，0才触发；「10/40」表示还差一次有效命中。顶部同时显示剩余击数、未瞄准／缺少焦点提示及橙色区域的方向距离。挖断后向左退，应先有约2秒掉灰／警示，再出现26颗混合碎岩加速坠落、撞击粒子与落地堆积；前兆不可解除。仅打开场景、挥空镐或站在起点不会自动触发。
3. 落地后先尝试通过，核对实际阻挡，再用矿镐逐步挖除全部清障区。应看到外观与阻挡同步撤除，顶部变为「已清障」，可走过原落点；重复进入不再触发。
4. 继续向右到橙色区域，或停止后重新Play单独重试。单独测试第二段时，先不要挖支撑岩，直接向右走约6.8个Unity世界单位，避免先被第一段瓦砾挡住。橙色提示使用锁定URP的Sprite-Unlit-Default材质、45%透明度，前置于地形且精确覆盖U92～95、V-41～-37；不受洞内光照变暗影响。实际进入第二段触发区后退开，应完整经历相同阶段；核对第二堆也能清空、实际通行且仅触发一次。不要用第一段结果代替第二段。
5. 在前兆、下落和落地期间分别按Esc暂停／恢复，事件与粒子应一起冻结。另核对落点有人时等待、离开后提交及8秒超时安全退休；当前不会造成实际伤害。观察边缘、透明缝隙、先挖底层后的悬空和卡边，记录手感问题。
6. 停止并重新Play应恢复初始地形与两事件；退出Play后保存、关闭并重开场景，核对两事件／粒子／网格引用和外观。完整人工验收及未通过边界见[CL02人工队列](DEVELOPMENT.md#cl02-manual-validation)。

独立效果作者资源均在 `Res/Effects/Geology`：`Event/GeologyEvent.prefab` 是事件Prefab，`Event/SupportCollapse.asset`／`RegionRockfall.asset` 是两份局部Definition，`Debris.prefab` 编辑尘雾／石粒，`RubblePile.prefab` 编辑落地堆积，当前材质／贴图／预览网格为 `Mixed*`。它们供测试场景复用，无需重新制作；原生人工资产不由初始化覆盖。旧Rock／Dust／Chip／Soil纹理、旧Soil材质／预览及四份旧首建脚本已移出Assets，保全清单位于 `artifacts/待清理/20261017-cl02-legacy/清单.md`；当前仍使用的 `Dust.mat`／`Chips.mat` 材质继续保留。

## 编辑态地形与草稿

## 主角地面诊断

打开 `Dark Nights → 工作台 → 运行诊断 → 主角地面接触／跳跃调试`。本地Host／离线工作台Play可开始、停止和显式导出；Client不记录权威运动步骤。只读记录不调跳跃、碰撞或土狼时间，编译Player时排除。

浮窗提供10 Hz曲线、状态、逐步和最近CSV回看。取消跟随或点曲线只冻结视图，关闭窗不停止记录；导出也不停止。最多7200步，停止／到上限／退出Play只冻结内存，SessionState跨脚本重载保留。成功开始新轮清空该轮内存、快照和导出路径，已导出磁盘文件保留；最近记录显式回看，失败保留原视图。

输入诊断schema2关联同一输入序号的本地采样、发送、权威接受／模拟处理，使用单调时钟；上限1024事件，epoch变化停止。实际Replica与Host即时展示分别标记，不能拿本地显示作为远端同步证据。导出到 `artifacts/hero-ground-trace/<时间与短ID>/` 的summary.json、steps.csv、terrain.json及jump-inputs.json；附近65×23碰撞格开始时冻结，地图版本变化另记。

“主角移动8×（快速跑图）”仅停止Play时设置、下次生效，只改变Host横向跑图；正常移动／跳跃手感验收关闭。未起跳丢支撑／近地空中只是诊断标签，结合真实格形状和轨迹判断。旧Host输入／展示修复与失败证据见[执行状态](DEVELOPMENT.md)及[主角原证据](evidence/hero-input-presentation-20261005.json)。
