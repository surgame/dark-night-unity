# YYGC 统一对象性能修正与验收

2026-09-13，接续 [U6 功能验收](YYGC_UNIFIED_IMPLEMENTATION.md)。YYGC 锁定 `745f3d2`。装配缓存及全程采样版本 `a7bb926` 已构建正式／Sample Mono，正式完整矩阵 347 项、Sample 基础／弱网各 30 项通过。其长时间容量观察发现投影积压，正在追加协议 7 的有界压缩；新 Player 尚待验证。各轮输入及原始失败证据分别保留。

## 已定位的热点

同一 Editor 中，对已冻结的 487,304 字节容量帧和只读 Worker Prefab 做同步微测量。每项预热一次、记录 12 批，原始样本保存在 `artifacts/yygc-unified/u6/performance/hotspot-*.json`。这些是定位数据，不是前台 Player 帧率。

| 操作 | 初次测量均值 | 用途 |
|---|---|---|
| 256 次真实装配校验 | 101.64 ms | 确认每次反射扫描 Behaviour 属性及绑定声明的成本 |
| 完整展示帧转换为 JSON | 39.93 ms | 确认验收驱动本身需要与正常运行负载分开 |
| MemoryPack 编码 | 1.62 ms | 记录当前完整投影的编码范围 |
| 解码、验证及冻结 | 3.69 ms | 与对象应用成本分开观察 |

仅缓存不可变反射声明后，256 次校验的两个观测均值为 16.66 ms 与 9.76 ms；环境负载会影响绝对值，不把这个变化直接换算为 Player 帧率改善。额外的类型解析缓存未显示明确收益，已撤回；最终框架修改仅保留 `ObjectAssemblyValidation.cs`。

## 本次修改

- YYGC 按 Behaviour 类型缓存所需配置类型、绑定键及组件类型。不缓存 Definition、配置实例、Unity 组件或校验成功结果；每次仍检查当前配置、工厂、能力、绑定唯一性和组件类型。
- 新回归先预热缓存，再移除配置、清空绑定、制造重复绑定，验证立即拒绝；恢复合法输入后可再次通过。
- MeasurementSeries 改为固定内存的全程直方图，不丢弃第 100,000 个样本以前的数据。分位数为桶上界，正值超过 0.000001 时相对误差不超过 1%；均值、总数和最大值仍覆盖全部样本。原尾部报告不改写。
- 客户端分别记录解码、对象准备、展示副本提交；Player 另记自动化报告耗时。`metrics-reset` 只清空诊断窗口，不修改游戏时间、状态、连接或 Ready。
- `report-detail` 可切换完整／摘要报告；容量脚本先完成完整对象、箭矢和 Ready 断言，再按参数测量摘要报告窗口，保留实际发布序号及计数。默认完整报告路径保留。
- 前台帧样本使用 Windows `GetForegroundWindow`／`GetWindowThreadProcessId`，区间两端均属于当前进程才计入；不把 Unity `isFocused` 当成 OS 证明。

1. Unity 编译、相关装配与全程采样回归；原配置和资源不因性能修正重写。最终 138/138 通过；额外类型解析候选的 139/139 单独保留，候选已撤回。ArchitectureGuard 为 280 文件、12 自检、0 错误。
2. 锁定已验证框架提交，集中构建受影响的正式 Mono 与 Sample Mono。复用本次 U6 导入缓存，不复制 Library，不重试被自动审批拒绝的清理。
3. 同一正式 Player 执行受影响功能矩阵、完整／摘要两种容量报告负载，检查耗时、GC、发布频率和预热后的 OS 工作集。Sample 使用四进程回归。
4. 普通前台完整三夜及容量采样单独验收。用户在本轮明确选择“暂不显示，保留前台验收待办”，因此继续隐藏启动，不再重复请求显示窗口。IL2CPP 与双机器限制继续保留。

`test-game-pressure.ps1` 支持 `-CompactReports`、`-DurationSeconds`、`-ForegroundRole`；`test-game-campaign.ps1` 支持 `-ForegroundRole`。前台角色为 host／client1／client2／client3，默认 none。指定前台角色时，脚本要求该进程至少 95% 的帧区间有 OS 前台证据；不足则失败，不以其他进程或隐藏窗口数据代替。

延续 [开发计划](DEVELOPMENT.md)的可用 60 FPS 目标。U0 未冻结更细的性能预算，也无可信旧架构 Player 性能基线；本次先修复实测热点并提供完整条件，不宣称原架构对比优势。容量为合成投影，Host 只有 17 个真实权威对象，不代表 256 个 AI 的完整模拟。

## Mono 测量与长窗口积压

`a7bb926` 使用同一 Player 完成完整矩阵，Entry SHA-256 为 `94ECDC51399A6E8F97C6008D6FDEF5547AE2F8FFFD0FFD46E9EE26F8D8031535`。新三夜四端各保留 113,068–255,457 个帧样本，OS 前台样本均为 0；全程直方图已经生效，隐藏窗口帧时仍不作为前台成绩。

| 容量报告方式 | 观察窗口 | 客户端帧时 p95 | 每次 JSON 报告均值 | 客户端对象应用均值 |
|---|---|---|---|---|
| 完整报告 | 30 秒 | 50.70–53.29 ms | 40.89–42.63 ms | 14.95–15.10 ms |
| 摘要报告 | 90 秒 | 28.47–29.04 ms | 5.19–5.61 ms | 14.50–14.67 ms |

两次都完成 256 实体／1024 箭矢的完整接收和四人 Ready 检查。摘要报告只减少自动化 JSON，网络仍发送 487,304 字节完整投影。90 秒后客户端落后约 2.8–4.1 秒；Host 在约 79 秒的选定窗口增长 36 MiB。进一步的 240 秒观察证明问题持续：客户端落后从 0.8–1.6 秒增至 4.6–9.4 秒，Host 在预热后约 209 秒工作集增长 76.03 MiB、私有内存增长 83.46 MiB。客户端自身内存变化很小；不能将原 18 项容量功能检查解释为无积压或内存稳定。

首次长测的 UDP 中继在固定 240 秒期限退出，短于“启动准备＋240 秒观察”，造成断网。已保留失败报告，并给中继增加显式存活时长，容量入口传入观察时长加 240 秒准备／收尾余量，同时立即检测中继提前退出。修正后的 240 秒观察通过原 18 项检查，并记录上面的持续积压；没有通过增加连接超时掩盖游戏故障。

证据：`artifacts/yygc-unified/u6/performance/player-validation.json`、`artifacts/yygc-unified/u6/compression/backlog-baseline.json`，以及 `artifacts/migration/pressure-20260913-205705-066`、`pressure-20260913-210439-061`（工具期限失败）、`pressure-20260913-211501-495`。最后三个路径均从仓库根目录起算。

## 追加修正：协议 7 有界压缩（Player 待验）

只读 Editor 探针将原 487,304 字节压缩为 10,594 字节；压缩／严格解码均值为 3.06／2.44 ms。该数据用于选择实现，不作为 Player 改善证明。

- 保留原 MemoryPack 完整投影和 YYGC 可靠同步链，在投影外增加 9 字节 `DNP` 版本 1 封套，标明原始／GZip 模式和未压缩长度。长度至少 1024 且压缩更小时才使用 GZip。
- 总包上限仍为 524,288 字节，未压缩体上限为 524,279 字节。解码分配前检查长度，验证 GZip 校验和、精确输出大小和压缩终点；拒绝截断、尾随字节和拼接成员。MemoryPack 字段与规则校验继续在解封之后执行。
- 游戏握手协议升至 7，明确拒绝协议 6／5；存档仍为 v2，YYGC 定义 wire 仍为 GuidV2。未增加依赖或修改 YYGC／FishNet。
- 原坏字段测试改为先放入合法封套，确保继续触发身份、NaN、规则键、事件和重复实体校验；另增加六个封套用例和协议 6 命令拒绝断言。
- 容量入口新增零丢包 LAN 的时效门槛：整个观察窗口内，各客户端最多落后 60 个服务端 tick（1 秒）。这是本轮明确新增的功能门槛，原报告不回填；详细前台性能预算仍未冻结。

首轮 Editor／Play 为 144/144，57.09 秒。架构检查要求把读取流拆到独立文件，修正后为 283 文件、12 自检、0 错误；最终 144/144 回归再次通过，57.63 秒；新的正式 Mono 继续验证。Sample 源码及其共用 YYGC 输入未变化，复用本轮已经通过的 Sample Mono／60 项证据。
