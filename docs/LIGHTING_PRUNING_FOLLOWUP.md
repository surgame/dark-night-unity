## GPU与至少四人性能验收任务

本节保存待执行范围与完成条件，不作为启动测试或Player构建的授权。最低支持硬件、正式分辨率、目标帧率及可用测试设备尚待确定；下列预算仅以最低目标PC、1080p、60 FPS为建议前提，不擅改作者参数，也不宣称所有硬件达标。

| 待测项 | 负载与记录 | 完成条件 |
| --- | --- | --- |
| GPU计量有效性 | 核对记录器、真实渲染帧、GPU完成及迟到回执；分开光照计算批次与完整帧；保留原／新配对和缺失项 | 同输入有效配对至少30对，并增加样本至噪声可判断；不能仅剔除与负载相关的缺失样本后签署通过；若Unity回执不可靠，调查平台GPU工具，不推算代替实测 |
| CPU尾部与GC | 静止、独立移动／转向、挖掘、换区；冻结、边界／几何更新、上传、提交分段；核对四灯SoftBlob挖掘p95及旧换区回退 | 解释可重复尖峰与分配来源；无超过测量噪声的可重复回退；原失败及候选身份保留，必要修正后仅重验受影响范围 |
| 至少真实四人光照 | 四人聚集且光束重叠、分散持续移动／转向、同时挖掘、连续换区；保留实际设备灯与作者配置；Host、Client分别统计 | 不以四灯夹具或同机四渲染进程替代真实多人结论；每负载采集数千完整帧并重复运行，足量判断p95／p99、超预算帧和持续资源增长；画面无旧灯／旧墙节点、墙后漏光或明显变化 |
| 工程预算与性价比 | 目标机CPU关键路径、整帧GPU、光照CPU／GPU、GC；毫秒差、帧预算占比、缓存命中与维护成本 | 区分静止复用和持续失效收益；确认整帧瓶颈后判断是否继续优化，不能把子系统百分比当FPS增幅；不借历史测试或旧Player核销当前候选 |

### 候选项目预算（待确认）

Unity官方建议按目标帧率和最低支持硬件制定帧时间预算，60 FPS为16.67 ms；没有统一的光照子系统毫秒标准。以下是本项目待确认的预算建议，非行业强制阈值，也非已经通过的结果。[官方性能分析建议](https://unity.com/how-to/best-practices-for-profiling-game-performance)

| 指标 | 60 FPS候选门槛 |
| --- | --- |
| 整帧CPU关键路径与GPU实际工作时间 | 分别p95≤13 ms，预留约20%余量；p99≤16.67 ms，另列超预算尖峰；扣除主动限帧等待，不将CPU与GPU简单相加 |
| 光照计算GPU | p95≤1 ms；动态更新p99≤2 ms；完整材质／画面成本另列 |
| 光照主线程CPU | 稳态p95≤0.5 ms；动态更新p95≤1 ms、p99≤2 ms |
| 光照稳态GC | 静止、移动、转向目标0 B／帧；不推广为整帧或动态重建零分配 |
| 挖掘／换区 | 分配有界、不持续积累，无可重复GC卡顿 |

## 已实现的优化与表现影响

| 优化 | 原本 | 现在 | 表现与边界 |
| --- | --- | --- | --- |
| 受光墙节点复用 | 每次渲染重新筛选候选并准备节点 | 灯具入射参数、几何和区域未变化时复用；强度归零等激活变化会失效 | 不改变光形；变更失效覆盖仍需最终回归 |
| 灯具参数与候选上传 | 每帧上传灯具向量，候选固定 16 灯槽共 32768 B | 参数改变才上传向量；候选静止帧 0 B，变更帧 1 灯 2048 B、4 灯 8192 B | 保留实际灯数和清空旧槽语义 |
| 柔阴影灯口前段共享 | 各像素及墙节点重复计算从光源到灯口的可见性 | 每灯预计算 5 个主光值和 5 个入射值，整批使用 640 B 缓冲；输入不变时复用 | 灯口到目标的遮挡仍按原规则计算 |
| 无贡献路径剪枝 | 在贡献必为零时仍进入后续计算 | 跳过零强度、超出有效范围、零权重连接和已被直射覆盖的返光路径 | 使用保守上界和浮点余量；已测画面无可见差异 |
| 重复遮挡探针复用 | 同位置的两次查询重复执行 | 复用该次可见性，保留原权重 | 不降低探针数或阴影质量 |
| 模式参数可见性 | 不生效的参数仍显示 | SoftBlob 隐藏沿墙扩展；Off、LegacyPoint、Continuous 按作用显示 | 隐藏不清除数值及覆盖位；连接半径对两种连续光形均有作用 |

软阴影、遮挡探针数以及扩大有效受光范围会增加计算；不能为追求性能自动降低作者值。当前只证实沿墙扩展对 SoftBlob 无效、单点强度仅用于 LegacyPoint，没有证据支持删除其他全局参数。参数变体样本较少且存在噪声，不能用跨变体时间差给每个参数定量定价。

## 初始批次结果（原候选）

基准为优化前冻结实现，候选身份见 [源码哈希](../artifacts/light-pruning-20261013/final-source-identity.json)。有效批次为 [完整数据](../artifacts/light-pruning-20261013/abba-final-v8/result.json)、[汇总](../artifacts/light-pruning-20261013/abba-final-v8/summary.json)及 [30 项对比表](../artifacts/light-pruning-20261013/abba-final-v8/performance.md)。同一 Unity 6000.4.9f1 Editor、RTX 5060 Ti、Direct3D 12，实际地形与照明 Shader，384×216 离屏光场；CPU 统计后端 Render，GPU 统计照明命令批次，不包含完整游戏帧。采用原／新／新／原的配对顺序。

30 个场景共 368 个渲染计时样本，7 个 GPU 回执缺失；剔除不完整配对后剩 177 对、354 个 GPU 样本。常规场景每后端仅 8 个样本，参数变体每后端 4 个样本，p95 需要补充样本确认。

| 场景 | CPU 中位数 原→新 ms | GPU 中位数 原→新 ms | GPU 降幅 |
| --- | --- | --- | --- |
| WallBand 1 灯静止 | 0.06655 → 0.04705 | 0.467584 → 0.048768 | 89.6% |
| WallBand 4 灯静止 | 0.11240 → 0.08405 | 0.611072 → 0.167680 | 72.6% |
| SoftBlob 1 灯静止 | 0.12595 → 0.07910 | 0.477824 → 0.055296 | 88.4% |
| SoftBlob 4 灯静止 | 0.11355 → 0.05775 | 0.622720 → 0.197888 | 68.2% |
| SoftBlob 4 灯换区 | 0.41670 → 0.77995 | 0.609536 → 0.496512 | 18.5% |

当前参数下旋转、挖掘和换区的 GPU 中位数下降约 14.6%–20.1%；部分 CPU 场景变慢。其中四灯 SoftBlob 换区 CPU 中位数上升 87.2%，p95 从 0.52576 ms 升至 3.90942 ms，原因未确认。单灯 SoftBlob 旋转 GPU p95 也出现升高，需要复核尾部耗时。静止及旋转的被测 Render 路径 GC 为 0 B；挖掘及换区仍有分配，不代表整帧零分配。

五张作者图、两种光形的 10 对 PNG（2560×1536）像素差异均为 0，见 [图像对比](../artifacts/light-pruning-20261013/abba-final-v8/png-comparisons.json)。浮点光场最大 RGB 差异约 2.09×10⁻⁶，30 个场景末帧也完成冻结对比。相关测试最近一批 77/77 通过，见 [测试回执](../artifacts/light-pruning-20261013/final-tests-exact-aperture.json)；该测试批次早于最后的 C# 参数上传与灯口缓存复用调整，不能作为最终全候选回归通过。最后这批缓存调整已编译并参与上述离屏对比；测试工具的停止检查随后修正，尚未编译验证。

四灯 CPU 定向复测期间，旧提交余量门槛曾触发，但测试工具没有及时停止，批次已完成。整个复测批次被排除，不能用于验收；原数据和 [无效标记](../artifacts/light-pruning-20261013/cpu-focus-v9/gate-invalid.json)保留。用户之后取消本专项提交余量限制，不追溯改变当时的证据状态。
