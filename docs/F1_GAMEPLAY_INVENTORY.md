# F1 游戏逻辑清单与移除评估

2026-10-07，针对“先整理开局后 F1 中的游戏逻辑，考虑全部移除，再逐项添加内容”的需求。范围是当前 Bootstrap 默认远征入口，源码基线为 `2079cdc`；协议25／存档v19／AMP1 schema2。这里记录现有行为和待决定的移除范围，尚未移除玩法，也未改变现行产品约定。

F1 的“远征”页配置了16个操作，连接着航程、船体、货物、舱段升级、NPC派工与远征结算。部分逻辑会在面板关闭时自动执行。要得到可控的开发起点，需要同时调整会话装配、自动推进、命令、展示和存档，单独隐藏按钮无法达到这个目标。

## F1 入口和显示条件

| 入口 | 出现条件 | 职责 |
| --- | --- | --- |
| 远征 | Editor或Development Build装配；进入会话后提供状态及操作 | 游戏侧 `ExpeditionHud` 注册，读取 `ExpeditionPanel` 的状态、按钮标签及许可。正式非开发Player仍有航程和远征业务，只缺少这张调试页。 |
| 快速测试 | 远征模式的主菜单，尚未开局且网络可启动 | 直接启动“已着陆 · 矿镐”新局。开始游戏后注销这张页；不是开局后常驻的玩法。 |
| 离线地图工作台 | 独立地形Debug场景 | `TerrainDebugPanel` 自己响应F1，含地图、岩壁、背景、显示、状态。它不属于正式会话的“远征”页，应单独决定是否保留。 |

正式场景引用 [ShipHud](../Game/Assets/DarkNights/Res/Objects/ExpeditionShip/ShipHud.prefab)，包含16个命令。旧 [Expedition模板](../Game/Assets/DarkNights/Res/UI/Expedition/Expedition.prefab)只有11个命令，不能据此漏掉驾驶等5项。F1开关及通用窗口属于YYGC；游戏侧负责注册自己的页。

## 远征页全部16个操作

下表同时列出正式航程会显示的操作和仍在资源、代码中保留的旧远征操作。可见不等于可执行；服务端还检查阶段、权限、距离、角色控制租约及支付条件。

| 操作和命令 | 实际业务 | 默认航程下的显示 |
| --- | --- | --- |
| 开始远征 `depart` | 开启地面探索，重置警戒和部分角色状态，开始设备部署。启用正式航程时拒绝这条旧开始命令。 | 隐藏；地面探索由安全着陆触发。 |
| 入仓原矿 `unload` | 将本人货袋的铁／金转移到船仓，受船仓容量及船旁距离限制。旧标签为“坡道卸货”。 | 着陆后显示。 |
| 船内卸货 `board` | 检查本人已经在船内并返回结果；当前代码没有转移货物，也不会通过按钮把舱外角色传送进船。 | 着陆后显示。 |
| 召回 `recall` | 探索转为撤收，并要求矿工回船；与设备归队、后续损失结算关联。 | 隐藏。 |
| 返航结算 `launch` | 检查撤收阶段、人员登船及设备回收，然后进入返航倒计时。 | 隐藏。 |
| 紧急返航 `emergency` | 忽略普通归队门槛，进入倒计时，到期计算未回收的货物和设备损失。界面要求4秒内再次点击确认。 | 隐藏。 |
| 机器人舱 `robot` | 房主支付铁资源，开启机器人舱；后续部署可生成搬运机器人和侦察机。 | 着陆后显示，仍要求整备或已结算阶段。 |
| 货舱 `cargo` | 房主支付铁资源，升级船仓容量。 | 着陆后显示，仍要求整备或已结算阶段。 |
| 船员舱 `crew` | 房主支付铁资源，开启矿工配置；后续部署可生成矿工。 | 着陆后显示，仍要求整备或已结算阶段。 |
| 矿工派工 `mine` | 客户端在已加载矿层中选取附近已露出的矿格，服务端给NPC矿工安排采矿任务，并检查双向步行通路。 | 着陆后显示；不是主角手持矿镐的开采入口。 |
| 补充损失 `resupply` | 房主支付补充费用并清除欠费，供后续部署恢复损失内容；不会在点击时直接补齐所有对象。 | 着陆后显示，仍要求整备或已结算阶段。 |
| 驾驶或离座 `pilot` | 太空待命时打开目的地选择；下降或着陆后申请唯一驾驶位或离座，并更新控制租约。 | 太空待命、下降、着陆时显示，标签随状态变化。 |
| 收舱试飞 `takeoff` | 旧流程召回人员和设备、关闭舱门后进入飞行。正式航程启用时拒绝。 | 隐藏。 |
| 泊位着陆 `land` | 旧试飞流程的手动着陆命令。正式航程启用时拒绝；当前正式下降走安全接地自动着陆。 | 隐藏。 |
| 取消航程 `cancel-flight` | 正式准备阶段取消航程；旧流程中用于取消收舱。 | 正式准备阶段显示。 |
| 重新派出设备 `deploy` | 当前驾驶者在停泊且探索阶段重新调用设备部署。 | 着陆后显示。 |

正常安全着陆会立即开启探索，因此舱段升级和补充损失虽然显示，仍可能因阶段条件不可执行。当前页面保留了新旧流程的条件组合。

## 面板背后自动运行的内容

| 业务 | 自动触发及影响 | 主要实现 |
| --- | --- | --- |
| 太空到星球航程 | 默认开局准备船内状态；选择目的地后后台生成地图、过场、到达同步、下降和安全着陆。 | `ExpeditionFlowBehaviour`、`ExpeditionJourneyBehaviour`、`SessionJourneyTransfer` |
| 船内及船外运动 | 船舱边界、坡道登船／下船、驾驶输入、船体携带乘员及控制租约变化。 | `ExpeditionShip`、`ShipCabinMotion`、`ShipFlightMotion`、`HeroControlBehaviour` |
| 设备和NPC | 开始地面探索会准备储物设备、炮塔、灯；舱段条件满足后创建搬运机器人、矿工、侦察机。推进部署、回收、运货、供电和自动采矿。 | `ExpeditionDevices`、`ExpeditionDrone`、`ExpeditionNavigation` |
| 警戒和战斗 | 探索时间、供电设备及采集增加警戒；达到条件后出生有限敌人，追击舱外角色；通电炮塔自动攻击。 | `ExpeditionThreat`、`ExpeditionCargo`、`ObjectCombat` |
| 货袋和船仓 | 主角／矿工采集写入角色货袋，运输和卸货转移到设备或船仓；有独立容量限制。 | `ExpeditionCargo`、`MiningToolBehaviour`、`HeroMining` |
| 损失和返航结算 | 返航倒计时结束，或者已有玩家所属角色全部死亡时结算；处理货物／设备损失、补充费用、收益、玩家恢复、敌人退休，并调用存档回调。 | `ExpeditionOperations` |
| 装备和交易 | 船内E交互出售原矿获得信用点、购买矿镐／手枪／喷气背包；四槽装备、开采、射击、爆炸和燃料逻辑另有入口。 | `ShipTradeService`、`ShipTradeHud`、`HeroInventoryBehaviour`、`HeroEquipment` |

“入仓原矿”和船内E出售是两条业务：前者转入船仓，后者把本人原矿换成信用点。旧返航结算还会把船仓原矿转为营地铁／金资源。若全部移除经济玩法，应一起处理这些状态和入口。

旧营地另保留招募、生产、建造、训练、修缮、夜袭及胜负逻辑。它们不属于当前F1远征按钮；默认远征调度也不会运行整套旧营地Tick，但仍被会话装配、命令、资源和存档引用。若目标是只保留基础开发环境，应列入扩展移除范围。氧气业务已在此前移除，不列作当前待删除内容。

来源：[默认启动装配](../Game/Assets/DarkNights/Scripts/Entry/GameSessionStartupModule.cs)、[会话能力要求](../Game/Assets/DarkNights/Scripts/Runtime/Objects/ObjectSession.cs)、[NPC与设备](../Game/Assets/DarkNights/Scripts/Runtime/Objects/ExpeditionDevices.cs)、[警戒敌人](../Game/Assets/DarkNights/Scripts/Runtime/Objects/ExpeditionThreat.cs)、[交易事务](../Game/Assets/DarkNights/Scripts/Runtime/Objects/ShipTradeService.cs)。

## 建议的可控起点

为了逐项添加内容，建议把正式开局收敛为“地图就绪，每位玩家一个可移动角色”，当前玩法作为待重新设计的内容退出运行链。下面是待决定的边界，不是已批准实施的删除清单。

| 内容 | 建议 |
| --- | --- |
| 主角基础 | 保留每位玩家唯一角色、可信控制、移动、跳跃、坡形碰撞、镜头。去掉船舱及驾驶依赖；默认不提供装备、喷气、攻击和收益。 |
| 地图基础 | 保留前景、矿层的数据和绘制，地图生成与制作工具、网格检查、局部加载、权威碰撞。采矿奖励、货袋和自动矿工退出，后续单独加入采集玩法。 |
| 联机基础 | 保留房主权威、2–4人加入、Ready、断线重连、epoch、输入租约和冻结副本。沿用YYGC既有对象体系，不建立第二套世界或状态模型。 |
| 存储基础 | 保留地图和角色的严格校验、原子保存与恢复。与玩法一起裁剪经济、航程、设备等存档内容；现有用户存档原文件保留。 |
| 开发工具 | 保留F10日志、地形工作台及只读检查。移除游戏侧F1远征操作和依赖旧玩法的快速测试；按新基线需要再加入有限的检查入口。 |
| 当前玩法 | 飞船航程、舱段成长、NPC派工、自动物流、警戒刷怪、炮塔战斗、损失结算、商店、装备使用，以及旧营地业务，均列为移除候选。 |

角色、地形和制作工具是已有的开发投入，不需要随着旧玩法一起清空。源素材、人工Prefab、场景及GUID保留；退出运行／打包引用与永久删除资源应分开核对。

后续添加顺序可从“单个工具修改一个格子”开始，再加入“单个物品的携带和使用”，然后分别讨论资源收益、交互对象、NPC、战斗和航程。每批只引入明确的操作、权威状态、保存边界及验收项，不在前一批顺带加入下一批玩法。

## 移除时必须一起处理的依赖

| 依赖位置 | 需要调整的原因 |
| --- | --- |
| `GameSessionStartupModule`、默认场景、`WorldSession.asset` | 当前默认加载远征场景并装配远征HUD；会话Definition还列出经济、波次、弹道和航程能力。 |
| `ObjectSession`、角色出生和运动 | 会话Prepare要求经济、波次、弹道能力；远征要求航程能力。基础主角出生、恢复及输入还与营地命令、登船标记和驾驶关联，不能直接删掉所属类。 |
| `ObjectSession.Advance`、`ExpeditionOperations.Advance` | 必须撤除自动部署、警戒、战斗、损失结算及船体推进；保留主角和地图需要的模拟。 |
| 命令类型、授权、处理器及输入 | 除16个远征字符串，还包括目的地、取消航程、买卖、装备使用，以及旧营地命令。删除后旧请求必须被拒绝，不能留下快捷键或服务端旁路。 |
| 展示副本、网络DTO和握手 | 当前投影包含营地、装备、船体、货物和航程；裁剪业务必须同步调整冻结复制、网络编码、类型注册及内容摘要。 |
| 存档、校验和恢复 | 当前v19保存关联状态，恢复检查航程和装备等配置。正式删除合同后需要明确新协议／存档版本，不能沿用旧格式编号掩盖语义变化。 |
| Definition、Addressables和预加载 | 启动按全部建筑、工位、单位规则准备资源。移除运行引用时同时收窄预加载及打包范围，并保留人工源资源。 |
| 测试和文档 | 替换依赖旧玩法的开局、采矿、航程及设备用例；保留历史证据身份。新基线验收不能借用旧Player通过数。 |

两种开关不足以构成精简：将 `ExpeditionFlowConfig.Enabled` 设为false会返回旧远征流程；使用 `--dn-camp-mode` 会进入旧营地。把舱段值归零也不会撤除设备、警戒和结算调度。

F1通用Hub属于YYGC，当前会自动创建窗口。游戏侧注销页可以移除业务入口；若还要求彻底取消框架F1窗口，应另列具体框架文件及方案，按 [YYGC授权约定](../AGENTS.md)取得该范围同意。本清单不涉及框架修改或升级。

## 后续实施和验收建议

1. 确定上述最小基线和扩展移除范围，在同一候选中完成基础开局、角色出生、地图及联机的接线，沿用已有状态所有者。
2. 成组撤除远征操作、自动推进及对应状态，连同选定的商店、装备、旧营地业务调整网络和存档。保留可恢复Git检查点，不长期保留可意外触发的旧运行链。
3. 按影响完成编译、架构及引用检查，以及针对基础开局、移动／碰撞、地图就绪、保存／恢复的Editor验证。
4. 每个受影响配置只构建一次Mono，复用产物验证2人／4人、晚加入、重连、加载epoch和退出；根据输入及地图通道影响安排弱网检查。IL2CPP仍需另外明确授权。
5. 检查运行和打包不再引用旧玩法，确认没有警戒增长、自动刷怪、派工、扣款或结算。此后每项新内容单独定义状态和验收，不自动恢复旧设计。

本次交付仅含源码清单、方案和文档检查；未启动／中断Unity、未运行Play或构建Player，无新增玩法验收结论。
