# Dark Nights 合作联机合同

本页维护当前会话的可信身份、权限、请求、同步、Ready、重连与epoch。当前开放操作见[玩法范围](GROUND_GAMEPLAY_BASELINE.md)，状态所有者见[架构](ARCHITECTURE.md)，文件合法性见[存档](SAVE_FORMAT.md)。版本、构建和验收状态统一查[DEVELOPMENT](DEVELOPMENT.md)。历史营地／太空方案不是当前请求授权表。

## 玩法权限

默认SharedCamp，2–4人共享营地及信用点；每位玩家控制服务端分配的专属主角。首次完整Ready直接创建worker，不扣招募资源或占用闲置角色；重复Ready不增员。当前购买、采集、装备、手电和飞船请求均走所属业务入口，不由客户端直接写资源或伤害。

| 操作 | SharedCamp普通玩家 | HostOnly普通玩家 | 房主 |
| --- | --- | --- | --- |
| 观察、镜头、帮助与信息查看 | 允许 | 允许 | 允许 |
| 合法主角输入、采集、装备／手电及购买 | 按角色控制租约和当前状态验证 | 拒绝修改 | 同一验证入口 |
| 交货入舱、集合／取消、导航／改道 | 本人租约、明确船体、位置与阶段版本验证 | 拒绝修改；仍可在操控室查看星图 | 同一业务验证；自动起降无驾驶席 |
| 暂停、倍速、保存、加载、重开、切控制模式 | 拒绝 | 拒绝 | 验证后允许 |
| Debug Hub免付费添加／移除和上帝模式 | 拒绝 | 拒绝 | 仅有效开发会话及明确调试请求 |
| 旧建造／训练／招募／修缮、直接出售、NPC／物流／旧结算 | 当前暂停 | 当前暂停 | 当前暂停，房主身份不解除范围限制 |

CampControlMode和PolicyRevision由SessionAuthority唯一写入，投影给各端，不通过转移FishNet所有权实现。暂停停止业务时间，网络、心跳、UI、合法会话控制及存储继续；不使用Time.timeScale=0停掉整个服务进程。菜单只锁本地输入，不自动暂停全房间。

当前星图候选协议35：JourneyWire沿原WorldSession可靠完整投影增加共享勘测位图、CoordinateFlight及TargetX／TargetY。位图唯一归ExpeditionJourneyState，Host只在实际移动时累加，晚加入／重连读取相同冻结结果。UI不显示未揭露节点、列表不公布总数；本轮只做显示隐藏，不声称对掌握完整配置的恶意客户端隐藏星体数据。

`SelectNavigationPoint`携带明确X／Y、本人角色／船体、控制租约与当前航线Revision；SessionCommand→SessionRequest完整冻结、SameIntent比较及归池重置均包含Y，非坐标命令须Y=0。SharedCamp／HostOnly、Ready、epoch、策略与去重沿原入口复核，Host也提交一次；未知坐标可航行，抵达仅回Orbit，不准备地图、结算或自动降落。正式星球确认另外要求已勘测且非PreviewOnly，旧驾驶及直接出售仍拒绝。Gathering／Ascent为6／7，入舱及安全交货事务不变；ArrivalSync继续等本次仍连接参与者全部Ready，超时安全等待。当前候选的独立Host＋Client、弱网／恢复结果只由DEVELOPMENT核销，旧协议34通过数不证明本批通过。

### 控制模式与切换合同

1. 开房默认SharedCamp；Ready前取得当前模式和策略版本。连接身份取可信网络上下文，客户端PlayerId／SenderObjectId不授予权限。
2. SetControlMode与请求在同一队列串行；切换增加PolicyRevision，在执行点拒绝尚未执行的旧策略意图，不支付、不分配、不自动重发。
3. 已生效操作保持，已生效任务按其原生命周期继续；暂停玩法不因模式改变恢复。切策略不改变epoch或EntityId。
4. HostOnly撤销来宾控制租约；恢复SharedCamp接回本连接仍有效的专属人物，不重复增员。UI取消失效预览，但服务端仍检查绕过UI的请求。
5. 加载保持当前房间策略，存档不能扩大来宾权限；新房间使用开房选择。权限／连接／租约和待确认请求不写入文件。

## 请求与服务端处理

业务参数明确携带协议、epoch、PolicyRevision、序号、目标EntityId／定义GUID、位置或操作值；库存调试还校验角色、明确实例、数量和版本。选择、BuildKind或本地UI下标不能代替请求参数。身份映射为可信PlayerSlotId＋ConnectionGeneration，角色输入另验控制租约及过期归零。

Host、远端和单人Host复用YYGC Gateway／Sender／Processor以及SessionAuthority处理链，Host一次输入只提交一次。客户端只显示待确认反馈，不先支付、结算伤害或修改权威矿格。

1. 业务解析前校验协议及规则／布局／定义／生成注册内容摘要，核验有效连接、epoch、Ready与操作范围。
2. 验证消息／列表／字符串上限、频率与积压；拒绝非法ID、敌方／不存在目标、越界位置、NaN／Infinity和不合法数量。
3. 以epoch、玩家槽、连接代次、请求序号去重，使用有界结果窗口；相同序号改参数拒绝，过期序号不重新执行。重复ActorIds按首次出现保序去重，不排序改变原语义。
4. 从传输回调复制不可变参数到主线程队列，不保存池化命令；处理时再次验证策略、最新目标、距离、版本、成本、库存及独占关系。
5. 同步短事务执行。资源准备await在事务外完成，不先扣款再等待；候选全部校验后安装，提交完成再通知。
6. 返回请求身份／结果及状态版本；客户端据回执结束待确认，实际世界来自冻结投影，旧页面／连接／epoch回执不能更新新会话。

可靠传输不能代替去重与原子支付。SharedCamp不授予开发者权限；普通商店仍验证距离、价格及余额，调试操作不经过经济扣款，也不直接Instantiate表现Prefab。

CL-00暂退喷气：BuyEquipment只接受手枪／矿镐，喷气请求在请求形状和交易入口拒绝；调试Give的库存事务同样拒绝喷气，不支付或增加库存版本。已有持有／燃料继续进入冻结投影，但服务端地面、平台和船舱运动不执行喷气／燃料恢复，客户端不据此显示可用能力。旧警戒能力不再装配；现有协议字段、风险零值及严格恢复合同保留。

## 同步粒度与通道

2026-10-28新地面局无船：沿原可靠完整投影发送Ship=null／Journey=null、空设备和未登船主角；仍由Host唯一创建与捕获，客户端不补船。对应Building／身份／设备数量共同校验，无船不能夹带航程或Boarded状态；旧含船投影仍按唯一船体关系严格校验。已有可空wire字段及消息形状保持，协议35不新增字段；本批实际Host本地回环与保存结果见DEVELOPMENT，不能替代独立Host＋Client验收。

CL02人工一点接入将现行协议升级为33：完整可靠投影增加最多一个地质站点的定义／配置身份及阶段、模拟时钟、退休原因和实际瓦砾位图。它与当前前景／矿层世界ID和地图代次共同校验；Host与普通Client均只读取冻结值，表现结合实际已知副本格显示，Unknown区域不冒充Empty。矿镐对保留源岩的新目标和待命中均拒绝，但不因此拒绝移动输入。换图／读档按同一事务交换事件对象和地图，晚加入不重触发已清或已退休点。当前仅完成代码、编译与静态／引用核对，双进程、弱网、晚加入和恢复尚未验收。

CL-01／04原首片使用协议32：完整可靠投影新增每图最多32个巢穴展示副本，归当前前景／矿层世界身份。休眠、前兆、幼虫位置与清理结果只从Host的TerrainGameplayBehaviour冻结，各端不按展示时钟自行触发或命中；新输入仍走既有矿镐／枪／炸药权威入口，不新增客户端清巢请求。晚加入取得当前状态，旧epoch及未知区域不绘制；双进程与晚加入／恢复验收尚待执行。

模拟60 Hz、业务倍速只有一个入口；对象可靠完整投影由YYGC StatefulBehaviour／StateSynchronizer分发。当前世界位置、身份、库存、动作与飞船从深度冻结读模型展示，不在客户端继续模拟RNG、经济或伤害。网络发送率不改变模拟规则步长，最终频率／插值效果按测量验收，不将待测参数视作达标结果。

| 数据 | 当前责任与边界 |
| --- | --- |
| 对象展示 | 会话可靠完整投影，携带epoch／revision／tick及当前对象身份、状态和只读权限；集合冻结后才发送／异步使用 |
| 前景／矿层 | 游戏侧NativeMapTransport沿独立MapWireMessage／MineralMapWireMessage广播复用原生AMP1；各自局部流，非逐矿床对象投影 |
| 请求和回执 | 现有业务／主角／调试入口，可信验证及去重；不广播未验证请求作为事实 |
| 一次表现事件 | 既有SessionEventJournal，按事件身份消费，不让晚加入重播历史伤害或经济结算 |
| 相机、选择、预览、光场和阴影 | 本地，不成为权威业务或新网络协议 |

投影发布前深度冻结列表／嵌套数据；R3订阅即复制客户端拥有的不可变副本，池状态不跨await／线程。资源未就绪时只保留有界最新投影，旧revision不回退世界；Host本地应用一次，回环重复帧／事件过滤。

### 双层局部地图

可信世界信号限定可接受地图WorldIdentity，前景／矿层共用世界代次，各自有流会话、代次和提交。兴趣区域来自服务端可信角色或船体，最多160×160格、按32格区块移动，含原生邻格及完整渲染页缓冲；不能用客户端自报位置扩张权限。

初次Ready合取对象、前景、矿层及实际本端绘制确认。无可信槽位时使用船体；不把ControllerSlot=-1的闲置角色当作本地玩家。Hello早于可信世界信号不安装，矿层按现有500 ms有界机制请求已冻结Hello；该空业务信封只用于重发请求，不创建新流或授予区域。

新区域完整区块到达后才能加载，旧提交不确认新区域。Unknown不是空格；未加载缓冲变化不装入表现。普通同世界换区等待新基线，保留背景／重叠页，RefreshingReplica期间Ready为假。断线、换世界、加载及撤权退休旧流、源、任务和页面。几何／缓存细节见[地形合同](TERRAIN_GENERATION.md#局部装载与换区)。

先验可靠完整对象投影及现有双层局部流，测量后才决定新的分块／拆流。历史运动不可靠通道、结构增量和SnapshotBegin／End建议不代表当前额外通道已接入。

## 主菜单房间与游戏内会合

正式UITK菜单在“开始游戏”页确认必要设置后立即启动同一Host会话，最多房主及三位队员，不设置开局前队伍大厅／队员准备操作。房间服务仍唯一拥有有限准入席位与临时票据；游戏Ready继续由原对象、双层地图及实际绘制流程决定。菜单会话只为新创建角色注入船舱出生策略，沿原权威短事务放入现有飞船；已恢复角色的位置不因此重置，快速测试和非菜单入口保留原策略。角色和船体状态仍归原Behaviour，不建立等待用业务世界。

LAN发现／准入使用IPv4 UDP27778，实际游戏仍为FishNet UDP27777。发现仅返回Host游戏会话已就绪且仍有空位的房间，房间在实际游戏内接收队友；浏览器已缓存行最多保留7秒，不能把发现缓存当作即时准入结果。浏览器只显示房间名、密码锁、人数及测得的查询往返时间；未知Ping用“—”，不生成演示房间或增加进行中分类。列表固定高度虚拟化、按接收预算和条目上限限制工作量，发现与挑战都校验版本和有界载荷。地址直连使用相同密码及准入；房主启动尚未就绪时明确拒绝稍后重试，不能绕过原完整Ready。取消已准入但尚未完成游戏连接的尝试发送带票据签名的离开请求；已附着连接停止后房主回收对应准入席位，不能长期占用可加入名额。

密码仅驻内存，使用随机盐、PBKDF2及一次挑战HMAC证明，不通过发现报文发送明文，不写日志／存档。开局前得到的临时票据还须在原定义兼容握手之后、FishNet完成认证之前再次证明，服务端绑定实际传输连接地址与单个占用；发现信息、请求中的Peer或客户端房间名不授予权限。此LAN协议不提供TLS加密或平台账号认证，不能据密码挑战声称抵御所有局域网攻击。无菜单房间的既有开发／验收连接入口保持原语义，不能用于绕过已建立菜单房间的票据门。

取消、退出与超时终止对应尝试并释放套接字／临时密钥，旧尝试不重新打开世界。等待页取真实准入、定义兼容、投影与Ready阶段，不播放定时成功或伪造百分比。好友来源由启动平台确定，界面不提供平台选择；当前好友服务尚未接入，入口明确提示不可用，未预建Steam／其他平台SDK或多传输层抽象。正式原生导入与实际多人验证的状态由DEVELOPMENT分别记录。

## 加入、晚加入与重连

```mermaid
sequenceDiagram
    participant C as 客户端
    participant H as 房主
    C->>H: 握手与内容摘要
    H-->>C: 可信槽位、连接代次、策略与世界身份
    H-->>C: 冻结对象基线与两层局部地图流
    C->>C: 资源准备、原子应用与实际绘制
    C->>H: Ready确认与主角请求
    H->>H: 验证可信连接并创建或恢复专属人物
    H-->>C: 控制租约和后续冻结投影
```

客户端不根据本地场景自行生成开局单位，逐实体spawn也不独自证明全世界就绪。首次基线传输期间其他玩家继续；只接受同epoch较新revision，过期首次快照不能回退。加载后各端重新Ready，超时连接不无限阻塞其余人。

普通重连通过服务端会话恢复凭据绑定原槽位，增加ConnectionGeneration，成功后轮换凭据；同槽位同一时刻只接受一个有效连接。当前保留窗口120秒、失联检测15秒，凭据仅内存保存；同进程同地址／端口重连可恢复身份，关闭程序后重新加入使用新身份。房主退出结束房间，没有房主迁移。

重连获取当前全新基线，丢弃旧连接待确认意图，不自动重放可能已支付请求。角色断开撤除控制占用，真正重连上线按现有主角创建流程处理；加载则优先接回仍有manual_control标记的合法保存主角，普通闲置角色或碰撞ID不能冒充可恢复人物。

## Host与展示副本

地表环境不增加协议字段。远景／相机视差属于本地，逐图装饰由同包Style引用的布局资产提供稳定锚点，按已同步原始背景的规范化摘要选版，其内容进入既有VisualIdentity核对；不为每棵树或草创建NetworkObject。各端只根据已确认、已加载的当前前景判断支撑，Unknown不当空格，不按订阅Generation重抽；地图／epoch更替由原TerrainPreview释放旧网格与材质。该数据接线不等于已完成晚加入／恢复的实际多人验收，范围见DEVELOPMENT。

Host也读取冻结展示。HostHeroProjection在权威模拟后只冻结本地主角值，核验epoch、槽位和控制租约，改善本地显示；远端走正式网络副本与插值。诊断记录器保留实际Replica身份，不能把即时展示当作远端同步证据。UI不持有可写State。

所有视图按epoch／EntityId绑定；对象删除／换职业／加载撤除旧绑定及插值。照明只消费持有、开关和方向副本，光场与后台缓存各端重建。

## 保存与加载

权威存档与网络读模型分开，文件只由房主处理。保存从模拟边界冻结State和最终两层地图；后台编码与原子提交见[存档合同](SAVE_FORMAT.md)，旧Godot／Unity格式拒绝且保留原文件，不从旧显示字段恢复各端相机或选择。

加载取得票据，停止业务推进／新业务请求，网络心跳继续。候选对象／地图完整校验并在未激活上下文准备，失败保留当前世界及暂停／倍速。同步提交后增加epoch、撤除旧Ready／去重窗口／副本缓存，发布同一新基线；当前控制策略保持。旧epoch命令、输入、地图及回执不能污染新世界。

## 联机验收重点

- 独立进程Host＋Client，按当前范围覆盖2人／4人、正常／弱网，同一配置构建一次复用。
- 购买竞争、非法距离／目标／数量、Host单次执行、重复序号不重复支付；普通Client不能取得调试权限。
- SharedCamp／HostOnly切换、队列旧策略、权限撤销和动作取消；加载不恢复旧房间策略。
- 对象及双层Ready、分散区域、晚加入／重连、流换代和乱序；旧revision／epoch不回退或写回。
- 采最后一份、工具切换／移除、个人货袋、手电持有／开关及投射物副本一致，保存／加载／重启恢复。
- 暂停时心跳、UI、连接和受支持会话操作继续；房主退出结束原因明确。
- 非法／旧档保留当前世界，恢复后真实控制租约重建；冻结读模型不持有归池状态。

当前结果和未完成组只在执行状态核销。暂停玩法的建造、训练、NPC、三夜、旧航程及结算矩阵不默认加入当前验收；IL2CPP和双机器条件分别保留。
