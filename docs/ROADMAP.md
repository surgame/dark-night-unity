## 3. CL模块拆分与交接

以下每张模块卡是任务分配单位，可以继续拆成列出的有限切片。卡片不指定新类名或第二套状态系统；具体状态继续归既有YYGC Behaviour／State或会话原生地图。任务启动时在DEVELOPMENT登记负责会话、分支／工作区、输入身份及拟改文件。

### CL-00 基础能力与旧逻辑退场

- 产出：喷气背包暂退、旧威胁退场的明确运行边界；手电仍占一格。
- 切片：引用与保存关系盘点 → 购买／装备／调试／运行入口处理 → 旧威胁引用及消费式警戒退场 → 合同与待验更新。作者资源、原GUID、原始证据和用户存档保留。
- 输入／交接：按D-01／03及Q-05／07明确旧档与遗留状态处理，向CL-01提供基础跳跃、可破坏材料、装备能力；向CL-03提供新威胁接入边界。
- 依赖与检查点：可先独立盘点；正式地图通行判断不能继续依赖喷气。对应G0，不以删除文件数量判定完成。

### CL-01 矿洞空间、矿室与返程

- 产出：至少一张初始天然主路／岔路可原路往返的联合样板，以及开发端审核入库、游戏内加载完整版本的路径；按沿路距离及到达难度递进矿种价值与储量，露头引导镐挖壁内矿脉，路边小矿提供有效短途收益；高处依赖玩家携带梯具，不考虑回环，动态破坏后不保证返回。目标及[已答QA与余项](EXPEDITION_CORE_LOOP_GOALS.md#cl01-map-qa)见阶段文档。
- 切片：空间合同与基础主路往返 → 矿室收益／线索与回程 → CL-04共同生成及预览 → 完整版本审核导出／加载 → 不同路线结构的有限图池。按D-09不以运行时随机拼图为交付要求；`.minemap`继续是作者源，导出结果可追溯且不由运行事件反写。
- 输入／交接：消费CL-00基础运动与采掘能力；向CL-02／04交付初始沿路深度、露头／壁内矿脉关联与富矿档位、站点、初始保护结构、可破坏／封堵范围及后果；向CL-08提供发现、原路及梯具损坏反馈。可挖性和代价须记录，不把动态返程保证作为自动修路条件。
- 巢穴协同：按D-08／09／11与CL-04合并开发；富矿潜在规模与路程深度参与巢穴选择，富矿大概率伴巢且越深概率越高；巢穴净空需求参与局部空间规划，地形、最终矿层与静态巢位共同审核冻结。概率数值、首种生物和触发待定，详见[联合设计](TERRAIN_GENERATION.md#cl01-vein-nest-design)。
- 协作边界：联合实施指定生成、导入、导出及公共状态文件的单一修改方，CL-02仍可独立完善机制；D-11已定携带／可破坏梯具，取得、数量、占格、搭建及回收等细节通过Q-01／02保留。当前仍只整理设计，不据此宣称高洞已可达或分配另一会话实施权；不自动启动测试、Play或Player。对应G1、G2、G3。

#### CL-01／04联合实施切片

以下是合并开发的依赖顺序；同一会话可连续实现，地图空间和巢穴行为仍各有唯一状态归属，不另建运行世界。

| 切片 | 主要交付与修改归属 | 完成／交接条件 |
| --- | --- | --- |
| A 路程分区与矿脉合同 | CL-01主责天然通路、稳定身份、初始路径距离／难度分档及露头／壁内矿脉关联；CL-04提供关联SiteId及模板空间需求；盘点基础路线和携带梯具高处 | D-11已答方向不重复提问，细化距离阈值、矿脉预算和梯具参数；作者Schema、坐标及允许改形范围一致，初始通行与动态风险分开 |
| B 首张露矿／富矿联合样板 | CL-01负责路边短矿脉、镐挖后延伸的富矿和远端更高收益；CL-04按富矿档位／路程深度共同规划关联巢位；CL-02提供可全堵／收窄的候选及后果 | 标清初始基础往返、无预置梯子的高处、矿脉潜在规模与封堵风险；不要求回环或保证事件后可返，具体改图／梯具／验证范围在切片中明确 |
| C 开发端共同生成与编辑 | 统一修改方沿现有生成入口完成有界候选、矿脉计划与富矿巢穴条件抽选、局部改形、最终坡形／矿层和同源预览；沿Tuner草稿、Undo及显式保存 | 预览沿路深度、真实露头／壁内储量、富矿关联巢位、矿层互斥及封堵风险；抽选读取同批矿脉计划，记录预算／空间剔除后的实际挂巢率，可选失败有界 |

空间生成、导出和运行加载可以先于完整战斗产出，但带活巢的版本必须补齐其实际行为及事件后果证据才能声明组合已审核；可能断路／失败是允许的玩法结果，不自动补梯或修路。入库数量／变体范围保留于Q-09，不能先批量生成再省略逐图审核；经济／撤离／远征保存未决仍按原模块处理。

### CL-02 地质事件：落石与局部塌方

- 产出：带前兆与反应窗口的局部事件，能改变路线或揭露奖励；按D-11允许完全封堵或收窄原路，不保证动态破坏后能返回。具体可挖性、清障代价及伤害仍由切片确定，原无伤害独立样板边界不因目标更新自动改变。
- 切片：事件位与触发条件 → 前兆／取消或退休 → 有界落石及权威影响 → 局部地形改变／安全检查 → 奖励空间与矿洞集成。
- 输入／交接：消费CL-01事件位和保护区域；向CL-03报告扰动及事件预算占用，向CL-07交付触发身份、阶段、地形变更和必要保存字段，向CL-08提供线索与结果反馈。
- 并行边界：可先用任务专属最小样板制作机制，不等待整张矿洞完成；不修改他人地图、共用场景或通用生成器。正式集成需Q-01／06及地图接口就绪。对应G2。

首个已授权切片（2026-10-14续接“介绍 CL-01 矿洞空间与返程”）：用户选择支撑岩破坏和进入区域两种触发，先独立功能开发，允许专属场景供后续场景功能使用；本批先做地形与清障，不含伤害，前兆后只避让、落地后矿镐清障。执行顺序：受控空格填岩事务 → YYGC单事件状态机和冻结反馈 → 原生独立场景装配／正式运动与矿镐 → 编译、引用核对与提交。事件不接入正式地图或存档；后续集成前再明确伤害、事件恢复、噪声预算与返程规则。

2026-10-15用户追加体验要求：以之前制作的真实游戏场景及既有岩壁美术为基础设计塌落部位、下方堆积和灰尘／石粒；碎岩应独立下落并符合重力加速直觉，不能以整块矩形匀速位移交付。先在既有作者矿洞片段检查局部坍塌、落地碰撞及矿镐清障，所有效果资产统一沿 `Res/Effects`；实际进度、证据、内存门控和正式集成边界仍只写DEVELOPMENT。

同日用户调整落地设计：改为区别原岩壁的松散土石堆，承担局部阻路并允许清障；土纹、碎石及坡面作为专属效果制作，不复用岩壁块外观。斜面须对应实际碰撞，局部土堆不自动扩成全图事件生成或新的材料／经济系统。

随后视觉审阅选择大小混合方向：保留缩小60%后认可的方形中颗粒，混入少量大块、小碎屑、分段崩落和落地尘雾，颜色对齐墙壁棕褐色，不预设三角形。继续重做Unity粒子、阻路与矿镐清障，效果目录保持归一；“能砸死人”只授权重量感表现，实际伤害／死亡规则仍另行明确。

### CL-03 新时间威胁、噪声与遭遇预算

- 产出：不可逆的全局危险进程，局部声源响应，敌人／事件数量与频率有上限。
- 切片：计时／暂停／阶段语义 → 阶段反馈与有限敌人档位 → 至少一种爆破同时影响局部生物和全局危险 → 特殊事件预算、冷却与重叠限制。
- 输入／交接：CL-00旧威胁退场边界和Q-07；消费CL-02／04触发报告；向事件模块给出预算准入结果，向CL-08给出只读危险阶段。
- 并行边界：计时与事件准入设计可独立进行；正式噪声链需要具体生物响应，不能只显示加速数字。调度只控制密度，不另拥有地图、敌人或事件状态。对应G2。

### CL-04 生物遭遇与可利用危险

2026-10-18按D-14扩展[多方向出巢与矿巢共生](TERRAIN_GENERATION.md#cl01-nest-orientations)：由局部地形、重力及生物能力选择侧壁钻出、顶部下落、低处沿坡爬出或斜向转出，矿群与巢位可共同规划，保留无巢矿与深层富矿的非必然关联。后续样板先审阅不同出口、破壳范围与剩余矿的关系，再验证身体／支撑／落点；不由横向演示推定所有朝向或跳跃／攀爬能力已实现。

- 产出：至少一种拟态／伏击生物，线索、显形、追击和撤退可理解；与隐藏矿室或地质事件形成组合。
- 切片：与CL-01联合完成空间合同、开发端协同生成／编辑和预制导出 → 首张样板落位及审核版本加载 → 选定首个有限遭遇与前兆／反应窗口 → 噪声感知／追击边界 → 与矿室、塌方组合。
- 输入／交接：按D-08／09向CL-01提供巢穴空间／出虫／线索／退路需求，静态分布在开发端与地形共同冻结并审核入库；运行消费已审核布局及CL-03预算／声源，所属状态和关系交CL-07同步及恢复。地图预制不冻结生物AI／触发时钟，也不批准运行时重抽巢位。H5巢穴仅作参考；[协同方案](TERRAIN_GENERATION.md#cl04-generation-design)尚未实现。
- 并行边界：单一遭遇可先在专属样板制作；毒气、电水、猎手、偷矿兽和连锁气囊后置，不混入首个切片。对应G2、G3。

### CL-05 采集、搬运、货舱与现场补给

- 产出：个人携货与船内保全的明确分界，入库只转移一次，现场消耗不重复参与出售；首次交付有可感知收益。
- 切片：携货／容量反馈 → 近船入库事务 → 现场补给消耗 → 交付／消耗／剩余货账交接。
- 输入／交接：复用现有采矿与货袋；给CL-06结算提供明确货物流转记录，给CL-07提供重复请求、竞争、断线和保存检查入口。
- 并行边界：可先研究并设计入库和防重复事务，Q-03之前不确定奖励分配或永久装备归属；具体补给与槽位涉及Q-02／09。对应G1、G3。

### CL-06 飞船、撤离、结算与再开局

- 产出：飞船作为交付／补给／撤离节点，正式入口可完成撤离与新矿区循环，最小跨局成长带来下局动力。按D-15以星球探索为主、固定飞船且不做DIY，先用可操作船舱原型审阅准备动线与起降反馈，具体布局和自动化程度不预设为已确认。
- 策划入口：[飞船远征与星图导航草案](SHIP_EXPEDITION_DESIGN.md)。按D-16纳入连续船位、星图／列表联动、全员目标抵达时间和目的地危险信息；危险与多星球节点先用mock，不扩展正式主题。撤离出售方案与原CL-05首次交付补给目标的节奏差异须先审阅。
- 开发入口：[执行方案F0至F6](SHIP_EXPEDITION_IMPLEMENTATION.md#实施切片与依赖)。复用现有YYGC航程状态、命令与可靠投影、事务、Ready、地图候选和存储；先合同与导航配置／反馈，再入舱、自动航程、结算及原生资源交付。F3／F5跨CL-05，候选／恢复由CL-07参与，HUD由CL-08承接；不因计划建档恢复旧航程或授权框架修改。
- 切片：自动到达与正式节点入口方案 → 撤离提出／集结／取消与紧急规则 → 成功／失败结算 → 至少两种永久升级 → 飞船上的关卡选择循环方案。Q-05已明确本轮保持菜单与循环现状，不以“继续同一局／开始新局”预设入口。
- 输入／交接：消费CL-05货账、CL-07人员／救援状态、CL-01新矿区；Q-03／04／05／08／09按对应实现前处理，不通过调试起飞冒充撤离。
- 并行边界：可以先做流程与界面方案、会话边界设计；运行结算须等货账与玩家规则就绪，不重复建设旧航程或自由飞行。对应G3。

### CL-07 合作、救援、权威同步与恢复

- 产出：两人所见事件、货物和地形一致，可互救和共同撤离；支持各新增模块必要的晚加入、重连和保存关系。
- 切片：每模块状态归属／命令与投影核对 → 倒地与救援事务 → 事件／货物／局部地形同步 → 存档恢复／矿区代次 → 两人完整过程验证。
- 输入／交接：从各模块首个切片开始参与，不留到全部功能之后“补联机”；用户规则涉及Q-03／05／08，技术遵循[联机](MULTIPLAYER.md)与[存档](SAVE_FORMAT.md)合同。
- 并行边界：每个模块自己保证服务端权威，CL-07负责交叉核对与集成，不另外建立平行状态模型；协议／存档共享文件指定单一修改方。对应所有检查点，G3集中闭环。

### CL-08 玩家反馈、线索与体验记录

- 产出：背包／货舱、危险阶段、队友状态与撤离意图可读；关键事件有多种线索；能复盘一局选择。
- 切片：沿用现有HUD／交互的呈现方案 → 各模块只读反馈 → 有界指标记录 → 阶段评审摘要。
- 输入／交接：消费CL-01地标、CL-02／04线索、CL-03危险、CL-05货物和CL-06／07人员／撤离状态；不在UI结算经济、伤害或推进事件。
- 记录：首次交付时间、返程耗时、撤离阶段、已保全／未保全价值、特殊事件次数／类型、失败原因、最大同屏敌人及同步异常。指标需候选身份，不新增无限日志队列。
- 并行边界：只做本阶段决策所需反馈，Q-06之前不以大规模光照改造替代危险可读性。对应G1–G4。

开发顺序和集成顺序分开：地图与塌方可同时产出，集成时按真实依赖衔接。计划支持多个会话分工，不自动启动子代理、另开聊天、创建worktree或第二个Editor。

| 可并行的工作包 | 各自产出 | 集成前置 |

| CL-00基础退场、CL-01矿洞路线、CL-02塌方样板 | 能力边界、地图／事件位、独立事件机制 | 正式矿洞通行需CL-00边界；塌方进正式图需两方接口和返程规则 |

## 5. 台账字段与状态流转

DEVELOPMENT每模块保留：ID、工作状态、负责会话／工作区、当前输入与产出、验证／证据、阻塞或未决ID、下一步、更新日期。必要的详细回执放原证据目录，行内链接，不把日志全文塞进表格。

- 工作状态：`待开始 → 进行中 → 实现待验证 → 待集成／待用户确认 → 用户确认完成`；需要等待时用`受阻`并说明具体原因和可继续部分。进入后续状态必须有事实依据，可因新缺陷返回进行中。
- 验证单列：`未执行／静态核对／编译通过／定向验收／失败／待验`并注明范围。UI样板、H5、单人和离屏结果不能代替正式双人完整体验。
- 负责会话未分配时写“未分配”，不推测其他聊天已接手。交接后保留来源身份和未完成项，不隐去失败。
- 阶段状态独立于模块状态：模块全完成也只能提出阶段评审；用户明确确认后依[阶段退出流程](EXPEDITION_CORE_LOOP_GOALS.md#8-阶段结束与约束解除)解除CL临时规则。
