## 3. 优先改动：洞室缩小

当前网格为 320×192、16 像素／格；生成器固定 12 室，普通洞室宽 38–50 格、高 18–25 格，裂隙宽 28 格、高 29 格，中心列间距约 77 格、行间距约 43 格。角色碰撞体宽 10 像素、高 22 像素；空间调整以这个真实碰撞体与实际镜头为依据，不以 12×12 角色贴图尺寸代替。

建议先保持格子密度、角色尺寸与整张网格尺寸，调整洞室净空及局部布局。直接缩放地图 Transform 会连带改变像素、移动距离和碰撞；只缩房间而保留原中心点，则会把多出的空间变成长通道，仍然空旷。

| 参数 | 第一轮调参候选，非冻结数值 |
|---|---|
| 普通洞室外接范围 | 宽 22–30 格、高 10–15 格；约为原线性尺度的 60%–70% |
| 竖向裂隙 | 宽 12–18 格、高 18–24 格，配置中途落脚点 |
| 矿房／中继洞室 | 宽 28–36 格、高 14–18 格；少数保留作空间对比 |
| 通道 | 通常净高 3–5 格，局部宽窄变化；按身体扫掠验收坡口、顶坡和转角 |
| 中心间距 | 普通房横向先试 45–60 格、纵向 25–35 格，再按房间包围盒／岩体厚度求布点 |
| 岩层及返程 | 先试房间之间最薄完整岩层不少于 4 格；岩棚高差由有限燃料运动实测约束 |

先制作固定三室样板：入口／小矿室／较大中继室，带一条回环、一处软岩封堵、一段往返竖井、一处斜面矿物覆盖。样板通过后再推广随机；房间数量先不作为缩小的替代方案。飞船停泊点只做满足飞船与四设备的局部地表整平，不重新铺满旧正式营地的 72 列平地。

生成配置增加明确的洞室尺寸、布局和生成版本参数；修正随尺寸变化的悬挑、阶地、坡形与矿物分布。给被截断的连通、过厚必经封堵和无法返程的落差设置生成失败／有界重试，保留失败 seed。冻结旧向量，新增新版本夹具，不能重新生成旧预期来掩盖变化。

验收：固定样板用正式主角步行、跳跃及有限喷气从飞船往返；无 Tab、传送或无限燃料。随后 100 种子静态几何／确定性检查，并对每个种子的指定 Demo 必经路线做能力约束往返检查；抽样实际 Play 复核近景。可选深区允许装备门槛，但必须标记需求，不能将整图都称为基础装备可达。

## 4. 优先改动：背景墙矿物与透岩矿光

### 4.1 数据与碰撞合同

矿物沿用独立 `MineralDepositBehaviour/State`，每个矿簇一个稳定身份、明确资源类型、位置／覆盖范围、容量与剩余量。不为每个像素／矿点生成业务实体。背景墙是持久装饰承载层，前景岩体破坏不删除背景墙和矿床；首版不开放背景墙破坏。

地形格只表示岩土、坡形及保护／破坏能力。新远征生成器不再写 copper／iron／gold 实心材料作为矿物，不用“矿石 tile 无碰撞”解决；需要用普通岩格替代其原岩体，独立记录背后矿床。保留历史图集和夹具的身份，不重排已有材料 ID。

渲染层次：远景 → 后壁 → 矿簇 → 前景岩体（含矿光）→ 人物和交互提示。矿簇没有阻挡人物的碰撞体；可使用只读命中区域供选择，不能加入权威 Solid 查询。人物走过已露出矿簇不减速、不被顶起；覆盖它的前景岩体仍正常阻挡。

### 4.2 行为真值表

| 矿床状态 | 前景覆盖 | 画面 | 玩家采矿与破坏 |
|---|---|---|---|
| 有余量 | 全部被岩覆盖 | 岩体表面显示矿种对应的微光／裂纹色，不直接穿透显示完整矿簇 | 挖掘先作用于挡路岩体；不能隔岩扣矿 |
| 有余量 | 部分露出／斜面覆盖 | 露出部分绘制矿簇；覆盖部分仍显示局部矿光 | 只允许射线可达且在有效距离内的露出采样点 |
| 有余量 | 完全露出 | 后壁上显示矿簇和有限局部辉光 | 可采集；不改变地形格与人物碰撞 |
| 枯竭 | 任意 | 熄灭矿光，可留低对比残痕 | 拒绝再次取矿；读档不能恢复容量 |

覆盖由“矿床范围＋当前权威格／坡形”推导，不能再持有一份可写覆盖格地图。表现可以缓存同一合同的计算结果。后台没有矿物快照时不得从旧材料伪造矿光；地图和矿床达到同一世界基线后才开放交互。

`HeroMining.TryMine` 的射线入口和 `TryDeposit(targetId)` 的直接目标入口必须共享范围、视线、容量、冷却与装备校验；现有直接入口不能成为隔墙采矿后门。首版建议炸药只移除获准破坏的前景岩体、露出矿床，不自动远距离收矿。岩体破坏与矿床产出分开结算，移除远征路径中“破矿格奖励＋矿床奖励”重叠来源。

### 4.3 光照实现与验收

扩展现有 `CaveVisualSource` 输入矿床冻结副本，`CaveLightField` 改用矿物源的颜色／强度；岩体 shader 叠加受剩余量、距离和覆盖深度约束的表面发光。已露出矿物可照亮近处后壁；深埋矿只给局部线索，不把整块厚岩染透。光色来自明确的资源配置，不能继续仅靠 RoomKind 推导资源种类。

地形变化、矿床余量／枯竭和设备照明变化使相关页面及有界光照邻域失效；静止地图不逐帧重建。当前 `CaveVisualSource.Flush` 会重建整张光纹理，需测量并按影响范围优化，不能把旧“局部地形刷新”当成光场已局部更新。仍用 Linear、Point 像素边缘，曝光／发光不改变采矿范围。

必测：平地与 12 种坡形覆盖、走穿露矿、隔墙直接请求、两人采最后一单位矿、满包不减矿、重复请求不增产、爆破露矿、矿尽熄光、跨区块矿簇、晚加入、暂停、读档恢复和旧 epoch 光场释放。真正跨进程画面同时核对矿种／余量／遮挡。

## 5. 远征循环的规则基线

### 5.1 状态与成长

拟议阶段：`整备 → 降落 → 展开 → 探索／作业 → 撤收 → 起飞冻结 → 结算 → 整备`。展开期间即可探索；中继部署是探索中的任务，不暂停全世界。紧急起飞从探索或撤收进入同一个起飞冻结入口。

Demo 只实现两档成长：裸装出发（基础工具／船载供氧）与轻型前哨（一次成功收益可购买最小部署能力）。三个中段舱类型先按固定槽位配置：机器人舱控制机器人数量／展开能力、货舱控制设备与资源容量、船员舱控制矿工数量；飞船长度和着陆占地随中段数量确定。具体初始资金、槽位和价格集中在新规则文件调参，不复制进 Prefab。

裸装 6–10 分钟、前哨 10–15 分钟只作为设计稿给出的试玩观察目标；不设 20 分钟强制结束，也不据此承诺已经实现平衡。首个“升级后第二次落地”必须让用户看到可携带能力变化，不能只做整备界面静态解锁。

### 5.2 氧气、货物与中继

建议氧气采用个人储量：船上和工作的氧气站附近补充，离开后消耗，耗尽先警告再按规则伤害。首版半径供氧额外验证与人物之间的岩体遮挡，不实现气体流体或复杂管线。氧气站只有完成部署并满足功率／中继连接才工作；多个供氧区重叠不重复叠加充氧。暂停停止耗氧，UI 与网络继续。

货物链为 `矿床 → 玩家货袋／矿工携带 → 仓储平台／机器人携带 → 船仓`。每次转移在同一权威事务内核验来源、目的地容量和实际数量；来源只扣成功接收量。容器是所属对象 State 的字段，索引只引用对象，不另建第二份总库存。首版不新增满包自动丢地和复杂掉落物；满包明确反馈，不消耗矿床。

共享经济表示已归队可支配的资产；开采中的货物不能立刻用于轨道升级。个人货袋登船后转入船仓，受船仓容量限制；仓储内容只有实际运输到船上才算保全。UI 分别显示携带、前线、已入船，避免“账面已到账但撤离又扣一次”。

中继首版为氧气站的显式父连接，限船→前哨→一个矿房中继。检查距离、合法位置、功率预算和父节点状态；掉线后停止依赖服务并显示原因。设备预算采用“总供给／总占用”，按确定顺序启停，不画复杂电线网络。后续需要路径化信号或独立中继设备时再扩展。

### 5.3 部署、矿工和运输

设备状态至少区分船载、预留、搬运、展开、运行、回收、已入船、损毁／遗弃。设备 ID 全程不变；状态切换不能通过“删旧创建新”复制耐久或库存。机器人同一时间只执行一个任务，目标预留由服务端仲裁；其他任务明确排队或失败。

推荐 Demo 搬运机器人采用低空悬浮外观：使用有尺寸的二维空域路径，不能穿岩或瞬移。矿工与地面敌人使用站立点／坡面／可跳跃边的路径图，并复用权威运动扫掠；不要直接复用 X 轴 MoveTo。矿工首版仅派往已有双向通路的矿房，不要求其自动挖路或使用玩家喷气动作。找不到路线时报告“需要开路”，保持可召回状态。

地形破坏按受影响区域使导航缓存失效；当前路径受阻时有界重寻路，超时释放预留并报告阻塞。导航缓存可重建，不存成第二套碰撞事实。生成器必须保证 Demo 矿房有适合矿工往返的路线，玩家单独能飞过去不足以满足派工条件。

矿工任务为行进→预留矿床作业位→采集→容量触发交货→返回，途中召回优先结束未提交工作，再携带已有货物返船。多个矿工的工作位和矿床最后余量均做并发检查。机器人装运中的货物由机器人持有，设备内原有库存由设备持有，不能两边都记一份。

### 5.4 威胁与撤离

远征警戒由时间、有效设备噪音和实际开采量驱动，使用独立配置；暂停不累计，同一次重复请求不再次加噪音。先复用一类现有敌人外观与伤害能力，补洞穴移动、出生合法性和目标选择；炮塔只复用攻击基础，需新定义、二维射程／遮挡与部署后供能校验。威胁从浅层路线开始，避免没寻路就生成无法攻击或穿墙的怪潮。

正常撤收：停止新派工→按配置优先级回收设备并安排人员返船→显示未回收清单→玩家登船→房主起飞。氧气站等保障设备尽量后收；依赖设备关停后重算预算，避免召回途中无声断氧。设备装船必须提前保留舱位。

紧急起飞：房主查看明确损失清单后启动短倒计时；服务端到截止 tick 冻结舱内货物、船上人员和已回收设备，之后请求均不能改变结算。未回收设备与未归队 NPC／机器人按建议规则损失，矿物只保留船仓实际接收量。客户端操作权限、截止状态和提示一致。

建议 Demo 中未登船玩家本次携带物损失、进入观战，下一次出发恢复基础玩家角色，不让玩家永久失去加入资格；NPC 可永久损失并重新购买。全员失能走失败结算，已入船货物与损失规则用同一结算入口。是否保留全部已入船收益、NPC 损失成本及倒计时长度属于待试玩确认的产品参数。

## 6. 权威状态、联网与保存

所有新增状态仍归 Runtime/Objects 下的 YYGC Behaviour／State。Core 只放配置、冻结合同与纯计算；View 只读副本；Entry 接线。下表是职责设计，名称可在实现时按现有类型收敛，不要求提前建立空类型和目录。

| 唯一所有者 | 负责的状态 |
|---|---|
| 远征会话阶段能力 | 当前远征 ID、阶段、警戒、起飞截止、结算标记 |
| 飞船／设备对象 | 船仓、搭载清单、设备生命周期、耐久、所在位置、库存 |
| 角色对象 | HP、运动、氧气、货袋、作业／登船状态 |
| 搬运机器人对象 | 当前位置、携带货物／设备引用、任务阶段、预留目标 |
| 矿床对象 | 明确资源类型、锚点／范围、剩余量、枯竭 |
| 营地配置能力 | 本存档拥有的舱段、人员、设备、可支配资源与升级 |

Demo 建议采用房主存档拥有全队成长，来宾共享本次远征结果，不把来宾收益写入跨房间个人经济。断线角色与货袋仍留在权威世界，不能因当前“重连生成新人”而刷新货物或复制人物；需为远征明确持久玩家槽位与恢复凭据的关系。可复用原存活角色，租约代次必须更新；凭据过期后的遗留角色和货物按确定规则留置／召回，不静默清零或复制。

命令继续经过既有 YYGC Gateway／Sender／Processor，携带 epoch、PolicyRevision、序号及具体对象 ID；身份只取可信连接。新增部署、运输、派工、存入货物、召回、起飞、购买／配置请求均在服务端验证。起飞、整备配置、跨局购买和保存加载建议仅房主；SharedCamp 下队员可采矿、存货、提出部署和派工，HostOnly 维持既有观看限制。

地图流和对象投影在共同世界基线完成后才 Ready。新对象继续用会话完整冻结投影，不先增加逐设备 NetworkTransform 或另一套 RPC。任务位置／库存等持续事实进入副本；展开动画是事实的表现，不由动画事件决定设备正式启用。

新增保存包含地图最终格／Flags、矿床、氧气与货物容器、设备状态、任务阶段／引用、远征阶段、警戒、舱段配置和 RNG。保存可重建路径目标而不保存临时搜索队列；加载时验证目标与关系，重新寻路或明确回退到阻塞状态。

跨局资产与活动远征先放同一个版本化保存包原子写入，避免两个文件分别成功造成双结算。以持久远征 ID 和结算标记保证同一远征只结算一次；写盘失败不展示可花费的“结算成功”。崩溃后根据包内活动／已结算状态恢复，重复起飞、重发回执和读档均不得再次发奖。

协议与存档发生破坏性合同变化时分别升级，并维护握手摘要、生成注册、DTO、严格校验和冻结新样本。建议首个正式合同变更从协议 12／v8 起，后续按实际变化递增，不能将所有阶段永远固定为同一新版本。不要求迁移旧档，也不删除用户旧文件；导出地图格式、生成器版本和玩家存档版本分开维护。

## 7. 简易美术批次

本轮只评估，不生成素材。未来首批采用确定性原生像素绘制：成本小、轮廓和连接处可控，暂不需要 AI 生图。若之后需要风格探索或大型研究源，遵循项目指定的 `imagegen-codex-provider`，仍需派生为合格像素资产。

| 资产 | 建议原生画布 | 用途与精度要求 |
|---|---|---|
| 飞船艏／尾 | 各 48×48 px | 侧面剪影与登船口；连接边统一，脚底／接口锚点固定 |
| 中段舱体 | 每段 32×48 px，3 个变体 | 无缝拼接；3 段配置全长约 192 px，即 12 个地形格 |
| 搬运机器人 | 16×16 px，2–4 帧 | 背景可读、朝向与携物挂点明确；只作悬浮动作表现 |
| 氧气／仓储／炮塔 | 每种 32×32 px | 开关／工作／受损状态；设备占地与美术外边界分开 |
| 灯 | 16×32 px | 清楚显示开关和可回收状态，不烘焙大范围辉光 |
| 背景矿簇 | 16×16、32×16 px | 透明边缘、矿种轮廓与配色；矿簇跨格不改变碰撞 |
| 图标与玩家 HUD | 16×16 px 图标 | 沿用已有字体、按钮和布局体系 |

以上像素尺寸按 16 px／格对齐，是首轮样板，不承诺最终美术比例。船体外观可替换，但接口、占地和交互锚点保持稳定。优先复用已有村民、主角和敌人原图。只绘最少待机／工作／搬运／展开状态，不在风格未定时做完整动画库。

源图单份放 `Res/Art/Custom/ExpeditionPrototype`，对应定义、Prefab、动画与专用材质按 `Res/Objects/<对象>` 归组；来源清单记录原生尺寸、调色板、用途及派生关系。首次工具仅向指定空目录输出，之后不覆盖人工编辑；批量导入生成 .meta，保留 GUID。检查透明边缘、Point、无不必要压缩、Linear，以及原生和实际镜头两种尺度。设备／船舱替换外观不应改动业务定义身份。

## 8. 分阶段执行与依赖

顺序为 **E0 → E1 → E2 → E3 → E4 → E5 → E6**。每阶段形成可恢复的中文提交和独立证据，所有阶段目前均为待开发。工期为单人有效开发日的初估，含对应阶段验证、不含等待反馈或正式美术；遇到框架缺口重新评估，不当成完成承诺。

| 阶段 | 实施内容／主要落点 | 阶段出口 | 估算 |

## 9. 验证矩阵与停止条件

| 验证层 | 必须覆盖 |
|---|---|
| 纯计算／合同 | 新生成器确定性、碰撞与坡形、路径能力、库存转移守恒、任务状态合法迁移、警戒、结算幂等、保存关系拒绝非法数据 |
| Editor／资源 | 编译、ArchitectureGuard、绑定与定义／Addressables 引用；新 Prefab／场景编辑、保存、关闭重开，人工改动不被生成器覆盖 |
| 实际 Play | 三室样板与代表随机路线、正常镜头尺寸、矿光覆盖／露出、氧气反馈、部署期间可探索、无法到达反馈、真实撤收 |
| 独立 Mono 进程 | Host＋Client；最终 Host＋3 Client；正常与 200 ms RTT＋5% loss＋25 ms jitter；保留同产物身份 |
| 并发与安全 | 抢最后矿物／容量／作业位、重复部署／购买／起飞、非法目标／视线／距离、过期租约／epoch／PolicyRevision、Host 一次输入一次结算 |
| 生命周期与持久化 | 展开中／携货中／采集中／撤收中保存；晚加入、断线重连、暂停、切策略、加载；真实结束进程再读盘；写盘失败与结算崩溃注入 |
| 性能 | 固定说明机器、分辨率、对象数量、种子；前台观察帧时、分配、网络字节和积压；静止地图不重建、破坏／熄矿更新成本、路径失效峰值 |
| 旧内容回归 | 原 Pinewatch 布局、三夜和既有规则仍正确；共享主角／装备／存档入口按影响回归，不引用历史通过数字作本轮结论 |

实现前将每条门槛转成编号用例，记录预期结果、产物／seed 和证据位置。基础版本／绑定失败则停止后续运行；地图／对象 Ready 不一致停止联机验收；资源不守恒或结算可重复则停止后续成长实现；矿工不能真实往返则不进入自动化平衡。

性能预算应在 E1 代表机器基线后确定并冻结，不能把后台功能成功写成前台性能达标。IL2CPP 需要另行说明范围与产物并取得用户确认；本路线默认 Mono，双机器和新机器依赖恢复单独列待验，不计为本机四进程通过。

## 11. 后续产品决策

以下不阻塞当前文档和 E1 的结构设计；进入依赖它们的阶段前集中确认，或由用户接受本文件建议基线：

- 房主存档统一拥有远征成长，还是未来允许来宾带走个人资产；本方案先选前者。
- 未登船玩家失去本次货袋，NPC／机器人／设备可永久损失；损失成本和救援机制怎样影响早期体验。
- 三种中段采用固定槽位、基础能源上限，首个成功循环解锁轻型前哨；槽位／价格／产量依据试玩收敛。
- 中继先由氧气站承担、搬运机器人先兼任有限物流；自动钻机、独立物流无人机何时进入下一轮。

这些属于范围与玩法选择，不应变成逐个实现步骤都要请求“继续”的审批流程。已确定的实现与验证按功能批次连续完成。
