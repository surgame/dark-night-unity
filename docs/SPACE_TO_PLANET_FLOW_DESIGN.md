# 太空飞船到星球降落：流程与配置设计

2026-09-26，状态：**分析设计，尚未实施或验收**。本轮范围为太空船内开局、驾驶台选目的地、本地快速过场、星球空中到达、手动降落和步行下船；战略资源小地图、任意地貌着陆、完整星际航行及返航玩法重做不在首轮范围。

## 1. 设计结论

采用“一个持续存在的会话和飞船，按航程阶段替换外部环境”的方案。星球是内容预设；每次航程由服务端产生一个地图实例。玩家确认目的地与取得驾驶席必须在同一个权威事务中完成。过场只消费航程状态，在各端播放，不负责切图或决定到达。

配置通过 UI Toolkit 单窗口编辑，底层复用 YYGC `ObjectDefinition.SharedConfigs`、`IConfigData`、配置注入、对象生命周期及现有命令／状态同步。`PooledBehaviour` 承载导航、驾驶等能力；可恢复航程状态由 `SessionStateBehaviour<T>` 承载。不会建立另一套 WorldState、网络对象系统或运行时脚本解释器。

首轮落地建议：一个真实可玩的星球模板，表格支持多个预设，每个预设配置一个安全降落区及上方到达位置。多预设可共用模板、引用不同生成／环境配置；这不等同于多套新美术已经完成。

## 3. 玩家流程与权威状态机

```mermaid
flowchart LR
    A[太空船内自由走动] --> B[驾驶台浏览星球]
    B --> C[确认目的地并取得驾驶席]
    C --> D[准备地图与必要资源]
    D --> E[本地星点快速过场]
    E --> F[星球半空安全悬停与同步]
    F --> G[驾驶者手动下降]
    G --> H[着陆确认与开舱]
    H --> I[步行下船探索]
```

浏览面板只是本地 UI，不占驾驶席、不生成地图、不改变他人界面。确认成功后才切换驾驶者输入；多人同时确认只允许第一个合法请求成功，其余明确显示席位已占用。

| 航程阶段（拟议） | 玩家可做什么 | 进入下一阶段的条件 |
| --- | --- | --- |
| `Orbit` 太空待命 | 船内走动；靠近驾驶台浏览和确认目的地 | 服务端验证目的地、本人角色、距离、权限及空闲席位；同事务设置目的地与 `PilotId` |
| `Preparing` 准备航程 | 非驾驶员继续走动；驾驶员可取消 | 地图候选通过校验、必要定义／资源可用、乘员在舱内；开始过场 |
| `Transit` 航行过场 | 船内可走动；不接收推力／出舱；可显示短遮罩 | 服务端最短过场时间满足且候选可提交；原子安装目标环境并增加 epoch |
| `ArrivalSync` 到达同步 | 已展示星球的端看到安全悬停；慢端保留过场等待画面 | 到达基线和必要可见资源在参与者上就绪；处理有界超时，重新签发有效控制租约 |
| `Descent` 手动下降 | 驾驶员驾驶，乘员在船内走动；允许安全离座／接管 | 服务端验证着陆区域、支撑、净空、速度和坡道出口，确认着陆 |
| `Landed` 已着陆 | 舱门动画结束后步行下船，开始现有探索玩法 | 首轮流程终点；之后复用既有地面玩法，返航接入另列切片 |

`Preparing` 失败／取消回到 `Orbit`，清理候选并释放本次席位；失败原因可见。`Transit` 提交前的系统失败也回到 `Orbit`。**提交之后不因某个客户端未就绪而回滚其他人的世界**：保持安全悬停，重同步故障客户端。

航程阶段与物理状态分开：船仍拥有速度、飞行／停泊状态、舱门状态、驾驶者；航程只决定当前允许的操作。舱门打开必须同时满足 `Landed`、有效支撑、静止及出口净空，不能用一个“未飞行”布尔值代替。

首轮默认保持水平船体、松手制动悬停、低速着陆。高速碰地阻止穿透并返回无法着陆原因，不擅自加入坠毁伤害。到达位置必须留出制动距离；不能在地面或岩壁里生成飞船。

## 4. YYGC 能力、状态和生命周期

当前 YYGC 的 `PooledBehaviour` 与 `StatefulBehaviour<T>` 均派生自 `CoreBehaviour`，彼此不是继承关系；`IConfigData` 只提供配置接口，本身不会自动同步或保存运行状态。以下名称为拟议设计，不代表源码已存在。

| 所属对象／模块 | 能力 | 配置或唯一状态 |
| --- | --- | --- |
| 现有会话 ObjectDefinition | `ExpeditionFlowBehaviour : PooledBehaviour` | `[RequireConfig(typeof(ExpeditionFlowConfig))]` 注入星球目录、策略引用；协调命令和阶段推进 |
| 同一会话对象 | `ExpeditionJourneyBehaviour : SessionStateBehaviour<ExpeditionJourneyState>` | 航程 ID、阶段、阶段修订、目的地 ID、种子、内容摘要、到达地图身份、阶段时间；不保存第二份船员列表或地图 |
| 现有飞船 ObjectDefinition | 导航／飞行／舱内能力，按职责拆为 `PooledBehaviour` | `ShipNavigationConfig`、`ShipFlightConfig`、`ShipCabinConfig` 注入；继续写飞船的唯一 `BuildingState` |
| 现有角色对象 | 现有角色与控制能力 | 位置、生命、货袋、登船关系归 `ActorState`；不再另建 PassengerState 保存同一位置 |
| `SessionTerrain` | 候选生成适配、权威地图生命周期 | 活动地图唯一归 `TerrainMapAuthority`；生成候选尚未激活，不能接受玩法写入 |
| View 表现对象 | `TravelTransitionBehaviour : PooledBehaviour` 及窄表现策略 | 本地动画、摄像机、星点与遮罩配置；无世界写权 |
| 现有 SessionAuthority | 权限、连接、Ready、输入租约 | 连接代次、Ready 集合与任务取消句柄只属于会话运行上下文，不进入星球资产或存档 |

`ObjectSession` 继续只组合能力与索引。现有 `ExpeditionShip`、`ShipFlightMotion` 等普通协调类的职责按批次迁入所属对象能力，迁移时撤掉对应旧调度入口，避免同一飞船被推进两次。新航程阶段不复用已有 `CampSimulationState.ExpeditionPhase` 的整数含义；旧字段只负责地面探索／撤收／结算，地面阶段开始由一次着陆事务触发。

飞船位移与舱内成员位移沿用同事务提交。首轮保持当前权威世界坐标作为角色位置唯一来源，舱内局部坐标按船位反算；切换环境时统一平移，不同时保存两套可写位置。客户端显示乘员时，以同一展示帧计算相对船体位置，再相对同一插值船体绘制，避免分别插值导致滑动。

配置随本次会话冻结为只读输入。`OnSpawn`／`OnReset` 绑定本次会话、清空上次缓存；`OnDespawn` 撤销订阅、取消任务并释放资源租约。后台只用已复制的纯参数；回到主线程后同时校验会话存活、航程 ID 和阶段修订，过时结果丢弃。不得持有池中 State 跨 await，也不得让 `SessionScope` 跨 await／线程。

## 5. 配置模型：单面板，不是一个万能 Behaviour

建议在正式会话定义的 `SharedConfigs` 中保存一个 `ExpeditionFlowConfig`，其中含星球行目录和公共策略引用。星球行是可序列化配置，不必为每颗不可交互的星球创建运行实体。独立可复用的大型生成／环境配置可采用资产引用，面板直接编辑其真实来源。

| 配置组 | 主要字段 | 来源与约束 |
| --- | --- | --- |
| 星球表 | 稳定 `PlanetId`、启用、排序、名称、说明、图标、生成／环境／飞行预设引用 | `ExpeditionFlowConfig.Planets`；显示名可改，ID 不由名称／行号推导 |
| 地图生成 | 生成模式、SeedPolicy、模板／参数、资源分布、地表高度、天空净高、洞口连接、保护规则 | 复用／引用地形资产，捕获为 Core 纯参数；地图尺寸先限现有支持值，不承诺任意尺寸 |
| 降落区 | 稳定 ZoneId、着陆区尺寸、平整度、支撑与出口余量、到达偏移、允许飞行边界 | 固定地图引用作者区域；随机地图配置约束，由生成器产出实际坐标；不能把两者重复维护 |
| 飞行 | 最大水平／垂直速度、加速度、制动、着陆容差、安全接管策略 | 首批引用当前 balance 飞行规则并显示来源；需按星球差异时正式迁成具名规则表，每值只保留一个权威来源 |
| 舱内／驾驶台 | 驾驶台交互区域、船内出生位置、地板线、船壳、坡道、舱门耗时 | 从正式飞船配置／作者标记导出只读几何；替换 `ShipGeometry` 常量时以现有几何作首个保真预设 |
| 环境 | 太空背景、天空背景、洞穴三层背景、岩壁样式、灯光／音效引用 | 复用现有风格资产，不复制整套 StrataCave；明确天空与洞穴背景作用区域 |
| 过场 | 表现策略引用、最短展示时间、星点密度／速度／颜色、遮罩、等待表现 | 时长下限由服务端使用；动画参数在 View 使用；同一参数不分叉成服务端／客户端两份 |
| 会话策略 | 接管条件、准备／就绪超时、失败重试预算、内容预热预算 | 强类型、有限值、有上限；不能通过配置取消身份、epoch、驾驶独占等不变量 |

“配置驱动”覆盖本流程的内容、参数、资源和支持的策略组合；新增一种真正不同的生成算法或飞行动作仍需实现并注册能力。编辑器不会允许随意连线绕开状态机、执行任意 C#，或用字符串反射创建未知类型。

balance 已拥有的 HP、成本、速度等数据保持唯一来源；单面板可定位／编辑该来源，不把它复制进 `IConfigData`。配置引用参与依赖扫描与内容指纹；运行时不依赖 Editor 类型或 AssetDatabase。带 Unity／YYGC 引用的配置放 Runtime 或 View，Core 只接收纯冻结值。

预设复制获得新稳定 ID，排序不改 ID，删除前检查引用。共享资产编辑明确显示受影响的星球；要独立修改时显式创建变体。现有场景／Prefab 和 GUID 保留，不通过普通配置 Apply 覆盖人工内容。

## 6. UI Toolkit 单窗口

建议菜单 `Dark Nights / Expedition / 航程配置`。单窗口包括顶部会话定义选择与操作区、星球表格、选中行详情、预览和校验区。表格用 `MultiColumnListView`；详情用 `SerializedObject`／`SerializedProperty` 等标准编辑与 Undo 接入，具体序列化绑定在 Unity 6000.4.9f1 验证。

```text
会话定义 [CampSession]   [新增] [复制] [校验] [应用草稿] [取消]
┌──────────────────────────────────────────────────────────────┐
│ 启用 │ 星球 ID │ 名称 │ 地图预设 │ 环境 │ 降落区 │ 校验状态  │
│  ✓   │ ...     │ ...  │ ...      │ ...  │ ...    │ 待预览    │
├───────────────────────────┬──────────────────────────────────┤
│ 选中行的配置              │ 地图／飞船／过场预览             │
│ 基本信息                  │ 天空、出生点、下降通道、停泊区   │
│ 生成与资源                │ 船体包络、坡道出口、洞穴入口     │
│ 到达与降落                │                                  │
│ 船体与驾驶规则            │ [当前种子] [新种子] [批量校验]   │
│ 环境与过场                │ 分阶段耗时、失败原因、依赖来源   │
└───────────────────────────┴──────────────────────────────────┘
```

核心交互要求：

- 支持增删／复制／排序／过滤／多行启停；行选择与排序不触发地图生成。复杂列表在行详情编辑，避免所有字段挤进表格。
- 修改先进入草稿；Apply 前检查整个引用图，Apply 使用一组 Undo 并只写本批资产。Cancel、窗口重开、域重载的草稿处理需明确，不能静默丢失修改。外部资产变化时提示重新载入／解决冲突。
- 参数轻改合并预览刷新，旧任务取消或忽略；显式批量生成使用一批种子和一次报告。生成不能阻塞 Editor UI，也不对每次击键启动完整烘焙。
- 预览复用正式生成器、着陆校验和 `TerrainPreview`，在空白离屏宿主中显示，不启动网络、真实游戏会话或访问用户存档。星点过场可单独预览与跳到完成姿态。
- 第一批完成表格、来源清晰的详情、依赖校验、固定种子地图与下降包络预览；不顺便重写正在开发的地形工作台。

## 7. 地图生成与空中到达

**新增 `SurfaceLandingCave` 生成模式，而不是把当前洞穴泊位的 Y 值抬高。** 首轮保持现有坐标体系和受支持地图尺寸；分别标明格坐标、权威世界单位和素材像素。当前地图格边长为 16 权威单位、岩壁原生密度为 8px／格，不能混用。

准备流水线：

1. 服务端冻结选中星球及传递依赖，确定 `JourneyId + PlanetId + Seed + GeneratorVersion + ContentHash`；Seed 由策略与服务端决定，客户端只提交预设 ID。
2. 后台执行纯生成：洞穴原始蓝图 → 地表／天空开口 → 安全着陆区与下降通道 → 出舱到洞口的可行走路线 → 资源／保护区 → 真实坡形 → 初始背景参考。背景在全部地形约束完成后捕获，避免旧轮廓残留。
3. 输出不可变候选：地图、矿床、`LandingZoneDescriptor`、空中到达姿态、飞行边界、背景参考与摘要。实际坐标属于此地图实例，后续网络与存档都使用该结果。
4. 校验船壳扫掠净空、制动余量、支撑面、坡道落脚点、角色实际坡形与通行能力；失败时有限次数换派生种子。全部失败就返回明确失败，不默默改数值／换星球。
5. 主线程准备 AnyRuleD 权威候选与目标对象资源，全部成功后才允许环境提交。任务期间旧太空环境仍可用，未提交候选不加入活动索引、不接受命令。

空间结构为“开放天空 → 地表安全平台 → 可步行入口 → 既有洞穴”。天空区域显示星球天空，地下使用 StrataCave；背景分区和摄像机裁切也属于预设合同，不能让洞穴三层后壁继续盖住天空。

首轮每个实例一个安全区：玩家有真实左右／上下控制，但着陆必须在该区域内且满足完整接触检查。接近时提示区域和速度，按着陆交互由服务端重新验证；自动吸附仅在配置的小容差内发生。未来多资源点地图可消费 `LandingZoneDescriptor` 集合，首轮不生成战略 UI 或资源情报协议。

着陆区支撑格与出舱落脚区域首轮采用受保护规则，避免一落地就能挖掉承重地形而产生悬空船。外围地形仍按正常规则可破坏；以后若支持挖坏平台，需增加失去支撑后的完整行为。

“快速”的实现是按需准备与复用：目录／小资源开房后可预热；确认目的地后只生成一份候选；候选缓存有数量／内存上限；切换后优先准备到达镜头的必要可见页，其他页按现有受测能力展开。首轮可靠完整地图基线继续传输，不因追求短动画跳过地形或背景 Ready。

分别记录生成、资源加载、基线传输、首个完整画面和可驾驶耗时。短过场建议初始调参 0.6–1.2 秒，但只是表现目标，不是弱网下保证到达的时限；加载较慢则星点进入稳定等待画面。当前未完成的可见页／局部刷新问题属于实施前置风险，不能直接宣称已有瞬时生成能力。

## 8. 联机事务、切换和就绪

### 8.1 命令与驾驶权

复用 YYGC `Gateway → Sender → Processor → SessionAuthority`。新命令使用强类型载荷和生成注册，不继续把任意字符串操作扩成通用脚本入口。

`SelectDestination` 显式携带 ShipEntityId、ActorEntityId、PlanetId、当前 JourneyRevision，以及现有协议／epoch／策略版本／序号／角色租约。身份始终来自可信连接。服务端验证：本人存活且有控制权、在船内驾驶台范围、当前阶段允许、星球启用且内容有效、席位空闲、船员及舱门满足条件，然后在一次短事务中锁定目的地、取得驾驶席、更新租约并进入 Preparing。

打开菜单不抢占。旧客户端菜单确认时重新检查真实距离和占用。并发请求按服务器接受顺序裁决；同序号重发返回既有结果，不能重复启动生成。改变参数的同序号请求拒绝。Host 使用相同入口，不本地预执行。

继续使用角色输入的序号、超时归零与控制租约；只有 `Descent` 且属于当前 PilotId 的合法输入能驱动船。`Preparing/Transit/ArrivalSync` 不接受推力。目的地确认与驾驶在 SharedCamp 下允许有权限的来宾操作，明确替换旧 `depart` 的仅房主语义；HostOnly 下遵循现有只允许房主修改的合同。

### 8.2 环境切换事务

首轮保留 Bootstrap 和正式会话宿主，替换外部环境、地图及地面对象内容。太空环境没有活动地面地图；增加明确的 `EnvironmentKind`，让 Ready 和保存合同支持“Space：船／船员／太空表现就绪”和“Planet：再加地图／背景就绪”。不能通过伪造 `MapReady=true` 掩盖缺失的星球地图。

服务端仅在候选完全准备后提交：暂时关闭交互输入 → 保存当前乘员相对船体的位置 → 安装目标地图及描述 → 将同一飞船和已登船成员平移至到达位置 → 更新地面对象索引和航程 → 增加世界 epoch → 清理旧输入与投影缓存 → 发布新基线。保留经济、货物、升级、飞船和角色 EntityId；不因换星球再次创建默认主角。

实体、地图、航程更新必须在通知外、无 await 的提交段完成，提交前保留旧环境，资源退休在成功后进行。现有地图 `Replace` 会直接释放旧地图，不能简单把几个现有方法串起来就声称支持回滚；实施须把准备、交换和退休分开，故障注入验证原子边界。对象变更复用 `ObjectMutationBatch`；环境资源交换使用专门的有限提交步骤，不建立通用事务框架。

首轮选择“服务端准备候选，提交后沿现有链同步完整新基线”：不要求客户端同时维护两张活动地图。各客户端收到目标 epoch 时，用同一个切换票据关联对象、地图、背景和表现；在全部匹配前保持遮罩或安全等待画面，不把新飞船画到旧地形上。需要进一步缩短可见等待时，再用测量证明是否有必要增加候选基线预取。

同一持续连接在航程切换时保留服务器确认的船员关联与驾驶意图，但旧输入租约作废；重新 Ready 后校验本人、席位和阶段，再签发新租约。这与从磁盘读档释放所有驾驶占用不同，不能直接调用 `CompleteLoad` 期待自动保留驾驶者。

### 8.3 Ready 与基线屏障

权威航程投影至少带 `JourneyId / PhaseRevision / PlanetId / EnvironmentKind / ContentHash / MapWorldId / MapEpoch / RequiredMapRevision`。区分世界 epoch、地图 epoch、地图权威修订、每连接流提交号，不能互相代用。

星球到达的 Ready 必须关联相同票据，并确认：对象完整投影已应用、目标地图完整基线及必要修订已应用、初始背景参考匹配、船与船员定义已装配、到达镜头必要地形和背景页已可用。各端 ACK 由既有客户端就绪链发出；服务端核对其连接代次、已下发票据和 revision 范围，不能仅凭一个无上下文的布尔值放行。

进入切换时冻结一组需要等待的活动连接，后加入者不无限延长该屏障。正常情况等该组就绪后同时解锁驾驶。慢端在配置超时后退出本次阻塞集合、保持 NotReady，按有限重同步预算重试；未就绪端不能提交玩法命令。服务器保持其原角色的安全舱内状态，不生成副本；必要时沿现有断线政策处理。

驾驶者超时需撤销驾驶占用，留在安全悬停并允许已 Ready 的合法成员到驾驶台接管；不能在其不可操作时让飞船继续下降。Host 本地表现失败不能把自己当普通慢端无限忽略，应停止本次放行并显示明确恢复／退出入口。

Ready 前不推进危险的飞行和地面风险／氧气结算；心跳、同步、超时与 UI 保持运作。Ready 后地面计时从真实着陆阶段启动。暂停不会调用 `Time.timeScale = 0`：玩法与航程阶段时间暂停，传输和超时继续，后台准备可完成但不强制推进航程；本地过场可保持等待姿态。

### 8.4 断线、接管和异常

| 情形 | 处理 |
| --- | --- |
| Preparing 驾驶者断线／死亡／失去权限 | 取消本次候选，释放席位，回 Orbit；迟到生成结果不得安装 |
| Transit 提交前驾驶者失效 | 首轮默认取消返回 Orbit，保证不会无驾驶者开始新航程 |
| 已提交或 Descent 驾驶者失效／离座 | 清空推力、撤销租约、制动并保持安全悬停；其他有权限的在船成员可接管 |
| 转为 HostOnly | 来宾旧请求拒绝，驾驶权按新策略撤销；房主可在驾驶台接管 |
| 晚加入 | 从当前完整快照进入；Orbit 出生在舱内，Planet 按当前飞船位置建立；不从头播放历史过场、不重复生成地图 |
| 重连 | 验证恢复凭据并更新连接代次，按已有角色恢复规则核对归属；旧连接输入失效，不自动夺回被别人占据的驾驶席 |
| 重复／乱序阶段或地图消息 | 校验 JourneyId、epoch、票据及修订，忽略过时消息；晚到的背景／可见页不能覆盖新环境 |
| 生成或依赖失败 | 提交前保留太空世界并给出原因；有限重试不改变已确认目的地 |
| 某客户端提交后失败 | 飞船按就绪策略安全等待，单端重同步／断开；不回滚其他端已安装的世界 |
| 房主退出 | 沿当前合同结束会话；不新增房主迁移 |

空中允许安全离座是对当前“只能停泊离座”的明确改变：离座事务清空输入并使船制动悬停，角色恢复舱内行走。全员可以移动的要求由此成立；始终只有一个人可以产生驾驶输入。

## 9. 可插拔本地过场

定义一个小的表现合同，例如 `ITravelTransitionPresentation`，支持开始、按当前阶段定位、进入等待姿态、完成及取消。由正式表现 ObjectDefinition 组合具体 `PooledBehaviour + IConfigData`，使用 DefinitionReference／PrefabRef 和现有 Addressables 生命周期；不建立新的全局资源加载器。

首个策略 `StarShift` 仅移动／重排本地星点并短暂遮罩，后续可以换成淡入淡出或航行插画。默认星点使用确定性简单绘制，无需 AI 生图；本轮不制作新星球美术。新增视觉素材时再按原生尺寸、用途与透明／共边要求单独评估。

过场输入只包含稳定航程标识、配置引用及可用于定位的阶段时间。星点位置不逐帧联网，也不使用游戏玩法 RNG。不同客户端可以有不同的星点动画细节；到达地图和飞船姿态必须相同。

动画完成只通知本地表现层，不发送“替全队切到星球”的命令。网络阶段已到达时可直接定位完成；动画未完成但数据已就绪时遵循最短展示时间；数据未就绪时进入等待。策略缺失可回退简单遮罩并报诊断，不能因此跳过 Ready；即使策略完全禁用，玩法流程仍可正确完成。

## 10. 存档与版本边界

正式实现将改变命令、投影与存档合同，需要升级当前协议 14／存档 v10；具体下一版本在实现时与同期改动协调，不在设计文档里抢占编号。继续严格拒绝不兼容旧格式，不自动删除或迁移用户旧档。

持久数据保存星球／配置身份与内容版本、种子与生成版本、当前航程稳定状态、地图最终格子与背景参考、实际到达／降落描述、船体和乘员状态。**已访问地图的恢复必须读取保存的最终格子，不能只凭种子重生成而丢掉开采结果。** 角色／驾驶槽位、连接代次和待执行输入仍是临时授权，不作为永久凭据保存。

首轮明确保存语义：Orbit、Descent、Landed 可正常捕获冻结档；Preparing、Transit、ArrivalSync 期间返回可见的“环境切换中，稍后保存”，不静默保存半成品。切换前可保留最近的有效存档，自动保存请求延后到下一个稳定阶段；取消排队或磁盘失败需要反馈。这样首轮不必序列化 Task、候选资源或一半 Ready 集合。

空中读档恢复同一地图、船体和舱内位置，清零速度与输入并进入安全悬停，驾驶席释放，待玩家重新接管；此行为延续现有空中恢复原则。存档配置缺失／不兼容应在候选准备前明确失败并保留当前世界，不悄悄改用另一颗星球。

既有远征结算不能用 `ResetDock()` 偷渡成完整星际返航。首轮保证下船后的采矿链不回归；现有返航入口需按阶段显示，未接入新航程的入口不能继续宣称会返回太空。后续另做“撤收 → 起飞 → 返回 Orbit”的完整切片。

## 11. 实施切片与验收门槛

| 切片 | 交付内容 | 本批必要验证 |
| --- | --- | --- |
| A 配置与状态合同 | 强类型配置、航程 State、操作权限表、冻结参数、配置指纹；定义装配 | 注入、缺配置失败、池复用清理、状态组合／存档校验、程序集及生成注册 |
| B 固定完整流程 | 一套固定地表降落样板、太空舱内出生、确认即取得驾驶席、可替换过场、真实下降与下船；从开始就接可信命令链 | 两个独立进程 Host＋Client 跑通全流程；双方选目的地竞争，远端驾驶与乘员步行，场景／Prefab 保存重开 |
| C 随机地图与在线切换 | 服务端随机候选、有限重试、原子环境提交、全链 Ready、失败保留 | 多种子船体可下降／出舱可达；故障注入、对象与地图混合次序、旧任务取消、切换不重复出生 |
| D 单面板制作 | UI Toolkit 表格、草稿与 Undo、多预设引用、正式路径预览、校验报告 | 编辑保存重开、域重载、排序与复制 ID、共享资源变体、外部修改冲突、批量预览、Player 无 Editor 依赖 |
| E 联机与恢复收口 | 全阶段迟到／重连、权限变更、掉线接管、稳定状态写盘恢复 | 同一 Mono 产物正常／真实 UDP 弱网 Host＋3 Client；每阶段晚加入与重连、旧 epoch 输入、暂停、磁盘失败、返还清理 |

A–B 优先形成最短可玩纵切，D 与配置模型同步完善，不先搭建一套没有游戏消费者的巨大配置平台。联机设计和基础多进程验证从 B 开始，不推迟到功能完成后补。

重点验收断言：

- 4 人开局都在同一艘船内，可以相互看到走动；太空无可穿出的坡道；重复 Ready 不增员。
- 两人同一时刻确认不同星球，恰好一个成功，目的地与驾驶者一致；请求重发只生成一个候选。
- 本地取消菜单、动画跳过或帧率差异不能改变全队航程；过场被替换／禁用时仍能跑通。
- 换图时船员相对位置、货袋、升级和 EntityId 保持；旧输入／旧地图／旧背景不会污染新环境。
- 任一端在地图／背景／必要可见页未齐时无法驱动飞船或下船；慢端和新增连接不会永久卡死已就绪队伍。
- 客户端驾驶、非驾驶员移动、飞船碰撞、低速着陆、开舱、从坡道走到洞口都在独立进程实测。
- 空中掉线／离座／切 HostOnly 后推力归零，其他合法成员可接管；重连不会抢回现有席位。
- 生成失败、资源失败、提交前取消、提交边界异常、连接中断及保存失败均有确定恢复结果，无半张地图、重复对象或货物丢失。
- 稳定阶段实际写盘重启恢复正确，切换中保存明确返回暂不可用；当前挖掘结果不得被种子重生成覆盖。

正常网络与至少 `200 ms RTT + 5% loss + 25 ms jitter` 的真实弱网按同一配置跑全流程，另加入短时断网与恢复。记录构建、依赖、种子、阶段修订、客户端 Ready 证据和最终状态摘要。固定场景＋随机种子测试不能替代实际画面和船员操作检查。

实施前合并同批验证项、检查磁盘与 Editor 占用，复用单一 Local Unity 验收通道；Mono 每配置构建一次供矩阵复用。IL2CPP 需另获明确确认，双机器及前台性能继续单列，不能以本机多进程通过替代。

## 12. 推荐首轮默认值与待验证问题

本设计建议以下可调整的产品默认值：确认星球后自动取得驾驶席；单安全降落区；水平船体与悬停；起飞前不要求全员点击投票；安全落地后自动开舱；乘员在非原子切换瞬间可在舱内行走；不做坠毁伤害或太空出舱。这些是设计建议，本轮不进入实现。

落地前需实证解决的主要问题有四项：当前地形可见页 Ready 的已知失败、太空无地图时现有启动／投影／保存的空值假设、环境交换与旧资源退休的事务边界、UI Toolkit 对 `SharedConfigs` 多态列表的 Undo／重载绑定。尚无证据要求修改 YYGC；先用游戏现有能力组合验证，发现框架缺口才在隔离 checkout 修正并更新改动账本。
