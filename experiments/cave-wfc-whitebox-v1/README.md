# 共点 WFC 洞穴白模

这是独立算法与白模实验，供评审随机大地图、连接合同及后续美术制作。源码在本目录，聊天内演示由同一源码打包；不接入正式 Unity、v17 地图生成器、角色、采挖、联机或存档。

## 算法与数据

1. `plan.js` 使用可恢复种子的确定性随机流，规划一条地下洞室主干及支路／局部回环，生成有符号空间引导场。引导的是洞形，不是角色寻路结果。
2. `catalog.js` 有 16 种实心／空气拓扑。四角各取 `-3/-1/+1/+3`，共 256 种离散配置；负值为空气，正值为岩体。角点顺序为左上、右上、右下、左下，mask 位权依次为 1、2、4、8。
3. 相邻边共享两个角点的**完整值**，不只共享实空。边按 N/E/S/W 编码，N/S 从左至右、E/W 从上至下，编码为 `第一个角点索引 × 4 + 第二个角点索引`。匹配双方使用相同读取方向，不额外反转。
4. `solver.js` 先建立候选域，再按加权 Shannon 熵选择格子，观察一个候选并向四邻传播删除不兼容项。权重贴近宏观场；并非先生成一张图再假装进行 WFC。矛盾有界重试四次，失败保留旧结果并报告，不补一张未经求解的替代图。
5. 格边上的零交叉可位于 1/4、1/2、3/4。相邻格从同一端点值插值得到同一交点，支持跨格的离散缓坡，不局限于固定中点的 45° 轮廓。交错角点使用同一 bilinear saddle 决策；当前只保证位置／边界一致，不保证所有相邻坡段切线 C1 连续。
6. 求解结果按全局格边身份串成闭合轮廓。白模岩体和顶面都读取这份轮廓，不用另一套随机轮廓。固定地下实心边框保证本样板轮廓闭合；未制作地表洞口。

WFC 在此承担局部配置与共边约束；洞室／廊道规划承担宏观结构。库内仍有完整的 16 个拓扑，尚未接入外部手绘模块库、专用切线 socket、流式分块或无限世界。当前 96×40 大格；渲染缩放不改变地形结果。

## 白模与操作

`renderer.js` 将正面岩体、亮顶面、暗底面分开着色，顶面统一向后偏移 `(0.34, -0.30)` 大格，形成有厚度的斜投影视觉。它是二维轮廓的有限深度展开，不是透视相机或可行走三维模型。背后灰色棱柱只表示背景尺度，不参与地形。

- “生成”复现输入种子；“换个种子”选择下一个确定性种子。
- “透视白模”查看空间厚度；“共点检查”查看原始格网和共享角点，点格查看四角与边码；“16基础型”查看拓扑图册。
- “全图／近看”、拖动、滚轮控制镜头。“顶面厚度”可对比展开前后的轮廓。
- 共边冲突统计只检查几何数据一致性，不表示角色能够通过、跳跃或返程。

## 重建

在仓库根目录运行；输出应指向当前聊天的独立预览目录，不放入 Game。

```powershell
python experiments/cave-wfc-whitebox-v1/build_preview.py --output "<预览目录>/cave-wfc-whitebox.html"
node experiments/cave-wfc-whitebox-v1/verify.cjs "<预览目录>"
```

`build_preview.py` 输出离线片段和逐源 SHA-256 清单，无第三方运行依赖。用 visualize 技能自带 `scripts/render.py` 包装为预览 HTML 后，`inspect.cjs "<预览目录>"` 核对同一画布及交互；该检查器使用本机 Codex 随附 Playwright／Edge。运行回执和截图按时间戳保留在预览目录。

## 交给后续美术对话

先阅读本目录 `art-contract.json`。512×512 为建议白模模板画布，尚未锁定实际美术分辨率、像素密度或世界尺寸。本片没有生成、裁切或修改任何复杂美术。

不能承诺只画 16 张固定图片便覆盖 256 个边界配置：应先选择“参数化边缘＋岩体填充”或把所需交点／坡向扩为明确的预绘变体。边界的拓扑、交点、厚度和接缝带应锁定后制作，AI 提示词本身不作为共边保证。

正式接入仍需确定坡形／碰撞合同、材料与美术变体、修改后的边缘、装配及保存／同步影响。白模、脚本与浏览器核对均不计作 Unity 编译、Play、人物通行、四人性能或美术认可。
