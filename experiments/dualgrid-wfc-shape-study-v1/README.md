# DualGrid、扩展WFC与组合方案的洞形白模

2026-10-31，CL-01／08独立研究。用户认可自然洞形风格，要求比较16tile、丰富WFC以及二者组合；本目录提供三套同尺度白模、形状与内容位，不接入正式游戏。

## 分工判断

DualGrid在这里定义局部四角如何连接，WFC负责从候选域中选择满足邻接约束的配置。两者可以出现在同一条制作流程中，不能把自然度或美术成本直接归因于算法名称。16是二值四角的拓扑数，包括全空和全实心；坡形、材质、内部纹理变体、矿层与生态不因此只需要16张最终图片。

| 方案 | 本白模实际实现 | 制作含义 |
| --- | --- | --- |
| 16型DualGrid | 同一洞形引导场按正负采样，四角只取−1／+1，固定中点边口。没有运行WFC | 小库容易核对、适合局部采掘。图中的直线模板是保守基线，不代表16种拓扑只能画成方块 |
| 扩展小块WFC | 使用旧独立实验的真实候选域、加权熵、四邻传播和四次有界重试。四角取−3／−1／+1／+3，共256数值配置，边口可在1/4、1/2、3/4 | A/B严格锁定相同实空角点，轮廓差异只来自幅值和边口。256不是256张必须手画的图，也不是免费获得的形状；非中点接口须明确美术／形状合同 |
| WFC＋DualGrid／现有坡形 | 新的一维宏观WFC选择6段连续轮廓：3种端口偏移×3种端口偏移×缓坡／斜肩／浅凹，共27数据候选；相邻段共享端口，首尾锁定。冻结占据后，使用16基础拓扑和当前游戏12种坡形公式 | WFC用于制作初始候选，小格状态与坡形负责表现。开挖不重排宏观段。第三套有独立初始选形，故不冒充与A/B完全同一占据 |

结合当前工程的格级采掘和已有坡形，优先建议第三种分层方向；正式首片可以先做一类岩体及少量内部变体，把坡面、水岸、矿层和生态独立制作。WFC的局部兼容不能替代宏观布局、玩点因果、动态阶段或美术接受；本例也未替换当前正式地图生成器。

## 白模内容与操作

三套均有三格高原主角比例参照。斜坡凹岸包含落脚面、独立瀑布／池面位置、可变岩肩、矿层位、侧窝及草菇白模；另外提供低顶斜肩和洞厅／侧窝。标记说明作者意图，不代表正式机关、生态动画、矿量或通行成立。

- 顶部切换三个方案，默认组合方案；切换洞形或种子获得另一组同源输入。
- “轮廓近看”查看小格细节；“格网与角点”显示底层样本，组合方案另画8格宽宏观段边界。
- “叠加参考轮廓”显示16型基线；A/B可直接比较，第三套叠加同时包含初始选形与坡形投影差异。
- “查看格型”显示16拓扑、同一拓扑的16种幅值配置，或16拓扑＋12既有坡形。位序对外为NW／NE／SW／SE，旧WFC库内部的顺时针位序在显示时明确转换。
- “局部挖一格”改变一个逻辑样本并展示受影响结果。A/B四个渲染格结果变化；坡形可能扩大有限邻域。白模为便于审阅仍全量重建结果，这不是局部更新性能测量。

宏观段是沿同一引导场进行连续变形的数据候选，不是27张独立大块手绘地图，也不是完整的随机关卡玩点库。局部白模以实心边框保持轮廓封闭，未制作正式地表洞口。

## 三方案过程白模

`dualgrid-wfc-steps.html`与上一版成图比较并存。每套六步，用相同的步骤下拉框或前后按钮查看；切换方案保留步骤位置。只显示当前步骤，不把最终轮廓当成过程演示。

| 方案 | 六步 |
| --- | --- |
| 16型 | 空实数据 → 16型库 → 四角查表 → 共享中点拼接 → 成图 → 移除一逻辑位置、四个渲染格变化 |
| 扩展WFC | 同一空实与幅值约束 → 实际候选域 → 最低加权熵格按权重选择 → 四邻约束传播 → 全部收敛后冻结 → 查角点配置更新四格 |
| 组合 | 六个8格宽宏观槽 → 27相对轮廓配置和端口过滤 → 大段真实选择／传播 → 冻结占据与现有坡形投影 → 成图 → 仅小格材料／坡形结果变化 |

`steps-trace.js`在新说明中复现原有两种求解过程，记录一次真实的边界观察及其传播前后候选。微观WFC记录选择时的熵值、原候选、选中ID、传播方向及删减；宏观记录每个槽的候选和选中配置。完成后逐格／逐段与未修改的原求解器结果比较，发生差异直接拒绝。步骤不伪造随机序列、传播顺序或候选数；中间快照与开挖前后对象分离。第一套直接查表，没有暗中执行WFC。

本例固定种子271。扩展WFC展示第三次观察，之前两次选择真实执行；候选图块显示该时刻的四角幅值，编号只是配置ID。组合的27项是连续引导场的相对形变数据，并非27个手绘房间。最后一步显示输出差异数；白模为便于核对仍全量重算，不声明测得运行时增量更新性能。扩展WFC能直接更新四格依赖于本例的角点共边合同，不能外推成任意邻接图块均可无传播修补。

## 同一视图的连续过程

用户指出前版虽有步骤，但每步换成图集或局部图解，无法连续理解整体。因此另存`dualgrid-wfc-continuous.html`，保留两份前版。新版本始终使用48×28世界范围及同一相机矩阵；同尺寸下，三方案和所有步骤的画布位置、缩放、人物比例参照、落脚面／浅池／侧窝地标均固定。步骤不切入图集、局部放大、另一个示意坐标系。

- 16型在原地图显示角点、已有格型轮廓、本格查表结果，再沿原位置向全图铺设；已落下的本格在后续铺设中保留。
- 小块WFC将候选轮廓叠在各自格内，本格观察及实际邻格删减都发生在原地；之后按真实顺序继续回放其余观察，直到冻结完整结果。
- 组合先在原图划定六段，将各段候选上下沿叠在原位置，依次真实选择和传播，再沿同一世界坐标投影成小格／现有坡形。
- 开挖在同一张完整地图上展示输出变化、原边界和有限粒子示意，不切局部特写。水与植被仍仅为内容位置，人物是固定比例参照，不是物理角色或通行结果。

前后按钮及步骤选择均沿同一过程位置过渡；“播放流程”按序走至开挖后停止，可暂停或重播，不自动循环。减弱动态偏好关闭过渡动画，仍可按序查看。候选平均轮廓的插值仅用于解释收缩过程，不是已通过共边验证的中间候选；端点消费实际快照，最终结果仍与原求解器一致。

`steps-trace.js`新增可选完整观察／传播增量记录，不改变随机调用与选择次序；`flow-model.js`重放并核对最终逐格身份，将候选摘要存为有界数值数组。宏观候选上下沿按与原形变相同的偏移式求解，最终使用原组合地图，不把插值画面写回数据。`flow-renderer.js`统一负责固定变换下的图层、轮廓和变化；`flow-app.js`管理六步、单次播放、取消、减弱动态和状态恢复。
