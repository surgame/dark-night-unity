# Dark Nights · 远征内容实验室

独立、可操控的 H5 内容候选集，共48个入口。覆盖2026-10-23头脑风暴的全部37项武器、道具与场景实验；2026-10-24按用户要求换用项目角色／场景素材，并增加第38项「项目实景 · 素材对照」；2026-10-25增加六处局部洞穴、三件装备和一条组合路线，方案见[局部洞穴特性](FEATURE_PLAN.md)。**人工确认后再单独安排正式接入；本目录没有Unity导入入口。**

## 开始试玩

双击 [dist/index.html](dist/index.html)，无需安装、联网、Unity或服务器。代码、样式、原126份来源素材／派生后壁和新增7份原生后壁全部内嵌在这一份文件里。也可打开 [dev.html](dev.html) 直接使用分文件源码。

默认进入「本轮新特性」十项；也可点「项目实景 ↗」亲自走过坡地松林、低谷、洞口和地下，观察角色与素材比例，或筛选「全部」回到原38项。点击画面或「开始」才推进模拟，读说明时不会自动受袭。每项均有独立目标、配装、操作提示与重置；完成目标后仍能继续试。机制洞室从靠近试验区的位置入场；标注默认关闭，可按需打开。

建议先玩S17地热、S18薄桥、S20根幕，再玩M06组合试采。新增场景的目标需要实际带回入口按E交付；设备练习仅检查对应装备的独立操作。四格为实验配装，手电用F切换；这不决定正式手电槽位合同。

本机开发预览使用 `http://127.0.0.1:8766/dist/index.html`。这个地址只在本地预览服务运行时有效，交付的离线文件不依赖它。若需自行启动，在仓库根执行：

```powershell
python -m http.server 8766 --bind 127.0.0.1 --directory experiments/expedition-playground
```

## 操作

| 输入 | 行为 |
| --- | --- |
| A／D、Shift、Space | 移动、冲刺、跳跃 |
| W／S | 攀爬梯具；松开可停在梯上，Space跳离 |
| 鼠标、按住左键 | 瞄准、持续使用当前装备；采掘有实际距离与遮挡 |
| 1～4／点击装备 | 换装备；槽位为本场景的试验配装，物资不限量 |
| E | 检查路标／茧／遗留物、开箱、交付、引爆装药、挂接／放下重矿、回收设备；压力阀每次按下释放一档 |
| 按住E | 在已连接绞盘旁提升矿箱，或在倒地队友旁慢速救援 |
| F、R、Esc | 切手电、重置本场景、暂停／继续 |
| 双角色、Tab | 开关第二角色、交换当前主控；救援场景预置倒地队友 |
| 方向键、I／J／K／L、右Shift、Enter | 另一角色移动／跳跃／爬梯、调整准星、使用装备、交互 |
| 全屏 | 放大当前画面；由浏览器提供，Esc退出 |

窄屏提供移动、爬梯、跳跃、使用和交互按钮。触碰画面调整准星。主要评审入口仍是桌面鼠标键盘；未签署移动设备实机体验。

## 新洞穴操作与边界

| 洞穴 | 观察与操作 | 预期后果 |
| --- | --- | --- |
| 地热 | 观察灰烟、橙色预警与喷流，冷凝枪瞄准地面裂口；中间岩脊用Space跳过 | 冷凝6秒后复燃；喷流推退并扣8HP，训练环境至少保留1HP |
| 薄桥 | 从桥缘瞄准脚前桥片打岩钉；金属横箍表示已加固 | 承重裂纹累计，出现碎屑后约1.55秒坍塌；已断片不能修复。S18可在坑侧携带搭梯，M06须预先加固 |
| 磁矿 | 比较空袋与背矿通过，使用消磁器瞄准侧壁核心 | 磁力周期聚能／吸引／间歇；货物越多牵引越强，持续反向行走能抵抗 |
| 根幕 | 瞄准上方铜绿根结；手电、照明弹或近处荧光棒均须有射程和可见枪线 | 受光退缩，暗处复生；关门等待角色让开，碰撞随同一状态开合。根幕不能用矿镐／爆破替代照明 |
| 压力囊 | 左侧阀杆附近E三次，再镐采；重置后直接攻击囊体对比 | 完整取6份，破裂取3份碎料；破裂先预警再喷流，等退去后采料交货 |
| 眠巢 | 正常步行，对比Shift冲刺或开枪，观察共振条 | 共振达到45时只唤醒两只；安静后条衰减，可诱开、捕网或清理，不无限出虫 |

新增装备24×24、握点[8,12]；热口32×20、磁核32×32、根结28×22、阀24×32、琥珀36×34，均为原生整数像素与既有手持色板，岩缝补色取已有洞穴深色。动态桥面和根幕独立绘制，避免开合导致整张岩壁每帧重烘焙。新增七类局部空间的后壁仍调用只读Core程序集的原生背景算法，单独保存于`assets/feature-backdrops/`，旧30类及原图保持。

新背景可用`node experiments/expedition-playground/build-feature-assets.mjs <新的证据绝对目录>`重建；记录程序集、输入及PNG哈希，不启动Unity。`build.mjs`对全部浏览器JS做语法编译，并从注册目录计算48入口。导出的试玩快照增加桥片、热口、磁核、根幕、压力与噪声状态；旧评审保留，新构建不沿用旧版完成计数。原`check-playthroughs.mjs`仍只覆盖原38项，明确排除新增10项；未运行不能据历史报告宣称本轮通过。

武器之间有真实机制区别：霰弹散布与击退、后方岩壁条件钉壁、近身打断、会挣脱的捕网、会失效的封巢、固定远处岩面的照明弹、按布置方向破岩、改变生物目标的诱饵。射击不被背景矿物误挡；前景实体岩层仍挡枪线。

采掘会修改实际前景碰撞；拆岩与采矿分开，探测不授予隔墙采矿。塌方留下可清障瓦砾；支撑只能推迟坠落。完整重矿支持两人靠近挂接后拖运，也可单人拆碎取得较低收益。绞盘松手保持高度；救援包与普通协助有不同时长。

## 场景、角色与来源

引用会话：`01a168f0-29aa-74e3-a28b-aa0143a1fa59`，标题「现在我的项目缺少天空背景(多层带透视的)以及地面上的一些植被/树木/物品/环境素材等，帮我评估一下怎么做最好，关键是天…」。

- 原生矿工身体／衣服、12帧走路、天空、分层森林、树石、草皮、火把和基础手持图来自当前工程。
- M05岩壁保留引用会话以项目 `CaveRockBaker` 生成的材质输出。其他洞室前景改用同源算法的H5像素实现，采掘后按真实剩余实体遮罩更新岩缘，撤掉旧版重复裁片、绿色直边与整格装饰裂纹。
- 30种初始洞室形状／变体的后壁由当前磁盘Core程序集的 `BackgroundContourBaker`＋`BackgroundPageBaker` 生成；复用工程三层轮廓和暖岩配色，区分开口巢／封壳巢。生成器只写实验及证据目录，没有启动Unity、修改Core或原图；身份见 `assets/cave-backdrops/source.json`。
- 幼虫、拟态矿虫、卵簇和巢口复用已有 `experiments/cl04-creature-art-v1` 素材，按原帧名、朝向和脚底锚点绘制；其正式装配状态以DEVELOPMENT为准。
- M05复用独立素材样板的轮廓，不冒充当前正式预制地图。原样板为自动漫游，洞唇有一小段净空不足；本H5派生在 `1044≤x<1124` 范围同步修整前景与碰撞，洞顶至少离地30逻辑像素，保留原样板不改。
- 其他37项是为机制比较制作的专用试验洞室，不声称布局等同于正式地图。矿层裁片、地质碎岩、基础手持／图标／爆炸帧使用现有工程资源；17件新装备和箱子、灯、菌类、吊丝、网、泡沫、路标等使用本实验新绘的原生像素候选，不再使用同形方块枪与大块矢量物件。新候选仍须人工判断是否适合正式使用。
- 原始PNG／WebP字节只读，派生JS内嵌用于离线分发。来源绝对路径、原生尺寸、固定锚点、SHA-256及路线来源见 [asset-provenance.json](asset-provenance.json)。

照明为Canvas射线遮挡近似，不复刻Unity Linear／URP／PrivateField。HP、倒地、救援时长、货物价值、运输、槽位和无限物资都是Demo规则，不确定正式平衡、共享经济或失败合同。

## 重建与技术核对

仅需现有Node.js，无npm依赖：

```powershell
node experiments/expedition-playground/build.mjs
node experiments/expedition-playground/check-playthroughs.mjs artifacts/expedition-playground/checks/manual-run-playthroughs.json
node experiments/expedition-playground/check-mechanics.mjs artifacts/expedition-playground/checks/manual-run-mechanics.json
```

`build.mjs` 从 `src/` 生成单文件交付、开发入口及带源码摘要的构建清单。`src/project-assets.js` 是已提交式派生输入，普通重建不需要访问引用会话的个人目录。

需要重新采集素材时运行 `build-assets.mjs [引用样板目录]`：脚本读取原素材及来源记录、检查原SHA-256，生成新的素材JS和来源表，不改原PNG／WebP。输入若有作者改动应先审阅其差异，不修改旧摘要绕过保护。

`check-playthroughs.mjs` 对38项使用同一模拟的逐帧移动、瞄准、装备和交互完成目标，不直接写目标计数或传送角色。`check-mechanics.mjs` 检查遮挡、基岩保护、定向爆破前后区分、隐藏物、数量上限、封巢到期、支撑失效、梯上停留、绞盘保持和双角色运输／救援等边界。逻辑通过不代替人工手感认可。

本轮额外核对用 `check-pixel-style.mjs <原生校准RGBA> <回执JSON>`：源素材／风格输入哈希只读核对，32×32岩壁样本与当前Core程序集逐字节对照；此校准不含Unity光照和轮廓修饰器。后壁再采样用 `build-style-assets.mjs <新的证据目录>`，依赖现有.NET 8、Python/Pillow及当前磁盘Core程序集；输出初始实心矩形输入、RGBA、原生PNG和来源身份，随后运行 `build-assets.mjs` 和 `build.mjs`。普通离线重建不要求这些采样工具。
