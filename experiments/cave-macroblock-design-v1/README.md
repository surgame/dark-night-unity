# 大块洞穴模块设计方案 v1

2026-11-02，CL-01／08，本聊天／Local。按用户要求先提交设计方案，后续再制作可玩的白模和美术。本目录是独立设计候选；模块选择、尺寸和预算均待用户评审，不表示现行生成器已经替换。

## 1. 设计依据与本轮范围

- [现行玩法](../../docs/GROUND_GAMEPLAY_BASELINE.md)：主角运动、矿镐、照明、前景／矿层、联合侧巢及人工塌方。飞船和交货目前暂退，洞口集合点不自动变成商店、保全设施或替代营地。
- [阶段目标与地图QA](../../docs/EXPEDITION_CORE_LOOP_GOALS.md#cl01-map-qa)：路边试采、露头引向壁内矿脉、按路程及难度递进收益、天然岔路、原路返回、富矿与侧巢共同设计。
- [已有模块探索](../cave-ecology-walk-v1/README.md)：窄洞、大厅、浅沟、泉瀑及独立生态层提供空间来源；货槽运输、搭梁、油火、遗物概率仍是旧独立演示候选，不直接成为正式规则。
- 本轮用户希望先白模、后美术；同一地图重复游玩3～5次。这里将其理解为设计目标，未自动决定存档重入、资源刷新、事件复位或撤离后返回旧矿区的规则。
- 严格二维正侧视，没有可见行走顶面、纵深路面或俯视透视。普通探索减少被迫大落差；深裂和梯具高处明确作为可选特殊空间。

## 2. 推荐结构

以“一个能独立说明用途的空间”为大块单位。大块内部可以含数个平台、凹窝和矿点，不把一个平台或每格岩石都拆成模块。大块保存作者轮廓；天然弯曲、长岩檐和不对称岩肩不受外部占地矩形约束。

制作链建议为：

**作者模块库 → 选择关键发现 → 安排主干与支路 → 接口匹配及有限过渡 → 联合安排矿层／侧巢／事件 → 开发端修整 → 冻结完整候选。**

本轮随机来自模块组合、允许的形态变体和经审核的内容组合。主干按深入与折返组织，不把回环／捷径列为必需。已有性能页的随机回路用于算法比较，不直接作为本方案玩法基线。

开发端制作与游戏端加载仍分开：先保留完整地图冻结流程。运行时是否重新组合模块，本轮不决定。WFC可以以后接入候选选择，首批无需依赖它。

## 3. 尺度与形状

- `H`：实际主角站立碰撞高度；不等于美术帽顶，也不等于屏幕像素。`B = 8H`仅作为本候选的大块占地起始尺。
- 小空间约`2B～3B`宽、中洞室约`3B～4B`宽、大厅约`4B～5B`宽。一个模块可以占多个基础单元。
- 表中尺寸是作者包络，不是空气净空。模块尺寸不要求全部相同；禁止为适配接口任意拉伸整块。
- 普通接口净空先建议`2.5H`、窄口`1.5H`、宽口`4H`。这些是待同镜头调整的设计建议，未校准正式碰撞、跳跃或通过余量。
- 边缘以长段、自然拐点、局部碎裂和不对称转折构成；圆角半径随位置变化，不套用整张地图统一的四分之一圆。
- 正式接入若消费现行地形格／坡形，必须只采用已有合法形状或另行定义明确的形状合同；展示中的任意曲线不能直接证明现行碰撞能表达它。

## 4. 首批12种玩法模块

每种先做一个作者白模，不同时制作全套形态变体。包络和角色尺度在图中可比较；图中的矿、巢、塌方均为设计插槽。

| ID | 模块与起始包络 | 核心体验／空间构成 | 接口与组合职责 |
| --- | --- | --- | --- |
| M01 | 洞口缓入，24H×16H | 地表洞檐收进地下；来侧观察、地标与集合位置 | 左右S；入口位置随所选布局明确，不恢复所有地图共用的固定入口骨架 |
| M02 | 浅层试采台，24H×12H | 宽缓站位、少量路边矿；建立首次可采收益与返程地标 | 左右S；适合前段，避开初始强制侧巢／封路组合 |
| M03 | 长檐窄路，24H×12H | 较长岩檐压缩视野，穿行后再展开；局部凹窝 | 左右S；连接两个大空间，避免连续重复 |
| M04 | 错层岩台厅，40H×24H | 下部主行进空间、多个岩台、可观察的上窝；承担主要地标 | 左右S及可选上侧N；高窝可关闭或封口，不默认需要梯具 |
| M05 | 天然岔洞，32H×20H | 进入后能看见两种探索方向，局部岩肩区分主支路 | 来侧S、深入S、侧支N；分支用途先定，不能只增加空走廊 |
| M06 | 层状转坡，32H×16H | 长岩层之间改变高度，交替短直段与天然弯折 | 左右S且地面高度差显式登记；不给每段都加跳跃 |
| M07 | 浅沟跳口，24H×16H | 短断口、两岸起落站位和可见浅沟；先看清再选择动作 | 左右S；记录预期起落／失误落区，尚未验证实际跳跃 |
| M08 | 露头矿窝，24H×16H | 路边露矿与岩壁后的厚矿体关联；支线有清楚尽头 | 单侧S；既可做小收益盲端，也可替换成同接口另一种矿窝 |
| M09 | 壁后富矿厅，40H×24H | 表面少量露头、较厚围岩、独立矿层潜力；采或继续的选择 | 左右S，另有封闭壁内空间；矿脉不必须对应开放洞室 |
| M10 | 侧巢矿厅，32H×20H | 矿体与侧巢平行，保留巢口、前兆、出虫及退避空间 | 单侧S；和所属富矿共同选定，候选巢位不等于自动激活 |
| M11 | 塌方咽喉，32H×20H | 收束通道、可识别支撑及局部堆积范围；初始／变化后可比较 | 左右S；事件范围与接口带分开，返程可能被收窄或封堵 |
| M12 | 深部折返厅，40H×24H | 大尺度端厅、高收益潜力与明确折返点，停留观察后决定返程 | 单侧S；不是强制Boss房、结算口或保证有某件特殊装备的房间 |

`S/N/W`只表示几何端口类型，不代表人物已经通过。M08／10／12的“单侧”是设计端口约束，矿镐破坏后的其他开口不重新定义整块邻接关系。

| M13 | 高处悬台，32H×28H | 可选高处与梯具预留；标注进入条件，不自动生成梯子，不作为首张主干必经点 |

这16种是制作起点，不是素材上限。后续优先补充“用途不同”的空间，再扩同一用途的形态变体；仅换颜色不算新玩点。

## 6. 六类连接组件

| ID | 组件 | 起始尺度与作用 |
| --- | --- | --- |
| C01 | 同高短接 | 4H或8H；两端剖面完全一致时也可直接对接、零额外组件 |
| C02 | 缓坡接段 | 8H～12H；消化显式允许的小高度差，不自动修改房间内部 |
| C03 | 宽窄渐变 | 8H；S↔N或S↔W，完整顶／底轮廓连续 |
| C04 | 岩肩折接 | 12H；转折及较明显错层作为作者连接段，不任意旋转已有房间 |
| C05 | 支路颈口 | 8H；接岔洞侧支，控制支路口的朝向和净空 |
| C06 | 围岩封口 | 4H；封闭未使用接口；不能用后壁图像冒充前景碰撞封口 |

过渡是有限作者库，不是任意端口都能补救的万能变形器。不能连接时换模块、换已允许的连接段或退回局部布局；记录失败，不无限拉长、穿透围岩或暗改关键洞室。

## 7. 接口合同

每个接口登记：稳定身份、侧向、局部位置、朝外法线、空实剖面、地面／顶面切向、地质材质、前景／后壁相位、允许连接类、变化影响及水口。

1. 接口两侧各建议保留`1H`作者带。共边采样及切向必须匹配；同名S端口不替代实际形状核对。
2. 普通几何接口、玩法关系和生态水口分别记录。干燥S口与带水S口不因空实相同就自动兼容。
3. 接口带不放矿物露头、巢口、支撑触发点及随机大植物；现行可破坏性仍由正式材料／玩法合同决定，不把作者带自动变成不可破坏墙。
4. 只允许平移和显式登记的水平镜像。镜像同时变换端口、矿层、侧巢、来水／流向、事件及物体锚点；禁止倒置瀑布或把首部入口翻成盲端。
5. 模块占地、实际实岩、事件包络和动画包络分别检查；矩形不重叠不代表实际轮廓无洞、共边或动态效果正确。
6. 玩家通行关系记录为“预期步行／预期跳跃／梯具候选／刻意断开”等设计语义，不在本轮建设全图通行测试或恢复D-19的生产通行门槛。

## 8. 首张组合样板

推荐主干：

`M01 → M02 → M03 → M05 → M04 → M11 → M09 → M12`

- M05侧支接M08，展示短途露矿和小型盲端收益。
- M04侧支接M10，展示矿巢相关空间，是否启用依所属规则明确。
- 主干8块、支线2块共10个玩法模块；接口实际匹配后只在需要处插连接组件。
- 这是首张人工设计的组合示例，不是已执行的随机生成结果；图中线性长度不等于实测步行时间。
- 首批库还包含M06／M07，可替换合适的中段连接用途，形成第二张完整候选；不把未通过的玩法换到主干后直接称为可玩地图。
- 深浅依据沿路距离和到达难度；并非画得更低就自动算深层。示例中的上下分支不是收益等级轴。

随机候选先选用途和关键发现，再从匹配接口的作者模块中选择；固定房间可锁身份、朝向和指定位置。锁位置时单独安排连接路径及预留占地，不能只按拓扑接线后假设空间必然放得下。

## 9. 同图重复3～5次的设计安排

建议保留大地标和主要路线，支持玩家逐次学习“哪里有矿、哪条支路值得走、哪里有风险”。3～5是游玩目标，不是每图必须含3～5个模块。

可以在制作端选择不同的完整版本：替换一个可选支线、调整允许的矿脉配方或使用另一套经审核生态配置。每套作为完整组合审核；本轮不默认每次重入随机刷新矿、复活侧巢、恢复塌方或清除历史破坏。存档重入及跨远征刷新仍须明确决定。

避免同图中紧邻重复同一个识别度很强的大厅；普通长檐和过渡可重复，但需要长度／上下轮廓变体。具体次数／权重待白模观察，不制造固定配额。

## 10. 白模与后续美术交接

每块至少交付一份作者形状与来源、一份端口表、预期玩法关系、内容插槽、事件／动画包络和可选变体。来源可追溯，派生数据不反写作者源。

- 白模阶段：灰度轮廓、实际比例角色尺、露头／壁内矿体关系、侧巢和塌方范围，确认模块本身是否有内容。
- 组合阶段：同一坐标审阅接口、占地、封口和组合节奏；只给用户明确看到的范围下结论。
- 美术阶段：前景截面、完整后壁、矿层、独立物体／生态分开；角色脚底与轮廓对应，矿和巢不烘进背景。
- 动态阶段：植物根部／骨骼和运动包络，水源／连续流段／落点／排水，塌方各阶段及有界粒子单独交付。静态水面参考图不能替代流水成品。
- 正式接入：大块只描述初始制作结果；运行前景／矿层继续归现行会话地形，所属事件拥有唯一状态，不新增按块并行结算的世界模型。

## 11. 制作顺序与本次交付

1. 先做M01／02／03／04／05／08／09／12，共8块：确认进入、试采、压缩／展开、岔路和富矿折返节奏。
2. 加入M06／07／10／11：分别核对变高、跳口、侧巢和塌方空间；接现行能力前标明待验。
3. 按需增加M13～16与同用途形态变体；之后再批量制作美术，避免一次铺开大量待改资源。

本轮仅完成候选方案、16块局部形状示意、首张组合示意和接口带视图。可切换单块、整体和接口；没有角色物理、随机求解、采集、塌方模拟或生态动画。展示检查不等于全路线／正式性能／美术共边通过。

可编辑来源：`catalog.js`、`view.html`、`app.js`；`build.cjs`将其打包为聊天片段。`inspect.cjs`只检查展示脚本、16种局部示意、三类视图的布局与状态恢复，不执行游戏测试。`records/`保留构建身份及定向展示记录。旧性能页、所有白模、美术原图和玩家状态均保留。
