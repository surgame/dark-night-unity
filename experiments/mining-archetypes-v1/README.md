# 矿脉与伴巢五方案离线样板

用户在R2侧旁版后要求增加联合方案，并改善矿脉辨识度。本目录是CL-01／04的形态候选比较，不是R3完整地图接入；R0、R1、首版R2及侧旁R2原演示／快照保持原字节，正式Game、作者资产和配置不变。

## 方案与取舍

| 方案 | 矿体与伴巢关系 | 想审阅的选择 |
| --- | --- | --- |
| 分叉夹巢 | 细脉分成铁支与金支，巢腔位于分枝之间，两处可挖封岩 | 先采哪支、是否冒险深入另一支 |
| 细脉富核 | 细线索进入不规则厚矿团，内核集中金矿，侧巢贴着厚矿 | 发现富核后，是否继续挖巢旁的剩余矿 |
| 错层夹巢 | 本图采用竖向错位矿带与细连接，夹层巢腔可由两处侧壁揭露 | 先沿层采，再决定是否跨层开挖 |
| 串珠矿囊 | 小、中、大矿囊由细脉相连，中段旁有巢腔 | 采到哪一囊收手，是否追下一处更厚矿体 |
| 环抱矿弧 | 开口矿弧围着巢腔，两个矿段可侧向接巢 | 继续沿弧采会贴近危险，何时停止 |

这些是建议候选，尚未选定正式分布或经济。常规富矿可优先比较分叉／串珠，富核／环抱适合作为少量特殊发现，错层依地质区域使用；不是全部矿都必须大型化、挂巢或采用同样结构。

## 同源与可插拔边界

- 同一`rift-expanded`真实地形、原露头`r1-vein-45395`及背景矿层。先用弯折细脉进入左侧厚围岩，再展开不同矿体；不靠打通新天然通道给配方腾位置。
- 只替换所选深段矿脉；其他R1矿脉及路边小矿占格保留。任何新矿格／巢腔与原空腔、保护格或其他矿格冲突即拒绝，不裁剪为另一个未声明形状。
- 五方案均为铁120／金120，总储量240的比较试参。占格90～105不等于价值不同，单位格储量随形态变化；未定义售价、开挖耗时或正式收益平衡。
- 联合输出连续矿格、分枝／富核形态、稳定SiteId、支撑、封岩及冻结侧挖顺序。首处侧通发生在预设矿格序31%～58%，之后仍有110～178储量；实际玩家可自由挖掘。
- 特色矿脉关闭时恢复R1原矿脉／坡形，不附加巢腔；只关闭巢穴时保留特色矿体，不附加空腔补丁。演示中的开挖顺序包含预设侧壁开挖，不代表采到某格就自动穿墙或触发AI。
- 沿用现有`TerrainDepositBlueprint`单床64格上限：同矿脉按矿种及不超过64格分组，容量为各组格容量之和；使用既有蓝图构造校验，不放宽正式合同或修改Core／YYGC。矿脉分组是静态制作元数据，不增加运行状态模型。

## 复现与展示

需要本机.NET 8兼容SDK、保留的R1快照和身份可核对的本地Core程序集；只读调用正式`PlanetTerrainGenerator.GenerateCandidate`，不启动Unity。

```powershell
dotnet build experiments/mining-archetypes-v1/MiningArchetypes.csproj --nologo -v minimal
dotnet experiments/mining-archetypes-v1/bin/Debug/net8.0/MiningArchetypes.dll '<项目绝对路径>' '<保留的R1快照绝对路径>' '<本批独立输出绝对路径>'
```

输出`mining-archetypes-snapshot.json`和`generation.json`，失败项在同批集中记录并返回非零。浏览器只消费冻结结果，提供五图同尺度总览、单方案放大、完整剖面／开挖顺序及两个模块开关。矿格纹理为代码绘制的示意符号；巢口、卵及警觉幼虫复用CL-04的3张原生PNG，16像素／格，不修改源图。

静态格级连通、支撑及模板检查不证明身体通行、梯具需求、真实视野、采掘节奏、战斗、噪声或同步／恢复。当前仅离线编译与演示核对，不执行Unity导入／编译／Play／Unity测试／Player。证据见[本批回执](../../docs/evidence/cl01-mining-archetypes-v1.json)，状态见[CL台账](../../docs/DEVELOPMENT.md#stage-cl)，合同见[联合方案](../../docs/TERRAIN_GENERATION.md#cl01-mining-archetypes)。bin／obj与演示证据留原位供复现，未清理。
