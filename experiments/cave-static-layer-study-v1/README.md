# 固定洞形下的整块编码与分层组合

本样板回应用户“暂不考虑地形可挖，混合方式还有什么价值”的要求，独立于正式Unity。旧版成图、步骤图解及连续开挖白模均保留；本片没有采掘输入、破坏状态或以可挖性为前提的优势，不据此暂停正式游戏采掘。

## 制作输入与呈现边界

原生逻辑范围48×28，沿用前一白模的固定作者洞形与16种四角拓扑；两份作者输入分别为271／902的凹岸引导。画面按同一世界坐标适配736至320宽度，不将浏览器绘制尺寸当成最终tile尺寸。主角只读复用282×309 RGBA原PNG，按三格高作为静止比例参照。没有新生图、修改原素材或制作正式透明图集。

纹理为程序白模笔触，草、菇、晶簇和岸边均为参数化原型。水流、波纹和植物摆动是程序动态说明，非Spine绑定、正式粒子、最终美术或物理验证。岸边沿实际轮廓采样，共边状态为干岩D／苔带M／湿岸W；生态仅选择左岸至主凹岸之间的20个连续槽，止于侧窝轮廓分支之前。侧窝没有伪造一条跨越空腔的连续附着线，也不宣称覆盖任意分支。

## 公平比较的三种方式

| 方式 | 本样板实际计算 | 能说明什么 |
| --- | --- | --- |
| 仅DualGrid | 固定空实场直接映射16型，共用独立水层 | 确定的基础形状本身不需要WFC；该视图没有选择额外生态 |
| 整块候选WFC | 16种几何掩码与11种生态原型派生176个组合记录；对全图1344格按作者掩码限域，四邻检查几何，20个地面槽另按生态端口连边 | 几何与生态可放在同一候选记录里，仍能严格保留作者形状 |
| 分层组合 | 基础16型直接生成；20个生态槽只在11种原型中求解 | 可把稳定形状与变化属性分别表达，不依赖地形能否开挖 |

两种WFC使用同一组原型、条件、权重、语义顺序与随机流。完整求解后检查几何逐格不变、生态逐槽相同；不故意让整块方案缺件、失败或显示得更差。176是本例全组合编码的记录数，可自动派生，不是176张手绘图，也不是整块方案的最低资产成本。分层是数据和职责选择，整块方式也可自动派生、复用相同绘制资源；本例不证明分层在美术、速度或内存上天然更优。

基础形状固定，故当前非平凡选择主要来自生态端口。生态图是沿连续岸线的链，不是任意二维内容生成，更不代表Townscaper三维算法的复刻。

## 有限规则与失败

11种原型为裸岩D-D、苔起D-M、苔带M-M、苔止M-D、湿起M-W、湿岸W-W、湿止W-M、蘑菇M-M、晶簇D-D、草簇M-M、芦苇W-W。库中没有D-W直连。两端固定干岩，中段给定一处蘑菇、一处湿岸，部分物体受局部坡度过滤；实际加权熵观察、候选传播、四次整次重试均在`model.js`执行。

“试一次规则冲突”要求相邻两槽分别为裸岩D-D和湿岸W-W，二者没有兼容接口。两种WFC均必须拒绝；界面保持上一有效几何与生态，并标记冲突位置。没有生成一个“不满足要求但看起来正常”的替代布局。合法链本身较容易有解，本片不据此声称WFC永不失败或复杂2D美术共边已验。

## 操作与代码

- 切换三种方式，使用同一洞形、镜头和种子；关闭分层标记时两种WFC应显示同一画面。
- “重排生态”只改变生态选择，地形摘要必须不变。
- “切换作者洞形”载入另一份固定作者输入，三种方式仍必须遵守同一新轮廓。
- “显示编码分层”展示完整候选框或基础轮廓与生态框；只作为编码解释。
- 水流与摆动默认运行，后台页面停止动画，减弱动态偏好冻结到同一确定帧；动画不调用生成RNG或修改布局。

`model.js`负责两种实际候选图、求解与等价校验；`renderer.js`只读绘制；`app.js`管理原子替换、失败保留、动画与状态。只读复用`cave-wfc-whitebox-v1/plan.js`、`catalog.js`及`dualgrid-wfc-shape-study-v1/model.js`、`renderer.js`。不修改这些前版源码。
